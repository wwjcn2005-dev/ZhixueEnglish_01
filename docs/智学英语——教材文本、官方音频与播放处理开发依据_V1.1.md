## 1. 总原则

> **教材是主线，学习是核心，孩子做主，AI 做助手。**

> **教材文本是语义事实权威；官方教材音频是教材资源主线之一；AI 可以辅助恢复、对齐、结构化和评价，
> 但不能凭空创造教材事实。**

由此派生的三条硬约束：

1. 教材页面没有的内容，不得由 AI 以"常识"补成教材事实；
2. 官方音频里确实存在的内容，属于教材资源的组成部分，不得当成 AI 生成内容；
3. 播放行为（是否播放过、播了几次）不产生学习判断证据；学习判断只来自孩子的作答与学习记录。

## 2. 职责边界：教材原文 / 官方音频 / ASR / AI

| 角色 | 负责回答 | 权限与限制 |
| --- | --- | --- |
| **教材原文** | "教材到底写了什么、表达了什么？" | 语义事实的主要依据；只读，不得改写、润色、覆盖 |
| **官方教材 MP3** | "教材实际说了什么、在哪里说、以什么完整语音形式呈现？" | **正式教材资源**，不是普通辅助素材；只读，不得删除/覆盖/重编码 |
| **ASR** | 音频转写辅助、时间切分、音频与教材文本匹配、帮助确定 segment 与 `start_ms / end_ms` | **不是教材文本权威来源**；不得作为教材事实或答案来源 |
| **AI** | 恢复教材页面空缺、从官方音频辅助定位、对齐、结构化、判断证据是否足够、生成真正的辅助性学习内容、开放题评价 | 不得添加教材外事实、不得猜测无证据内容、不得用外部知识填补教材空缺、不得把 AI 猜测当作教材事实 |

一句话口径：

```text
教材原文负责"说什么"；官方音频负责"怎么说、在哪里说"；ASR 帮助两者对齐；AI 只做辅助与结构化。
```

## 3. 正式教材资源身份（三种，不得混淆）

### 3.1 TEXTBOOK_NATIVE

教材页面**直接存在**的内容（正文、对话、标题、活动指令、教材练习等）。

### 3.2 TEXTBOOK_AUDIO_RECOVERED

教材页面本身存在**空格、挖空、截断或不完整呈现**，但完整信息可以通过
官方教材 MP3 + 已验证音频 segment + 教材上下文 + 已确认的对齐关系**可靠恢复**。

必须明确：

> **TEXTBOOK_AUDIO_RECOVERED 仍然属于正式教材资源，不属于普通 AI 生成内容。**
> AI 在这里只是帮助恢复/结构化**已经存在的教材事实**。

恢复记录必须同时保存（缺一不可）：

```text
original_text（教材原始印刷文本，含挖空，逐字保留，不得覆盖）
recovered_text（恢复后的内容）
blank / 恢复位置（span 或选项对）
source_audio_id            → 官方 MP3
source_segment_id          → 该音频的 VERIFIED segment
source_text_block_id       → 教材 content_block
evidence（音频时间段 start_ms / end_ms 与依据说明）
confidence
recovery_method
generation_run_id
content_hash（稳定，防重复）
```

承载方式（P4-02 已实施，不新建体系）：沿用现有教材活动资源目录的同一 schema，
下一版本 `structured/exercises/exercise_catalog_v4.json`：
既有字段逐字保留（`questions[].text` = 教材原始印刷文本），用既有来源状态字段表达身份
（`TEXTBOOK_NATIVE` / `TEXTBOOK_AUDIO_RECOVERED` / `NEED_REVIEW`），新增最小字段 `recovered`。

入库门槛（宁缺勿猜）：

1. 恢复内容必须**确实存在于官方音频**，并能追溯到具体 audio segment 与时间段；
2. 教材自身声明了挖空数量时，**音频证据确认数必须与之一致**（交叉验证）；
3. 只有"整段听力材料未印刷"而无教材挖空结构、或证据不足、或数量不一致时 → `NEED_REVIEW`，
   不得进入正式资源；不得为了凑数强行通过。

### 3.3 AI_GENERATED

真正由 AI 生成的辅助内容，例如：听力选择题干扰项、合理的辅助练习、其他不属于教材原始事实的学习辅助内容。

> AI_GENERATED **不得反向成为教材事实来源**；不得与 TEXTBOOK_NATIVE / TEXTBOOK_AUDIO_RECOVERED 混用身份。
> 正式资源与待审资源（`NEED_REVIEW`）必须分开，不得混在同一查询结果里。

## 4. 教材资源 → 正式题库

固定链路（唯一口径）：

```text
完整教材资源
    ↓
本地正式题库
    ↓
程序确定性题目 + AI 合理补足
    ↓
质量校验
    ↓
正式题库
    ↓
APP 按学习证据调用
```

规则：

1. **有多少资源就利用多少资源**，没有固定题数；
2. 不为了"凑题数"生成题目；资源不足时允许 0 题；
3. 能确定答案的优先**确定性生成**（教材文本 + 结构性证据即可判定）；
4. 没有可靠答案的开放任务使用 AI 评价或其他合适机制，不得伪造"标准答案"；
5. AI 生成的辅助内容必须经过**确定性规则校验**（重复、越界、证据缺失、异常长度、confidence 等）后才可入库；
6. 正式题库必须保留**来源与证据链**（题目 → 教材资源 → 音频/文本块 → 生成方式 → run 记录）；
7. 题库不得写入教材事实层；AI 生成题不得直接进入孩子的正式学习流程。

---

## 5. 官方音频必须作为完整教材资源考虑

> **54 个官方 MP3 都是正式教材资源。**

当前 APP 没有调用某个 MP3，**不能证明该 MP3 没有价值**；它只能说明：

> 当前 APP 对教材资源的学习能力覆盖还不完整。

因此：

* 不因为当前 APP 没调用就删除官方音频；
* 不因为暂时没有题型就认定资源无用；
* 根据教材资源逐步建设本地题库，再由程序与 AI **合理**利用这些资源；
* 资源完整性与产品覆盖度是两个不同的问题，报告时必须分开陈述。

## 6. 音频对齐规则

### 6.1 固定链路

```text
官方教材 MP3
    ↓
ASR / 时间切分
    ↓
与教材原文匹配
    ↓
确认对应教材文本
    ↓
确认 sentence / segment
    ↓
确认 start_ms / end_ms
    ↓
学习资源
    ↓
题库 / APP
```

### 6.2 方法复用（不得另建体系）

继续沿用已经验证的：

* **P3-06**：AU06 逐句核验（word timestamps + 人工听辨确认）；
* **P3-07**：ASR word window 与教材文本匹配 + 边界复核（波形低能量区 + 前后句 speech 硬约束）；
* **P3-08**：句级边界加工（同一方法扩到 27 个 PARTIAL 音频，未新增算法）。

不得重新发明另一套音频对齐体系；不得用"文件名相似 / 音频时长 / 文字长度 / AI 语义判断"单独推断对应关系。

### 6.3 边界与状态（与《最高指导原则》六·8、六·9 一致）

1. 准确锚定优先于切割；官方完整音频优先于未经验证的切割；
2. 只有存在教材结构提供的**明确、可验证边界**时，才允许建立片段级映射；
3. 每条对齐关系必须带证据与状态（`VERIFIED` / `PARTIAL` / `NEED_MANUAL_CONFIRMATION`）；
4. **未达到 VERIFIED 的边界不得用于需要精确边界的题型**（如听音写句）；
5. 无法确定时保留官方完整音频 + 完整教材文本与上下文，标记待审，禁止自动猜测；
6. 对齐关系只能是只读派生：不得反向修改教材事实（contentpack、教材原文、音频文件）。

与《最高指导原则》六·9 保持同一口径：**本依据同样不要求把听力切成短句或短片段**。
有 VERIFIED 边界才使用片段；没有就保留官方完整音频 + 完整教材文本与上下文，并标记待审。

## 7. 音频播放边界规则（资源侧）

核心原则：

> **音频资源负责保证"播放内容完整"；播放器负责保证"播放行为稳定"。**

segment 的 `start_ms` / `end_ms` 必须优先保证：

1. 不截断句首；
2. 不截断句尾；
3. 不因为过度追求精确边界而切掉自然语音；
4. 句间存在静音时，可将结束点落在安全的静音 / 低能量区域；
5. 播放以**完整、自然、可理解**为优先。

> 不要为了毫秒级"漂亮边界"破坏实际学习体验。

## 7A. 教材展示范围与素材调用分层（2026-09-26 同步）

> 本节是**新增章节**，位置介于 §7（音频播放边界规则）与 §8（播放器状态规则）之间；原有章节编号不变。
> 本节与《最高指导原则与开发规范 V1.3》第二十九章 §13、《产品与 UI 架构总纲 V2.0》§5.2 保持同一口径。

### 7A.1 教材展示与数据使用分层

1. 教材原文展示页只展示**能够与官方教材音频可靠对应**的教材文本内容；
2. 不追求把整本教材的全部文字搬进 APP；
3. 依赖插图、版面、活动情境的教材内容，不为了"展示完整"而拆成零碎文本重新排版；
4. 其他教材数据（词汇、短语、句型、练习、音频等）继续**完整保留**，供正式学习功能及后续 AI 学习功能调用；
5. 一句话口径：**数据保留 ≠ 前端全部展示。**

### 7A.2 教材原文页的定位

> 教材原文页 = **教材音频对应内容的查看与播放页**。

- 它不是完整教材的电子化页面；
- 它不是新增的一级学习入口；
- 它不是孩子进入日常学习的前置步骤。

### 7A.3 展示形态

1. 播放入口贴合**自然段或可靠对应的文本内容**；
2. 不采用**逐句喇叭按钮堆叠**的方式破坏阅读体验；
3. 只有存在**可靠句子级映射**时，才支持相应句子的播放与高亮；
4. 没有可靠句子级映射时，使用**完整活动音频**；
5. 不伪造不存在的句子音频切片（与 §6.3、§7 同口径）。

### 7A.4 事实权威关系

- 只有**可靠对应**的教材文本与官方音频，才能作为正式音频学习展示内容；
- 不确定的文本或对齐结果**不得伪装成已经确认的教材事实**；
- 本节与 §1、§2、§6.3 保持同一口径，不重复改写已经存在的事实权威定义。

## 8. 官方音频播放器状态规则（V1.1 新增核心）

### 8.1 允许自动播放，但不得改变状态机

完整 APP 中可以继续使用自动播放。但：

> 自动播放只是"触发播放"的入口之一，**不能改变播放器状态机**。

限定（与《最高指导原则》"不用弹窗、自动跳转、自动播放干扰学习"一致）：
允许的是**学习内容本身的自动播放**（进入题目/单词卡播放该条官方音频）；
不得用自动播放做装饰动画、弹窗、跳转或其他与学习无关的干扰。

### 8.2 `play()` 不等于已经开始播放

禁止：

```javascript
audio.play();
playing = true;
```

这种"调用即认为已开始"的写法。正确口径：

```text
play()
 ↓
等待真实 playing 事件
 ↓
确认正在播放
```

### 8.3 播放状态由真实音频事件驱动

```text
playing → 正式进入播放状态
pause   → 清除播放状态
ended   → 清除播放状态
play() 失败（reject / error） → 清除播放状态并进入错误或恢复路径
```

UI 不得通过猜测播放器内部状态来决定播放状态。

### 8.4 禁止用 `audio.paused` 简单判断用户意图

尤其禁止把下面这段作为"自动播放 + 用户点击"的唯一控制逻辑：

```javascript
if (!audio.paused) {
    pause();
} else {
    play();
}
```

原因：自动播放刚调用 `play()` 时，音频可能尚未真正进入可听播放状态；此时用户第一次点击若被误判为"暂停"，
就会出现**同一道题有时第一次播放不完整、有时第二次又正常**的现象。这属于**播放器竞态**，不是音频文件损坏。

### 8.5 自动播放与用户点击必须解耦

```text
进入题目
    ↓
自动播放
    ↓
等待 playing
    ↓
播放器确认播放中
```

用户主动点击时：

```text
用户点击
    ↓
明确执行当前音频的播放 / 重播行为
```

不能因为自动播放正在启动，就把用户第一次点击误认为暂停。

### 8.6 切换音频必须先停止旧音频

固定顺序：

```text
pause old audio
    ↓
切换 src / segment
    ↓
初始化当前播放状态
    ↓
按当前场景执行 play()
```

避免旧音频与新音频之间产生状态串扰。

### 8.7 页面 / 题目切换必须清理旧状态

切换题目、单词、句子、音频 segment、播放模式时，不允许旧音频状态污染新题：

* 旧音频先 pause；
* 旧事件监听与定时器清理；
* 播放状态复位（回到"未播放"的初始态）；
* 新题只依据新音频的真实事件进入播放状态。

## 9. 资源层与播放器层必须分离

> **资源层负责"播放什么、播放哪一段"；播放器层负责"稳定地把这一段播放出来"。**

排障分流（不得互相顶替）：

| 现象 | 优先检查 | 不得做的事 |
| --- | --- | --- |
| 音频**内容不完整** | segment、`start_ms`、`end_ms`、音频与教材文本匹配 | 只改播放器逻辑就当成修好了 |
| 音频内容完整但**播放行为异常** | autoplay、`play`/`playing` 时序、pause、ended、src 切换、页面生命周期、播放器状态机 | 因为播放器偶发异常就重新处理教材音频资源 |

* 以"文件名相似、音频时长、文字长度、AI 语义判断"单独推定教材↔音频关系；

* 把 ASR 转写或 AI 猜测写成教材事实或教材答案；
* 因为播放器偶发异常重新处理教材音频资源；
* 为了让教材"看起来完整"而把整本教材文字搬进前端或重新排版。

本文件只描述**当前有效的长期开发原则**。

## 12. 自检清单（改教材音频/播放相关代码前先过一遍）

```text
[ ] 教材原文仍是"说什么"的唯一权威
```
