## 1. 产品定位

本产品定位为：

> **电子教材 + 可点读音频 + 轻量学习工具 + 学习证据 + AI随堂助教**

它不是普通 AI 聊天软件，不是题库，也不是学校 LMS。

核心目标是：

> 让孩子打开 APP 后，首先看到和学校正在学习内容一致的教材内容。

教材本身就是主要学习入口。

在教材内容之上叠加：

- 音频
- 点读
- 跟读
- 词汇
- 短语
- 语法
- 听写
- 阅读
- 输出
- 学习证据
- 本地分析
- AI反馈

最终闭环：

```text
电子教材
→ 听/读
→ 练习
→ 产生证据
→ 分析
→ AI辅助
→ 孩子决定下一步
```

## 2. 教育原则

最高原则保持不变：

> **教材是主线，学习是核心，孩子做主，AI 做助手。**

具体要求：

- 教材内容权威，不能改写教材事实。
- 学习行为产生真实证据，不以浏览、点击或播放代替学习证据。
- AI 不能替代孩子学习。
- AI 不能强制安排学习。
- 学习数据和内容数据严格区分。
- 正式数据安全边界保持不变。
- 孩子决定学习内容、开始时间、节奏和是否继续巩固。

## 3. 三层架构

### 3.1 教材层

负责：

- 呈现外研版初一英语（上册）电子教材
- 保持教材原有内容主线
- 提供课文、对话、句子、词汇、练习等原始学习内容
- 作为所有学习活动的事实来源

### 3.2 学习层

负责：

- 听
- 读
- 跟读
- 词汇
- 短语
- 语法
- 听写
- 阅读
- 写作
- 句型转换
- 学习证据记录

### 3.3 AI层

负责：

- 分析
- 评估
- 反馈
- 建议
- 周末诊断
- 情景角色练习

AI 不能取代教材，也不能自动替孩子决定学习路径。

## 4. PDF 教材层

当前真实电子教材资源是：

> **PDF**

PDF 是教材内容的重要原始载体。

产品设计目标不是重新编写一套“仿教材内容”，而是尽可能保留原教材的内容结构和视觉阅读体验，并在其上叠加学习能力。

约束：

- 原始 PDF 只读。
- 不把 PDF 改写成网页教材后当作教材事实源。
- 不修改教材内容。
- 不覆盖原版面。
- 必要时可以做结构化派生，但派生数据不能替代原始教材。

## 5. MP3 音频层

当前真实教材音频资源是：

> **MP3**

项目中已有正式教材音频资源及对应映射关系。音频是教材学习层的重要基础资源。

当前产品核心技术资源关系应明确描述为：

```text
PDF教材 + MP3音频 + 学习层 + AI辅助层
```

而不是：

```text
网页题库 + AI聊天
```

约束：

- 原始 MP3 只读。
- 不修改、不移动、不重命名、不转码、不切割原始 MP3。
- 播放与时间区间只引用原始 MP3。
- 音频映射必须可追溯。

## 6. 教材即入口

本版本最重要的产品设计变化是：

> **教材即入口。**

孩子进入某个 Unit 后，不应该首先看到一堆词汇按钮、语法按钮、跟读按钮、AI按钮或练习按钮。

孩子应该首先看到：

> 教材内容。

教材是孩子理解“今天学什么”的第一入口。

学习能力应围绕教材页面就地展开，而不是把教材拆成多个孤立功能入口。

## 7. 音频热点

PDF 教材内容作为视觉主体。

对于存在对应 MP3 音频的教材文本区域，在阅读界面上增加轻量、克制的“音频热点”。

交互：

```text
教材正文
→ 某一句/某一段具有对应音频
→ 该区域显示非常轻微的颜色背景或边界提示
→ 孩子点击文本区域
→ 播放对应 MP3
→ 当前正在播放的句子/段落得到轻量高亮
→ 孩子继续阅读、重复播放或进入跟读
```

音频热点不是传统的大按钮。不得破坏教材阅读体验，不得把页面做成按钮控制台。

## 8. 句子作为学习锚点

“句子”是连接教材和学习能力的核心学习锚点。

一个教材句子可以关联：

- 原文
- 所属 Unit
- 所属课文/对话
- MP3
- 时间轴
- 词汇
- 短语
- 语法结构
- 跟读
- 听写
- 句型转换
- 阅读
- 输出
- AI分析
- 学习证据

例如：

```text
He likes sports.
→ 听
→ 读
→ 跟读
→ 词汇理解
→ 语法观察
→ 听写
→ 句型变化
→ 输出
```

这样可以避免把教材、词汇、语法、练习和 AI 拆成互不相关的页面。

## 9. 语音跟读

正式方案加入语音跟读能力，最小闭环：

```text
教材句子
→ 点击播放 MP3
→ 孩子听
→ 孩子跟读
→ 真实录音
→ 回放
→ 分析本次表现
→ AI给出简短反馈
→ 孩子选择再读或继续
```

评价重点是：

- 是否完整
- 是否存在明显停顿
- 节奏是否自然
- 重音是否值得注意
- 某些词是否需要再次练习

约束：

- 默认不生成总分。
- 不生成排名、等级、排名化指标。
- 语音评价必须基于真实语音分析能力。
- 波形相似度不得直接定义为“发音正确率”。
- 一次跟读结果只能评价“这一次表现”，不能推出“孩子英语口语能力是多少”。
- 不得写成“掌握程度 88%”或“已完成口语掌握”。

音频能力采用渐进式分层：

1. 段落级音频
2. 句子级音频
3. 词汇级音频
4. 跟读录音
5. AI辅助评价本次跟读表现

不要一次性承诺全部能力。

## 10. 词汇

词汇必须依托教材上下文。重点词汇优先从教材中产生。

不得把词汇学习做成脱离课文的独立背词系统。

基本流程：

```text
教材句子/课文
→ 重点词汇
→ 理解
→ 主动回忆
→ 练习
→ 学习证据
```

## 11. 语法

语法优先从教材真实句子中观察、解释、练习。

流程：

```text
教材句子
→ 发现结构
→ 孩子尝试理解/变化
→ 出现错误
→ AI通过提问和提示帮助孩子自己发现问题
```

AI 不应在普通解题提示场景直接给标准答案；批改结论可以有明确判定。

## 12. 听写

听写采用短、小、针对性的方式。

优先使用：

- 教材句子
- 当前 Unit 的核心词汇与表达
- 有真实证据显示需要巩固的内容

听写不追求一次大量输入，不把听写变成独立刷题系统。

## 13. 阅读

阅读以教材为主线。

教材课文、对话和阅读材料是阅读训练的主来源。阅读练习应帮助孩子理解教材，而不是替代教材。

推荐：

```text
教材阅读
→ 理解
→ 观察表达
→ 简要输出
```

## 14. 写作

写作以教材为主线。

推荐：

```text
模仿
→ 变化
→ 独立输出
```

写作不追求一次性长作文。先从教材句子、句型和短文本逐步过渡。

## 15. 学校进度

学校教学进度是 APP 的重要上下文。

原则：

> 学校教什么，APP优先提供什么；孩子今天想练什么，由孩子决定；一周学习产生的真实证据，用于周末发现最值得巩固的内容。

不得实现为：

> 学校今天教什么，APP就强制要求孩子完成什么。

孩子始终拥有：

- 选择学习内容的权利
- 选择开始时间的权利
- 选择学习节奏的权利
- 选择是否继续巩固的权利

## 16. 平日 10–15 分钟模型

孩子平日只有约 10–20 分钟。默认推荐 10–15 分钟高价值学习任务。

不是强制“每日10分钟流水线”。

推荐结构：

```text
当前学校 Unit
→ 一个核心学习目标
→ 2～3个短任务
→ 产生真实学习证据
→ 给出简短反馈
→ 孩子决定：再练一次 / 换一个内容 / 结束
```

## 17. 周末 25–40 分钟模型

周末可以提供约 25–40 分钟的较完整学习。

流程：

```text
一周真实学习证据
→ 本地确定性分析
→ 发现最值得巩固的问题
→ 必要时调用 DeepSeek
→ AI生成解释、反馈、建议
→ 孩子选择是否继续
→ 针对性练习
→ 角色扮演/输出
→ 产生新的学习证据
```

不得把整个 learning.db 原始数据直接全部上传给 DeepSeek。

优先：

```text
本地分析
→ 提炼必要信息
→ AI处理必要上下文
```

## 18. 学习证据

学习证据来自真实学习行为，包括：

- 单词识别
- 主动回忆
- 听力答题
- 阅读答题
- 语法练习
- 跟读
- 重复学习
- 错误与修正
- 同一知识点不同时间的表现变化

没有足够学习证据时，系统不得给出虚假的掌握评价。

正确表述示例：

> 目前学习记录较少，暂时无法形成可靠评价。

## 19. 本地诊断

本地诊断优先使用确定性规则：

- 学习次数
- 正确/错误
- 重复练习
- 跟读表现
- 词汇薄弱点
- 语法薄弱点
- 一周学习证据
- 是否需要巩固

本地诊断先产生可追溯证据，不直接制造长期能力结论。

## 20. DeepSeek

DeepSeek 是“随堂助教”，不是“自动老师”。

AI 主要负责：

> 分析 → 评估 → 反馈 → 建议

尤其负责：

- 为什么错
- 哪里容易混淆
- 应该注意什么
- 下一步可以怎么练
- 如何用教材中的句子继续练习

AI 不能：

- 替孩子选择全部学习内容
- 自动宣布长期掌握
- 用一次回答判断长期能力
- 用伪精确分数制造“科学感”
- 脱离教材无限聊天

DeepSeek 只在本地分析和规则处理之后按需调用。

## 21. Role-play

基于教材情境的角色扮演最后再加入。

约束：

- 必须基于教材真实情境和表达。
- 不能生成脱离教材的无限对话系统。
- 不能把角色扮演作为正式掌握判断的唯一依据。

## 22. 导航原则

总体保持：

```text
首页 / 学习 / 进展
```

一级页面不超过 3 个。

不要把教材、词汇、语法、跟读、AI 做成互相孤立的五个入口。

如果当前教材页面已经能够完成任务，就不要再创建一个新的页面。

## 23. UI 原则

采用：

> **Clean Modern Learning**

禁止：

- 游戏化
- 积分
- 排名
- 徽章
- 糖果色
- 大量动画
- 儿童化视觉

教材内容是视觉主体。

音频热点使用轻量、克制、明显可感知但不喧宾夺主的颜色提示。

AI 提示同样应该克制。

## 24. 本地优先技术架构

技术路线采用：

> **Local-first**

不是绝对“完全离线”，因为 DeepSeek API 调用本身需要网络。

推荐：

- SQLite：本地学习数据
- PDF：电子教材资源
- MP3：教材音频资源
- Android：正式 APP
- DeepSeek API：按需调用
- 用户自己的 API Key：安全存储

本地优先的核心教材、学习记录、学习证据和主要业务逻辑尽量在本地运行。

不建立不必要的账号体系和云端学习数据平台。

## 25. 隐私与成本

AI 费用是重要约束。

不要：

- 每次打开教材都调用 AI
- 播放一次音频就调用 AI
- 把全部学习数据持续发送给 AI

优先：

```text
本地确定性分析
→ 只有真正需要解释、反馈、诊断时
→ 调用 DeepSeek
```

API Key 必须采用 Android 安全存储机制。

## 26. 商业化版权注意事项

产品未来如果公开发布或商业化，必须单独确认外研版教材 PDF 和 MP3 音频的：

- 使用权
- 复制权
- 发行权
- APP内嵌权
- 商业分发权

当前产品设计阶段可以基于用户已经拥有的电子教材和音频做个人验证。

不能因为“本地使用”就默认商业分发没有版权问题。

## 27. 分阶段开发路线

### Phase 0：资源确认

确认 PDF 教材结构、Unit/Module/课文结构、页面映射、MP3 文件、MP3 与教材内容映射、音频粒度、时间轴和商业化版权问题。

### Phase 1：最小教材 Spike

只选一个 Unit，实现 PDF 教材内容 + 对应 MP3 + 最基本音频热点。

点击教材文本区域 → 播放对应 MP3 → 当前内容轻量高亮。

不做 AI、学习记录、掌握度、语音评分、周末诊断。

### Phase 2：语音跟读 Spike

只选一个教材句子，增加麦克风录音、停止、回放、再录和本次语音表现展示。

先不进入正式学习数据库。

### Phase 3：学习证据

确认体验成立后，再接正式 learning 层，记录真实学习行为和证据。

### Phase 4：本地诊断

先不调用 AI，使用确定性规则分析学习次数、正确/错误、重复练习、跟读表现、词汇/语法薄弱点和一周学习证据。

### Phase 5：DeepSeek

只把经过本地分析、真正需要 AI 的信息发送给 DeepSeek，用于解释、反馈、建议和周末诊断。

### Phase 6：Role-play

最后加入基于教材情境的角色扮演。

## 28. 明确不做事项

当前阶段不得：

1. 修改任何 Python 代码
2. 修改 Android 代码
3. 修改 learning.db
4. 修改教材 PDF
5. 修改 MP3
6. 重新构建完整 AI 系统
7. 接入 DeepSeek
8. 安装新的第三方依赖
9. 更换 Flutter/RN
10. 重写现有 Web 系统
11. 批量迁移数据
12. 做大范围代码清理
13. 创建正式语音评分系统
14. 创建新的正式学习记录
15. 改变 V1.3 / V2.0 已确定的核心原则

## 29. 产品最终闭环

```text
打开 APP
→ 看到学校正在使用的教材内容
→ 点击教材文字或音频热点
→ 听/读教材原声
→ 进行跟读/词汇/语法/听写/阅读/输出
→ 产生真实学习证据
→ 本地确定性分析
→ 必要时调用 DeepSeek
→ AI分析/评估/反馈/建议
→ 孩子决定是否继续、换内容或结束
→ 新证据进入长期学习记录
```

产品的最终价值不是“功能数量”，而是：孩子是否真的能够围绕学校教材持续学习，并知道自己的真实学习状态。
