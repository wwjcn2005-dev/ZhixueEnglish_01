## 1. 最高产品原则

> **教材是主线，学习是核心，孩子做主，AI 做助手。**

- **AI 负责**：分析、提示、辅助。
- **孩子负责**：选择学习内容、选择学习时间、选择学习节奏、决定是否继续、决定是否再次巩固。

**正式 UI 不得通过视觉或交互把 AI 变成学习流程的控制者。**

---

## 2. 正式 UI 总体气质

固定为：**清爽、专业、安静、轻科技感。**

设计定位：**学习工具感 > 教育产品感 > 游戏感。**

明确禁止：

- 儿童卡通风
- 糖果色
- 大量渐变
- 游戏化
- 积分
- 排名
- 徽章
- 连续学习天数
- 奖励动画
- 大面积 AI 装饰
- 满屏统计
- 强制推荐
- 自动连续学习

正式产品应该让初一学生感觉：**"这是一个我可以自己使用和掌控的学习工具。"**

---

## 3. 全局色彩规范

| 用途 | 色值 |
| --- | --- |
| 页面背景 | `#F6F7F9` |
| 内容卡片 | `#FFFFFF` |
| 主文字 | `#17181A` |
| 次文字 | `#6B7078` |
| 辅助文字 | `#9298A1` |
| 分割线 | `#E7E9ED` |
| 品牌主色 | `#1677FF` |
| AI 辅助色 | `#00A8E8` |
| 成功 | `#18A566` |
| 警告 | `#F59E0B` |
| 错误 | `#E5484D` |

使用规则：

1. `#1677FF` 是**用户操作与主要交互强调色**。
2. `#00A8E8` **仅代表 AI 辅助**。
3. AI 色**不得大面积装饰化使用**。
4. **"忘了"不是错误/失败**，不得使用强烈错误红色表达。
5. 成功/警告/错误颜色**只能用于真正的系统状态**，不得用于游戏化反馈。

---

## 4. 主题规范

第一版正式产品**默认采用浅色主题**。

原因：英语学习存在较长时间的阅读场景，浅色主题更适合：单词、音标、中文释义、句型、教材内容、列表阅读。

第一版**暂不实现完整深色主题**，但设计实现**不得故意阻断未来深色主题扩展**（颜色以语义化方式定义，不把色值硬编码进组件逻辑）。

---

## 5. 字体层级

| 层级 | 字号 |
| --- | --- |
| 页面标题 | 24sp |
| 重要大标题 | 28–32sp |
| 学习页面核心单词 | 36–44sp |
| 小标题 | 18–20sp |
| 正文 | 16sp |
| 辅助信息 | 14sp |
| 极辅助信息 | 12–13sp |

**必须强调**：学习页面中**"单词本身是第一视觉中心"**。不得让 "Vocabulary""学习" 等页面标题抢过单词本身。

---

## 6. 间距规范

- 基础单位：**4dp**
- 主要间距：**8 / 12 / 16 / 20 / 24 / 32dp**
- 手机页面左右主要内容边距：约 **20dp**

原则：**宁可留白，不要塞满屏幕。**

---

## 7. 卡片规范

卡片允许使用，但必须克制。默认：

- 白色背景
- 12–16dp 圆角
- 轻边界
- **不使用明显阴影**
- 卡片之间有足够留白
- **禁止卡片无限嵌套**

卡片的作用是**组织信息**，不是装饰页面。

---

## 8. 按钮规范

正式产品统一三类按钮：

1. **主按钮**：承担当前页面最重要的操作。
2. **次按钮**：承担返回、查看、辅助操作。
3. **文字按钮**：承担低优先级操作。

**按钮不得全部做成"主按钮"。**

---

## 9. 图标规范

采用：简洁、线性、现代的图标体系。

禁止：卡通图标、彩色 emoji 作为正式图标、复杂插画、大量装饰性图标。

后续 Android 实现应尽量统一图标来源和视觉重量。

---

## 10. 动效规范

动效原则：**轻、短、克制。**

允许：页面轻微进入过渡、点击反馈、列表轻微过渡。

禁止：烟花、粒子奖励、闯关动画、大型奖励动画、AI 机器人跳出、自动播放装饰动画。

**动效不能打断学习。**

---

## 11. 全局交互原则

正式产品统一采用：

```text
孩子主动选择 → 系统执行 → 系统反馈 → 孩子再次选择
```

禁止：

```text
系统推荐 → 系统自动开始 → 系统自动跳转 → 系统要求继续
```

**不得通过 UI 强迫孩子继续学习。**

---

## 12. 导航规范

第一版采用：**"首页 + 页面返回"，不采用复杂底部导航。**

原因：当前正式产品核心区域有限（教材、需要再学、最近学习（未来）、学习流程），单一学习流更适合页面逐级进入。

**系统返回与页面左上角返回必须保持一致。**

正式学习流程：

```text
首页
→ 教材中心
→ Unit
→ 资源列表
→ Study
→ Recall
→ Practice
→ Result
```

另一条入口：

```text
首页
→ 需要再学
→ 资源
→ Study
→ Recall / Practice
→ Result
```

**结果页不自动跳转。孩子自己决定下一步。**

---

## 13. 首页视觉原则

首页是**"学习导航大厅"**，第一屏只回答：

1. 我现在学什么？
2. 有没有需要再学的？
3. 我想去哪里学习？

建议核心区域：

1. 我的教材
2. 需要再学
3. 教材学习入口
4. 最近学过（未来）

禁止首页变成：数据仪表盘、AI 对话中心、游戏中心、学习排行榜、统计中心。

---

## 14. 教材中心视觉原则

教材是主线。正式产品必须让孩子明确知道：**自己正在使用哪一本教材。**

当前教材：外研社《义务教育教科书·英语 七年级上册》（2022 课标修订）。

教材中心主要提供：教材信息、按单元学习、词汇表、短语、句型。

**不要为了符合数据库结构而强制展示 Section / Activity 这些内部教材解析层级。**

---

## 15. Unit / Section / Activity 原则

- **Unit 可以成为孩子看到的导航页面。**
- **Section 不作为第一版独立页面。**
- **Activity 不作为第一版独立页面。**

原因：当前真实数据中 **Activity → learning_item 的结构化关联为 0/362**。

Section / Activity 目前更适合承担：**教材出处和内部结构**。

**不得为了数据库结构制造空页面。**

---

## 16. 资源类型视觉原则

正式产品资源类型：Vocabulary、Phrase、Sentence Pattern。

三者并列存在，但**学习体验不强行完全一致**。

- **Vocabulary**：第一优先级。拥有完整 Study → Recall → Practice → Result。
- **Phrase**：当前第一版以 **Study** 为主。
- **Sentence Pattern**：当前第一版以 **Study** 为主。

**不得为了形式统一而假造不存在的 Recall、判题或 AI 能力。**

---

## 17. Vocabulary Study 页面规范

核心原则：**"单词本身是页面视觉中心。"**

页面核心结构：单词 / 音标 / 词性 / 中文释义 / 教材出处。

主要操作：**"我看完了"**。

不要显示：

- `study`、`done`、`item_id`、`task_id`、`session_id`
- `CORE`、`contentpack`
- 内部技术状态、掌握度、正确率

**不要让技术实现泄漏给孩子。**

---

## 18. Vocabulary Recall 页面规范

核心内容：单词、音标 / 词性（有则显示）；**中文释义默认隐藏**。

提供：**"显示意思"**。

注意：**"显示意思"不产生学习记录。**

然后提供**三个等权选择**：

1. **"我记得"**
2. **"有点模糊"**
3. **"忘了"**

三个选项：

- 视觉权重基本一致
- 不做红绿答题暗示
- 不表示考试对错
- 不表示系统评价

它表达的是：**孩子对自己记忆状态的自我判断。**

---

## 19. Vocabulary Practice / Result 规范

正式产品**不得向孩子显示**：`correct`、`incorrect`、`partial`。

不得显示："答对""答错""系统判定""你已掌握"。

Result 页面只回答：

1. 我刚才学了什么？
2. 我刚才怎么判断自己的记忆状态？
3. 我接下来想做什么？

可提供：**"再学一次" / "回到词汇表" / "看看需要再学的"**。

**不自动跳转。**

---

## 20. "需要再学"规范

正式 UI **不使用**："当前错误池""当前薄弱池"。

孩子语言使用：**"需要再学"**。

分类：**"上次忘了" / "上次有点模糊"**。

首页可以显示数量。但不要设计：错题统计仪表盘、正确率、掌握率、雷达图、学习分数、排名。

**"忘了"不是失败。"有点模糊"不是失败。它们只是"下一次学习的线索"。**

---

## 21. AI UI 规范

**AI 不是首页主角。**

AI 颜色：`#00A8E8`，只用于真正的 AI 辅助信息。

未来如果增加 AI 分析 / AI 提示 / AI 讲解，必须保持：**"AI 是助手，不是老师控制台。"**

AI 不得替孩子：自动选择学习科目、自动选择资源、自动制定学习计划、自动强制继续、自动跳转。

**当前版本：AI 入口暂不实现。**

---

## 22. 状态规范

正式产品必须考虑：Loading、Empty、Error、Success、Back、重复点击、学习中离开。

状态信息使用孩子能理解的自然语言，例如：

- "还没有学过"
- "暂时没有需要再学的内容"
- "刚才的操作没有成功"

禁止暴露：HTTP、Exception、SQL、`session_id`、`task_id`、`item_id`、trace、stack trace 等技术信息。

---

## 23. 正式产品语言规范

内部程序语言：`study`、`done`、`practice`、`correct`、`incorrect`、`partial`、`current_error`、`current_weak` **不得直接出现在孩子 UI**。

正式 UI 优先采用：

- "我看完了"
- "我记得"
- "有点模糊"
- "忘了"
- "需要再学"
- "上次忘了"
- "上次有点模糊"

语言原则：**自然、简洁、不评判、不制造考试压力。**

## 24. 正式产品第一版页面基准

第一版核心页面：

1. 启动页
2. 首次使用
3. 首页
4. 教材中心
5. Unit 页面
6. 资源列表
7. Vocabulary Study

11. 需要再学

这些页面的视觉和交互设计必须以本文件为共同基准。

## 25. 明确不属于第一版

第一版暂不实现：

自动推荐、自动学习计划、自动连续学习、打卡、连续学习天数、积分、排名、徽章、游戏化奖励、掌握度百分比、正确率、雷达图、做题系统、自动判题、AI 对话、AI 出题、AI 讲解、TTS、发音评分、音频播放、多设备同步、家长端、教师端、复杂账号系统。

---

## 26. 与其他规范的关系

本规范**不能取代**项目最高指导原则："教材是主线，学习是核心，孩子做主，AI 做助手"。

优先级：

1. 如果未来页面设计与本规范冲突：**优先服从项目最高指导原则。**
2. 如果视觉设计与真实数据能力冲突：**优先服从真实数据和已冻结业务能力。**
3. **UI 不得为了视觉完整而虚构数据或业务能力。**
