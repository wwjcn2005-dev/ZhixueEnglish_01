**最高指导原则与开发规范 V1.3**

项目性质：以学校实际教材为核心的个人 AI 辅助学习 APP 当前教材：外研版初中英语教材 核心目标：帮助学生真正吃透学校英语教材

**V1.1 修订说明（2026-09-12）**

- 一句话总纲升级为：教材是主线，APP 负责整理与提效，学习是核心，孩子做主，AI 做助手。

- 新增“APP 负责整理与提效”的产品定位（二·4）。

- 新增“教材练习规范”独立章节（七），明确教材练习准确还原原则。

- 补充“教材真实性优先于开发便利”（四·5、十八）与教材练习结构化最低要求（五·4）。

- 补入已冻结的“发音资源与语音能力原则”（六·5）、“AI 数据复用优先原则”与“AI 反馈水平与阶段适配原则”（九）。

- 第一阶段 MVP 与最终验收标准补充教材练习与教材音频关联要求（十四、十八）。

- 正式确立 AI 职责为“分析 → 评估 → 反馈 → 建议”，并增加“没有证据，不评价”。
- 正式确立“学习进度 ≠ 掌握程度”。

## 二十八、练习与 AI 生成同步规则（2026-09-19 同步 · 当前唯一有效口径）

> 本节把已经实施并验证通过的设计依据、数据规则与 AI 规则同步进最高规范。
> 与本节冲突的旧条文一律失效；旧版本文件已移入 `docs/archive/`，**不是开发依据**。
> 页面结构与 UI 细节见《产品与UI架构总纲 V2.0》；AI 生成/校验/缓存细节见《AI 教材习题生成与题库入库流程规范》。

### 1. 产品总原则（不变）

教材是主线，学习是核心，孩子做主，AI 做助手。孩子自己决定学什么、什么时候学、学多少、是否继续；AI 只做分析、评价、提示、建议，不替孩子制定强制学习计划。

### 2. 页面与入口（当前唯一有效结构）

课程页（含首页）只有六个学习入口，顺序固定：

```text
跟读练习 → 听音辨意 → 词形练习 → 本课检测 → 自主练习 → 听读课文
```

- 听音辨意是**同一条入口**，`单词听辨｜句子听辨` 是其**内部模式**（不作为独立入口、独立学习模块）；
  **只显示当前 Section 有资源的模式**（显隐规则见第二十九章 §15·2），**不再要求模式常显**；
  "听音写词"已删除，不得再作为独立入口、独立学习模块或后续开发目标。
- 阅读能力并入"本课检测"（含阅读简答，必须有可输入输入框），不设独立"阅读理解"入口。
- 不得恢复：AI 专区 / AI 中心 / AI Dashboard / 功能分类页 / 已经合并或删除的旧独立入口。

### 3. 题量原则（固化）

**质量优先，宁缺毋滥**：合格资源不足时宁可不做（允许 0 题），不得为凑数而降低标准。

有多少资源就用多少资源，**没有固定题数**；资源不足时不硬凑（允许 0 题）。禁止"每题固定 N 个干扰项 / 每类固定 N 题 / 每页固定 N 题 / 必须四选一"。

### 4. AI 生成内容的数据边界（固化）

教材是唯一内容来源。AI 只允许在**本册教材 + 孩子已学过的前置教材**范围内重组、改写、替换、组合；不得因为模型"知道"某个词就把它自动加入初一教材学习内容。正确答案必须来自教材，不得由生成 AI 重新创造。

**AI 在题库中只做两件事（固化）**：
1. **补干扰项**（详见第 12 节）；
2. **按音频补全教材文本挖空**（详见第 16 节）。

**除此之外，AI 不承担题库内容生产**：**不得生成独立题**、不得自造题目、不得把教材练习变成 AI 自造练习。

句子听辨的正确答案由当前教材句确定；AI 干扰项可使用孩子**截至当前真实学习进度已经学过的 Section** 的教材资源：Starter 继续纳入合法已学内容，此前已学 Section 可以属于此前 Unit（可聚合到 Unit 表达），但不得使用未来尚未学习的 Section / Unit 或无正式资源依据的内容。学习进度以 **Section** 为核心粒度、由真实学习证据判定，与正在浏览的 Unit 无关；题目自身所在 Unit 属于本题教材上下文，始终可用。Appendix 不是教学 Unit，不进入资源范围。

### 5. AI 输出必须过确定性闸门（固化）

AI 只产生候选；能否进入系统由确定性规则决定，至少包括：正确答案重复、干扰项互相重复、空值/异常文本、evidence 缺失、教材阶段越界、confidence 不足、异常长度、以及"正确答案 + 句首/句尾少量词"的追加型干扰项。**（2026-09-29 补充）另加三项校验**：**合乎逻辑**、**匹配上下文**、**同类型（题型一致）**。

**校验与入库的关系（2026-09-29 明确）**：未经校验的 AI 输出**不得进入页面、缓存，也不得入库**；**经校验通过后，AI 补全内容允许入库** `questionbank.db` 作为素材。**入库不等于进入孩子界面**——是否展示仍由各功能自身的资源范围规则决定。

### 6. AI 调用时机与缓存（固化）

```text
离线生成 → 确定性校验 → 缓存 → 页面只读缓存
```

页面打开、切题、刷新、答题都不进行即时 AI 生成；不因刷新/切题/重复练习重复调用。缓存结果必须与教材版本、Unit/课时、具体教材资源、Prompt 版本、Rules 版本稳定关联；规则或 Prompt 版本变化后，旧结果不得当作新结果复用。不要新建第二套平行缓存体系。

### 7. 自主练习范围（固化）

自主练习覆盖**当前学习进度之前已经学过的全部有效内容**（以已经产生有效学习证据的 **Section 集合** 为基础；学完 U1 → U1；学完 U2 → U1+U2；依此类推）：**可以跨多个已学 Section、可以跨已学 Unit，不得只限制为当前 Section，也不得使用当前学习进度之后尚未学习的内容**；**当前页面所在 Section 只是当前上下文，不是自主练习资源池的额外过滤条件**。AI 可以在该范围内分析、选择重点、调整题型与难度、重新组合教材资源，但**不得把孩子能够自主练习的范围缩小为当前 Section/当前 Unit/若干推荐项/当前薄弱项**。仍遵守"有多少资源就用多少资源，没有固定题数"。

### 8. 教材原始数据长期保留（固化）

教材原始 PDF、官方 MP3 以及已经形成的正式教材数据资产，不得因为页面调整或数据优化而删除、破坏或覆盖。不因为某个页面（或当前 Demo）不使用某资源就删除正式资源；不重新解析教材来替代已经确认的正式数据，除非未来有明确的新需求。

### 9. 教材词汇层级（固化）

加粗重点词 = 核心 Vocabulary 学习资源；非加粗词 = "认识即可"的辅助词汇。两者不得混为同一学习层级；不得恢复"所有教材词汇同等学习目标"的旧规则。

### 10. 音频资源优先级（固化）

```text
官方教材音频 → 已确认的教材对应资源 → 必要时系统 TTS → 其他允许的 fallback
```

句子练习必须优先使用教材来源；不得重新引入任意互联网句子音频作为教材句子资源。

### 11. 练习页 UI（当前已确认）

顶部保留现有进度条，不显示"第 X 题 / 共 X 题"；主要内容位于屏幕中部；提交 / 下一题 / 重做 / 完成等主要操作位于底部操作区；单词、句子答案输入框内文字**水平居中**；听音类的**内部模式**（不是独立入口）**仅展示当前 Section 有资源的模式**，并在**同一行内展示**（手机窄屏也不主动换行成多行）。界面已经能表达功能时不再增加解释文字（不出现"听一遍""再听一遍""听后输入"等重复说明）。

### 12. 句子听辨 AI 干扰项（固化）

- 可使用：当前教材句子、当前 Unit 教材句子、教材 Vocabulary、Phrase、Sentence Pattern、已有 textbook evidence 及其他已允许的教材语义资源。
- 干扰项必须与正确答案相关、容易混淆、明确错误、符合初一阶段、有教材 evidence、不使用教材外内容。
- **禁止**把"正确答案 + 句首/句尾少量词"（例如在正确句后加 everyone / here / for you）当作主要干扰项手法；候选完整保留正确答案词序、且只在句首/句尾追加少量词的，直接过滤。
- 数量随合格资源动态决定：3 个合格干扰项 → 4 选项；2 个 → 3 选项；1 个 → 2 选项；0 个 → 不硬凑，走既有回落机制。

### 13. Demo / Spike 与正式实现的区分（固化）

正式教材数据、学习数据（`learning.db`）与正式 Web 属于正式资产；Demo 中的确定性模拟 AI、Spike 输出、Demo 缓存与测试专用数据只是**验证机制**，不得描述成"正式生产系统已经全面采用"，也不得据此直接扩展为正式架构。真实 AI 接入属于未来的正式实现，须按 AI 规范单独实施与验证。

## 一、最高指导原则

本文件是本项目的最高指导原则。今后所有产品设计、数据设计、AI 设计、程序开发、教材处理、功能增加和版本迭代，都必须服从以下原则。

### 1. 教材是主线，AI 是辅助

本 APP 不是一个以 AI 为中心的聊天产品。教材才是主线。AI 的职责是分析、解释、提示、诊断、辅助训练。AI 不负责决定孩子今天必须学习什么，也不负责替孩子完成学习。

### 2. 孩子拥有学习主动权

AI 负责分析、提示、辅助；孩子自己决定学习哪一科、什么时候学习、学习节奏、是否继续巩固。

- 不强制每日学习、打卡或完成计划。

- 不强制按照 AI 推荐路线学习。

- 不使用积分、排行榜、勋章等游戏化机制刺激学习。

- AI 推荐只能作为建议。

- APP 应帮助孩子知道自己哪里不会、接下来可以怎么学，而不是替孩子安排整个学习生活。

### 3. 第一目标不是刷题，而是真正吃透教材

产品首先解决的问题不是“怎么让孩子多做英语题”，而是“学校英语教材到底有没有真正学会”。

说明：“孩子做主”的准确含义见第二十二章：自主权不等于取消结构；孩子决定学习节奏、是否进入、是否暂停、是否回看，系统提供符合教材学习逻辑的推荐顺序但不强制。

## 二、产品定位与明确边界

### 1. 正确定位

本 APP 是一个围绕真实学校英语教材建立的 AI 辅助学习空间，把教材内容、听力、词汇、句型、语法、课文和训练组织起来，并利用 AI 帮助孩子理解和发现问题。

### 2. 第一阶段明确不做

- AI 聊天老师

- 自动作业机

- 无限题库和无限题目生成

- 积分、排行榜、勋章、连续打卡等游戏化系统

- 家长监控后台和学校 LMS

- 一开始就建设复杂口语、作文、视频老师、自适应课程等高级系统

- 自动决定孩子每天必须学习什么

### 3. 与“智学小四门”的关系

英语 APP 与“智学小四门”保持产品独立。可以复用 Android、数据库、AI 调用、真机测试和开发治理方面的技术经验，但不得未经重新审视直接复制小四门的业务模型、学习模型和数据结构。

### 4. APP 负责整理与提效，而不是替代教材（V1.1 新增）

APP 不是教材的替代品。教材负责提供真实学习内容。

APP 主要负责：

- 整理教材；

- 结构化教材；

- 关联教材配套音频；

- 整理教材练习；

- 方便孩子查找；

- 减少翻找和切换；

- 让学习过程更加连续；

- 保存真实学习行为；

- 在真正需要时提供学习辅助。

不要为了“功能丰富”而无意义增加大量教材之外的内容。

判断一个新功能是否值得开发，首先要问：这个功能是否让孩子更方便、更准确、更高效地学习学校正在使用的教材？

## 三、核心学习闭环

整个系统围绕以下核心闭环设计：

教材 → 听/读 → 理解 → 词汇 → 句型 → 语法 → 训练 → 诊断 → 巩固 → 再测

教材内容优先于练习数量。系统的价值在于帮助孩子真正理解、记住并使用教材，而不是制造大量题目。

V1.1 起，在原有闭环基础上进一步明确为：教材素材整理 → 教材学习 → 教材练习 → 学习反馈 → 发现问题 → 针对性巩固 → 再测。

最终标准不是功能多少，而是：孩子是否真的能够通过 APP 更高效地吃透学校教材。

其中：教材练习优先于系统自建练习（详见“七、教材练习规范”）。

## 四、教材是整个系统的事实源

### 1. 原始教材必须保留

现有外研版电子教材和配套音频是系统基础。原始 PDF、图片、音频必须只读、原样保存，不得删除、覆盖、改写或用 AI 重写。

### 2. 彩色原版 PDF 不是问题

原版教材中的彩色插图、活动编号、表格、图片、页面布局和颜色均可能属于教材信息的一部分。正确做法不是把教材变成纯文字，而是让原教材负责保存真实样貌，让结构化数据负责程序理解。

### 3. 四层数据结构

- 第一层：原始教材层——原始 PDF、图片、音频，只读不可破坏。

- 第二层：教材结构层——教材、Module、Unit、Activity、Page、Audio 等结构。

- 第三层：教材内容层——单词、短语、句子、对话、阅读、语法、听力任务、图片等。

- 第四层：学习模型层——学习目标、知识对象、训练、错误类型、薄弱点、掌握状态、巩固记录、AI 分析。

### 4. 教材内容 ≠ 知识点

一个教材句子可能同时涉及词汇、词形、句型、语法、句法和语义。因此一个教材内容对象可以对应多个学习对象，不能简单地把“一句话”等同于“一个知识点”。

### 5. 教材真实性优先于开发便利（V1.1 新增）

当页面设计便利、程序实现便利、数据结构便利、AI 能力、功能数量、开发速度与真实教材发生冲突时，优先保护真实教材。

宁可暂时少一个功能，也不能通过猜测、改写或过度简化破坏教材真实性；无法确认的教材内容必须明确标记为待确认，不得猜测补齐。

## 五、教材解析与结构化规范

### 1. 先侦察，后处理

首先判断 PDF 是文本型、扫描型还是混合型；先测试少量页面（建议 5～10 页），确认文字、页面结构、Activity、图片、页码和音频关联均可靠后，再处理整本教材。

### 2. 本地优先

- PDF 解析优先使用本地程序。

- 音频文件扫描和候选匹配优先使用本地程序。

- JSON、CSV、Markdown 等中间数据优先本地生成。

- 如需音频转写，原始音频必须保留，转写结果只能作为辅助；转写结果不得作为教材事实，也不得作为教材答案来源，不得据此生成正式答案（见七·9）。

- 能用本地程序完成的机械性工作，不调用云端 AI。

### 3. 所有识别结果必须可追溯

任何结构化内容都必须尽可能能够定位到原始教材的 Module、Unit、Activity、Page 或具体音频文件，并保存识别置信度和审核状态。

### 4. 教材练习结构化的最低要求（V1.1 新增）

教材结构化不仅要识别 Module、Unit、Activity、Page 和 Audio，还必须尽可能识别：

- 练习题型；

- 题目；

- 选项；

- 填空位置；

- 匹配关系；

- Activity 与 Audio 的关系。

教材练习的结构化必须以真实教材为依据，不得因程序实现便利而改写教材事实。

## 六、听力系统规范

### 1. 听力是第一阶段核心功能

教材吃透必须包含教材听力，因此教材配套原始音频属于第一阶段核心内容，不应被推迟到后续版本。

### 2. 核心流程

播放 → 完成教材听力任务 → 由系统/规则/AI 批改 → 重听 → 查看文字 → 理解 → 诊断

说明：流程中的“检查”责任主体是**系统/规则/AI**，不是孩子。系统依据教材事实与可靠答案进行批改或分析（见七·7、七·8）；教材没有可靠答案来源时，系统明确说明“暂不判分”并标记 NEEDS_REVIEW，而不是让孩子自己判断。

### 3. 原始音频优先

第一阶段优先实现教材原始音频与 Activity 的准确映射。以后可增加逐句播放、原文开关、关键词提示、精听和 AI 听力诊断。

限定：逐句播放、原文开关等属于后续能力，只有存在教材结构提供的明确、可验证边界时才可实现。**不得为了做逐句播放或制造“短听力”而切割官方音频，也不得用音频时长、文字长度或 AI 判断来推算切点**（见六·9）。

### 4. AI 生成听力的边界

AI 生成听力属于后续辅助训练，不能替代教材原始音频；系统必须明确区分“原始教材内容”和“AI 生成内容”。

### 5. 发音资源与语音能力原则（V1.1 并入）

**（1）发音是独立的学习资源能力**

单词文本、Phrase / 语块、Sentence Pattern / 句型、发音信息、IPA 与实际音频属于不同层次的资源，不得混为一个字段或一个概念。发音能力应作为 Vocabulary、Phrase、Sentence Pattern 等学习资源的通用辅助能力存在，而不是强制建立一个独立的大型“发音学习入口”。

（2）音频来源必须分级：官方教材音频 &gt; 系统标准 TTS &gt; AI / 云端 TTS

- 第一优先级：官方教材音频。教材存在对应官方音频时必须优先使用；官方教材音频是教材真实性最高的语音资源。系统必须能够区分官方教材原声、系统 TTS、AI / 云端生成语音，不得将生成语音标记为教材官方音频。

- 第二优先级：系统标准 TTS。教材没有对应官方音频，不代表必须调用 AI。普通单词、普通 Phrase 等明确的英语文本，优先考虑系统可用的标准英语 TTS 作为低成本发音兜底，并应尽可能成本低、稳定、即时、不依赖大模型、不因普通单词发音而产生不必要的 AI 调用。

- 第三优先级：AI / 云端高质量 TTS。属于更高阶的可选能力；不得因为“某个单词没有官方音频”就默认调用大模型。应优先用于真正具有增量价值的场景，例如更自然的句子朗读、语音示范、不同朗读方式、朗读训练、后续纠音辅助，以及重音、节奏、连读、停顿等语音学习能力。必须考虑 AI 成本，普通单词发音不得成为无必要的高频 AI 消耗来源。

**（3）发音资源的三个概念必须分离**

pronunciation_text：需要朗读的原始文本（例如 peaceful）；pronunciation_ipa：该文本对应的 IPA 等发音信息（例如 /ˈpiːsfəl/）；audio：实际可播放的声音资源。三者不是同一个东西。尤其禁止让 AI 猜测一个发音后，直接把猜测结果永久当成教材事实写入教材数据库；教材事实与系统生成能力必须保持可追溯的边界。

**（4）发音在产品界面中的出现原则**

发音功能应自然嵌入学习对象，而不是制造新的复杂入口。

- Vocabulary：单词卡提供「单词 + 音标 / 发音信息 + 播放入口」，默认不自动播放，由孩子主动点击。

- Phrase：语块同样提供播放入口，应支持播放整个语块，而不仅仅是逐词朗读。

- Sentence Pattern / 例句：提供完整句子的朗读；后续可进一步支持重音、节奏、连读、停顿、语调等更自然的能力，但这些属于后续能力。

**（5）AI 在发音领域的定位**

AI 负责分析、提示、辅助，不负责替代教材资源。

- AI 可以做：朗读分析、纠音辅助、重音分析、节奏分析、连读 / 停顿分析、学习建议、后续个性化语音训练。

- AI 不应做：无必要地为每个没有官方音频的单词调用大模型；把生成音频冒充教材官方音频；在没有可靠教材依据时擅自修改教材发音事实；用 AI 生成内容替代教材原始语音资源。

**（6）发音来源必须可追溯**

如果未来进入正式数据模型设计，应能够区分至少以下概念：pronunciation_source（发音信息来自哪里）、audio_source（实际播放声音来自哪里）、audio_status（是否存在、是否生成、是否可播放）、locale（英语语言 / 地区环境）、voice_type（官方音频、系统 TTS、AI voice 等）、fallback_level（当前采用的是哪一级语音资源）。本条仅写入设计规范，不得因此修改现有数据库。

**（7）教材官方音频审计原则**

未来正式实现发音资源之前，必须先进行教材发音资源只读审计，至少包括：现有教材 MP3 清单；每个 MP3 的内容与适用范围；Vocabulary 与官方音频的对应关系；官方音频覆盖率；Phrase / Sentence Pattern 是否存在对应官方音频；PDF 是否提供音标等发音信息；哪些内容需要系统 TTS 兜底；哪些内容未来才需要 AI / 云端 TTS。在完成上述只读审计之前，不得直接批量生成 AI 音频。

**（8）与现有教材资源原则保持一致**

教材官方内容是事实来源；系统 TTS 是技术兜底；AI 是辅助能力。不得反向让 AI 生成内容成为教材内容。

（9）与 Vocabulary / Phrase / Sentence Pattern 建设的关系

- Vocabulary：重点词与认识即可词的原有规则不变；发音资源不能改变 textbook_emphasis、learning_requirement、review_status、item_id、content_hash 等已有教材数据语义。

- Phrase：Phrase 仍然是独立资源类型，不能因为一个 Phrase 有发音，就把它并入 Vocabulary。

- Sentence Pattern：Sentence Pattern 仍然是独立资源类型；完整句子朗读与单词 / 语块发音属于不同层级。

**（10）成本原则**

AI 费用是系统长期运行的重要约束。因此普通单词发音必须优先使用已有官方音频或低成本 TTS，不得出现“打开单词页面 → 自动调用 AI → 生成一次发音”这种高频、无必要的调用模式。发音播放应尽可能本地、缓存、可复用、不重复生成、不因页面浏览产生 AI 调用。

### 6. 教材听力与教材练习的严格匹配原则（V1.1 新增）

教材听力音频与教材练习之间的关系必须建立在可靠证据基础上。

以下弱证据只能作为候选线索，不得直接用于确认匹配：

- MP3 文件名；

- Activity 编号；

- 文件顺序；

- 页面顺序；

- 目录位置；

- 简单编号推测；

- 页面位置相邻、文件相邻；

- 同一页存在多个活动时的相邻关系；

- 音频时长与文本长度的比例关系（既不能据此确认匹配，也不能据此确定片段边界）。

特别规定：**同一页存在多个活动时，不得仅按页码或位置把题目、正文、对话或音频串到一起**。此类关系必须锚定到具体活动；无法确定时标记 NEEDS_REVIEW（见六·8、十一·8）。

正式确认时应综合：教材页面 + Activity + 教材文字 + 题目结构 + 音频文件信息 + 其他可验证教材证据，进行严格比对。

如果无法确认，宁可标记为待确认，也不得强行匹配。绝对禁止为了提高所谓“音频覆盖率”而进行无证据推断。

### 7. 听力音频不是孤立资源（V1.1 新增）

教材听力应尽可能建立：Unit → Section → Activity → Question → Audio，而不是简单的 Unit → Audio。

孩子在 APP 中听到音频后，应能够完成教材原本要求完成的任务：教材原本是选择题，就让孩子选择；原本是填空题，就让孩子填写；原本是匹配题，就让孩子完成匹配。

### 8. 教材文字—音频—上下文—Question 严谨锚定原则（V1.2.1 新增）

教材中的下列对象必须形成**可验证、可追溯的确定性关系**：

教材文本 → 上下文 → 官方音频 → 教材活动 → Question → 回答区域

- 上述关系中的每一条都必须能够指出教材依据（页码、活动号、内容块、音频文件、可验证结构证据），并保留审核状态。

- 只有存在教材事实或确定性结构证据时，才允许建立映射；正式教材事实优先于程序推断，两者冲突时以教材事实为准。

- 下列因素**只能作为候选线索，不得单独用于推断关系**：页面相邻；文件相邻；活动编号相近；音频时长；文字长度；文件名相似；AI 语义判断；“看起来应该对应”；同页存在的其他内容。

- 同一页存在多个活动时，**不得仅按页码**把题目、正文、对话或音频串到一起。

- Question 必须锚定到明确的教材活动与上下文；无法确定时不返回题目、标记 NEEDS_REVIEW，不得串题。

- 听力材料与 Question 必须锚定：一段音频可以服务该活动的多道题，但每道题都必须锚定到同一活动，不得跨活动。

- **正文、Dialogue、Reading 等教材内容不能因为解析方便而被当作 Question 的题干。**

- 锚定关系只能是只读派生：不得反向修改教材事实（contentpack、教材原文、音频文件）。

### 9. 官方音频完整性与切分原则（V1.2.1 新增）

1. 出版社已经按活动提供独立官方音频时，默认使用**官方完整音频**。

2. 不得因为“文字短、音频长”就认为音频错误。

3. 不得根据文字长度推测音频播放范围。

4. 不得根据音频时长推测题目边界。

5. 不得使用 AI 猜测音频切点。

6. 不得为了 UI 方便而人为制造未经验证的音频片段。

7. 只有存在教材结构提供的明确、可验证边界时，才允许建立片段级映射。

8. 无法确定片段边界时：保留官方完整音频；保留完整对应教材文本与上下文；标记 NEEDS_REVIEW；禁止自动猜测。

9. 结论口径：**准确锚定优先于切割；官方完整音频优先于未经验证的切割。** 本规范不要求把听力切成短句或短片段。

10. 音频播放行为本身只表示“孩子播放过一次音频”，**不产生正式判断证据**（见二十二·5）。

11. 现状事实（P2-6-F-0 实测，2026-09-13）：当前 54 条官方音频为 41 条活动级 + 13 条板块级，无跨活动音频，SPLIT_REQUIRED = 0。

## 七、教材练习规范（V1.1 新增）

### 1. 教材练习属于教材核心内容

教材上的练习属于教材核心内容，而不是普通参考素材。教材练习数字化的目标，是准确还原教材练习，而不是重新设计一套类似练习。

### 2. 必须尽可能保留教材层级

必须尽可能保持：Module → Unit → Section → Activity → Exercise → Question，并保留能够确认教材事实的信息，例如：

- 题号；

- 题干；

- 选项；

- 填空位置；

- 匹配关系；

- 图片 / 表格等必要结构；

- 教材页面；

- 对应官方音频；

- 原教材要求。

### 3. 原题型必须尽可能还原

教材是 Listen and choose，原则上就实现选择题；是 Listen and complete，就实现填空题；是 Listen and match，就实现匹配题；是 Listen and judge，就实现判断题；是 Reading choice，就实现阅读选择题；是 Vocabulary fill，就实现词汇填空。

不得因为程序实现方便，把不同教材题型统一降级成“完成 / 未完成”之类的泛化任务。

### 4. APP 可以优化操作，但不能改变教材内容

允许：手机端重新布局；优化按钮与交互；把相关教材资源集中呈现；提供重听、重新作答等便利操作。

禁止：擅自改题干；擅自改选项；擅自改题目要求；擅自改变题型；擅自删除必要教材信息；自行猜测教材答案。

### 5. 教材练习优先于系统自建练习

系统首先应该帮助孩子完成真实教材练习，而不是优先生成大量系统自建练习。系统自建练习只有在以下情况下才有意义：

- 服务明确的教材学习目标；

- 针对孩子已经暴露出的薄弱点；

- 帮助孩子进一步理解或巩固教材。

不得用大量 AI 生成题目替代真实教材练习。

### 6. 无法确认不得猜测

无法确认的教材内容、题型或音频关系必须明确标记为待确认；待确认信息只存在于开发数据与报告中，不得进入孩子界面，也不得为了完整度而猜测补齐。

### 7. 正式教材练习批改责任原则（V1.2.1 新增）

正式教材练习必须经过系统/规则/AI 的正式批改或分析后，才能形成正式学习证据。

基本链路：

孩子选择练习 → 孩子作答 → 系统/规则/AI 批改 → 结果 → 错误与薄弱分析 → Evidence → Mastery / Diagnosis

【孩子的自主权】（本规范自始至终不变）

孩子决定：学什么；哪个单元；哪项内容；什么时候学；学多久；是否暂停；是否继续；是否复习；是否进行阶段验证。

【系统与 AI 的专业职责】

系统/规则/AI 负责：批改；判断正确 / 错误 / 部分正确；错误分析；教材证据解释；Evidence 形成；Mastery 计算；Diagnosis；后续建议。

必须明确：**孩子拥有学习选择权，但不承担系统应该完成的专业批改责任。** 专业判断、批改、错误分析与证据形成不推回给孩子。

因此：不得把“请你自己判断做得怎么样”作为正式教材练习的核心闭环；不得把“我完成了这次练习”作为正式正确或错误证据。

同时说明：教材没有可靠答案事实时，系统的做法是**暂不判分并明确说明原因**（标记 NEEDS_REVIEW），这属于系统职责范围内的事实说明，**不等于把判断责任推回给孩子**。

### 8. 客观题与主观题的批改边界（V1.2.1 新增）

【客观题】包括但不限于：choice（选择）、judge（判断）、fill_blank（填空）、match（匹配）。

- 如果存在可靠的教材答案事实：优先使用**确定性规则判分**。

- 不存在可靠答案事实时：不判分，标记 NEEDS_REVIEW（见七·9、十一·8）。

- 不得：AI 猜答案；用常识替代教材答案；用语言模型生成教材答案；根据上下文推测答案并写入正式数据。

【主观题】包括但不限于：short_answer（简答）、writing（写作）、speaking 相关的开放任务。

- 可以使用 AI 进行：语义分析；教材证据对照；评分或判断；错误类型分析；改进建议。

- AI 必须受**教材事实、教材上下文、题目要求、评分标准**约束。

- AI 不能创造教材事实；评分要点必须由人工定义并留档；判断结果必须与孩子原始作答一起保存以便复核。

### 9. 答案事实原则（V1.2.1 新增）

**教材答案是独立于教材内容事实的另一类事实。**

教材内容事实：正文；对话；阅读；词汇；句型；活动；音频。

教材答案事实：choice 的正确选项；judge 的判断结果；fill_blank 的答案；match 的对应关系；其他需要标准答案的客观题。

- 即使教材内容事实完整，**也不能推导出可靠教材答案**。

- 没有可靠答案来源时：**禁止自动补答案**，状态进入 NEEDS_REVIEW，等待教师用书、官方答案或人工核验的可靠来源。

- 实测基线（P2-6-F-0，2026-09-13）：正式练习 157 条、题目 360 道，可靠答案为 0；教材学生用书没有答案页，项目内没有教师用书答案。因此客观题在人工核验答案之前**不判分**。

### 10. 自我判断与完成动作的证据边界（V1.2.1 新增）

下列表述均不能直接产生 correct / incorrect / partial，也不能直接产生正式 Evidence：

- “我完成了”；

- “我觉得会了”；

- “我觉得做对了”；

- “我觉得做得不错”；

- “我自己判断掌握了”。

尤其不能把 `done` 作为正式正确或错误证据。

- 完成动作只能表示：**发生过一次学习或作答行为**。

- 完成动作不能表示：答案正确；已经掌握；掌握较稳定。

- 正式 Evidence 必须来自：可验证的规则判分；可靠答案事实；AI 批改结果；明确的正式判断结果。

- 自评与完成动作可以作为**事实记录**保留（例如单元反思、是否看过、是否听过），但不得进入有效判断证据。

本条与第二十二章第 5 条一致，是对该条的强化。

## 九、AI 功能边界

- 允许 AI 解释当前教材内容和问题。

- 优先给提示和思路，而不是直接给出解题过程与最终答案。

- 说明：本条针对**解题辅导与提示**场景。**批改不受此限**——客观题在存在可靠答案事实时必须给出正确 / 错误 / 部分正确的正式判定；教材没有可靠答案事实时，不猜答案、不编造答案，标记 NEEDS_REVIEW（见七·8、七·9）。

- 教材答案不能由 AI 生成：可靠答案事实只能来自教师用书、官方答案或经人工核验的可靠来源（见七·9）。

- AI 诊断应尽可能说明错误原因。

- AI 生成训练必须服务于明确的学习目标或薄弱点。

- AI 解释必须锚定当前教材、Module、Unit 或题目上下文。

- 静态页面浏览不应无意义调用 AI，应优先使用缓存和规则。

- AI 生成内容必须与原始教材明确区分。

禁止 AI 替换原教材、随机大量生成题目、通过无限聊天成为产品核心，或自动决定孩子的学习路径。

**AI 的价值边界（V1.1 补充）**

AI 的价值是在真实教材和真实学习行为基础上提供辅助，而不是成为 APP 的主要内容生产者。

AI 可以：解释；提示；分析；诊断；辅助批改；根据真实薄弱点提供少量针对性训练。

AI 不应该：替代教材；改写教材事实；把教材练习变成 AI 自造练习；为了增加内容而大量生成题目；自动决定孩子的学习路径。

AI 辅助的准确边界：AI 可以批改、分析、解释、归纳错误并给出建议（见七·7、七·8），但**不得创造教材事实**——不得生成或改写教材正文、题干、选项、答案、音频与音频片段，也不得把 AI 生成的结论写入教材内容事实。

继续严格执行：AI 建议 → 孩子决定 → 系统执行，以及已有的 AI 数据复用、成本控制和教材 / AI 数据隔离原则。

### AI 数据复用优先原则

AI 已经调用并产生、且仍然有价值的数据，必须优先复用。禁止因为以下原因无意义地再次调用 AI：页面重新进入、页面刷新、重复分析、重复学习、任务重建、入口变化、相同资源再次访问、相同学习内容再次展示。

核心顺序：已有有效 AI 数据 → 优先查找 → 可以复用则直接复用 → 只有缺失、失效、不适用或明确要求重新生成时 → 才允许新的 AI 调用。

AI 调用优先级（正式冻结）：

- Level 0：已有完全匹配且有效的 AI 数据 → 直接复用 → AI 调用 0 次。

- Level 1：已有数据通过 item_id / textbook_id / snapshot_id / 数据版本等确认仍然适用 → 直接复用 → AI 调用 0 次。

- Level 2：已有数据部分可复用，只缺少部分内容 → 只补充缺失部分 → 禁止整包重新生成。

- Level 3：已有数据因教材版本、规则、prompt、模型等发生实质变化而失效 → 才允许重新生成。

- Level 4：完全不存在可用数据 → 才允许首次生成。

- Level 5：孩子明确要求重新分析 / 重新生成 → 可以生成新 AI 数据 → 旧数据必须保留其历史关系 → 禁止无痕覆盖旧数据。

AI 数据与教材资源隔离：AI 产生的数据属于 AI 辅助数据，不得反向修改教材事实；AI 不得写入或改变 Vocabulary、Phrase、Sentence Pattern、原始教材内容、教材事实字段以及已冻结的教材资源身份。允许的关系是教材资源 → AI 分析 → AI Artifact；禁止的关系是教材资源 → AI 分析 → 修改教材资源。

AI 与学习行为的边界：真实学习行为只能产生于孩子的实际学习行为，错误、薄弱、复习需求等学习事实不能由 AI 凭空制造。AI 可以分析已有学习行为、分析已有错误、解释错因、提供提示、提供复习建议、辅助理解；AI 不可以修改 LearningRecord、修改历史学习事实、直接决定 MasteryState、自动创建 LearningTask、自动创建 TaskItem、自动安排学习、自动替孩子选择学习内容。原则仍然是：AI 建议 → 孩子决定 → 系统执行。

展示与生成分离：“展示 AI 数据”与“生成 AI 数据”必须严格分离。页面打开、页面刷新、页面切换、列表展示、查看历史记录等只读行为，不得因为展示需要而自动调用 AI；如果已有 AI Artifact，优先读取并展示已有结果。

AI 成本控制：AI 调用必须具有明确业务目的。禁止重复生成相同结果、无意义刷新导致重复调用、页面生命周期触发 AI、为了填充界面而调用 AI、为了制造数据量而调用 AI、已有有效结果却再次整包生成。项目应优先：规则 → 已有数据 → 缓存 → 增量补充 → 最后才是新的 AI 调用。

（本原则为受控增补，依据 P1-06-C2 审计冻结；增补时间 2026-09-12。）

### AI 反馈水平与阶段适配原则

AI 负责分析、解释、诊断、提示和辅助练习，但所有 AI 反馈必须符合孩子当前的初中阶段、当前年级、当前教材版本、当前教材进度以及当前学习内容。

AI 应优先使用孩子已经接触或教材明确提供的词汇、句型、语法和表达方式；如因解释需要使用超出当前学习范围的内容，只能作为辅助说明，并应控制数量和难度，不得将超出当前阶段的内容包装成当前学习要求。

AI 不得为了体现“高级”“专业”而无必要扩大知识范围，不得使用明显超出孩子当前学习阶段的词汇、语法体系、表达方式或练习难度。

AI 反馈的评价标准不是内容是否高级，而是孩子当前是否能够理解、掌握并继续学习。本原则适用于 AI 解释、AI 提示、AI 诊断、AI 示例、AI 练习、AI 批改反馈及其他 AI 生成内容。

补充（P2-5 同步）：AI 的完整角色边界见第二十二章——AI 不得决定孩子学什么、不得自动安排学习路径或推进学习、不得用分数排名等级评价孩子、不得在证据不足时做确定性结论。

## 十、学生学习体验

### 1. 学习主动权

孩子可以自主选择 Module、Unit、词汇、句型、语法、课文、听力或训练，并自行决定学习节奏。

### 2. 掌握状态

建议至少采用：未学习、正在学习、初步掌握、掌握较稳定、需要再次巩固。

### 3. 错误不只记录对错

系统应尽可能区分词汇、词形、拼写、语法规则、句型结构、阅读理解、题目指令等原因；无法可靠判断时，应允许标记为待进一步判断，而不是武断归因。

说明：“待进一步判断”的**判断主体是系统**，判断依据是**教材事实与可靠答案**；这类内容进入 NEEDS_REVIEW（见十一·8），不得把判断责任推给孩子，也不得以孩子自评代替。

### 4. 学习进度与掌握度分离

学校教材进度表示“学到哪里”，个人掌握度表示“实际上掌握得怎么样”，两者必须独立保存。

补充（P2-5 同步）：学生的学习自主权与系统责任边界见第二十二章；系统可建议、可提示，但不得强迫、不得自动推进。

同时说明：本章第 2 条列举的“掌握状态”以第二十二章第 4、5 条的定义与证据要求为准——“学过”只是事实记录，“掌握较稳定”必须由多维证据支持；这些状态只用于系统判断是否给出提示，不得作为对孩子的等级评价，也不得仅凭单次结果变更。

## 十一、技术与开发治理原则

### 1. 开发流程

侦察 → 提取 → 结构化 → 审核 → 建模 → 开发 → 验证 → 扩展

### 2. P0：教材与音频只读侦察

Codex 只扫描和分析真实教材与音频，输出审计报告，不修改原始资料和正式 APP 工程。

### 3. P1：教材结构化

输出 JSON、CSV、Markdown 等中间结果，暂不写入正式学习数据库。

### 4. P2：人工审核

审核 Module、Unit、Activity、Page、Text、Vocabulary、Grammar、Listening 和 Audio mapping。

### 5. P3：建立学习模型

在教材结构可靠后，再设计学习对象、掌握度、错误类型、训练、巩固、学习记录和 AI 辅助。

### 6. P4：APP 开发

最后进入正式 Android APP，实现教材 → 学习 → 训练 → 诊断 → 巩固 → 再测的闭环。

### 7. 教材练习与听力资源的正式处理流程（V1.1 新增）

在教材练习与听力资源的正式处理场景中，原有流程可细化为：真实教材扫描 → 结构识别 → 教材文字提取 → 官方音频扫描 → 文字 / 音频严格比对 → Activity / Question 建模 → 题型识别 → 答案核验 → 结构化数据 → APP 呈现 → 自动测试 → 真机验证。

如果关键教材证据不足，不得猜测补齐：应停止扩展并报告，等待人工确认。

### 8. NEEDS_REVIEW 规则（V1.2.1 新增）

任何无法由教材事实确定的内容，必须进入 NEEDS_REVIEW，包括但不限于：题目结构；题目与上下文的关系；音频与文本的关系；音频片段边界；选择题选项；填空位置；教材答案；主观题评分标准；其他不确定的教材事实。

NEEDS_REVIEW 的含义是：

- **禁止自动修复**；

- 等待可靠事实来源或人工核验。

NEEDS_REVIEW 不是“AI 帮忙猜一下”，也不是“先补上再核验”。

NEEDS_REVIEW 内容只存在于开发数据与报告中，不得进入孩子界面（与七·6 一致）。

解除 NEEDS_REVIEW 的唯一途径：出现可靠事实来源（教师用书、官方答案、人工核验结论）并记录审核人与依据。

如果发现教材结构异常、音频无法匹配、文件缺失或解析结果不可靠，应停止扩展并报告问题，不得自行猜测后继续实施。

## 十六、版本迭代原则

任何新增功能必须回答四个问题：

- 它是否帮助孩子真正吃透教材？

- 它是否可以不用 AI 完成？如果可以，应优先采用规则或本地实现。

- 它是否增加了孩子的学习负担？如果增加，应重新评估。

- 这个功能是否减少了孩子使用教材时的无效操作？（是否更容易找到音频、更容易找到练习、更容易完成教材题目、更容易回到自己不会的内容；是否减少无意义翻找；是否让教材学习更加连续。）

如果答案是否定的，则不因为“技术上可以做”而优先开发。

## 十七、功能优先级

教材真实性 → 教材学习闭环 → 发现真正不会什么 → 针对性巩固 → AI 辅助效率 → 体验优化 → 高级功能

## 十八、最终验收标准

第一版不以“功能很多”为成功标准，而以“孩子拿着学校正在学习的外研版教材，能够真正用这个 APP 把一个单元学明白”为核心验收标准；孩子使用的应是学校正在学习的教材本身，而不是一套与教材相似的替代内容。

至少应能完成：选择教材 → Module → Unit → 学习教材内容 → 听教材音频 → 学习词汇 → 学习句型 → 理解语法 → 理解课文 → 完成教材练习 → 完成教材听力任务 → 由系统/规则/AI 批改 → 发现问题 → 针对性巩固 → 再次测试，并且以上内容对应真实的学校教材，而不是 APP 自造的相似内容。

说明：验收标准中的“批改”由系统/规则/AI 完成（见七·7、七·8）；教材没有可靠答案事实时，系统明确说明暂不判分并标记 NEEDS_REVIEW，不得让孩子自己判断，也不得编造答案。

## 十九、冲突时的最终裁决顺序

1. 保护真实教材

2. 服务“真正吃透教材”

3. 保护孩子自主学习权

4. 保证数据可追溯、可审核、可恢复

5. 控制 AI 成本

6. 控制系统复杂度

7. 最后才考虑炫酷和扩展功能

当开发便利（页面设计、程序实现、数据结构、AI 能力、功能数量、开发速度）与真实教材发生冲突时，一律优先保护真实教材。

## 二十、项目一句话总纲

**教材是主线，APP 负责整理与提效，学习是核心，孩子做主，AI 做助手。**

不追求 AI 有多聪明，不追求题有多少，也不追求功能有多复杂，而是让孩子真正把学校教材听懂、读懂、理解、会用，并知道自己哪里还没有真正掌握。

APP 的核心价值，是把学校教材及其配套学习素材准确整理成一个更加方便、高效的学习空间，让孩子能够更方便地听懂、读懂、理解、练习、巩固并真正掌握教材。

## 二十二、学习系统原则（P2-5 同步）

本章同步 P2-5 学习系统设计中已经项目负责人确认的教育原则。本章与第一章、第九章、第十章、第十六章、第十八章、第二十章一致，是对既有条目的细化与补强，不推翻任何既有条目。

依据文档：audit/P2-5_learning_system_design.md、audit/P2-5_architecture_impact.md、structured/learning/learning_model_v1.json、learning_evidence_model_v1.json、learning_flow_v1.json、intervention_model_v1.json、stage_assessment_model_v1.json、ai_role_model_v1.json。

### 1. 产品总原则与产品边界

一句话总纲保持：教材是主线，APP 负责整理与提效，学习是核心，孩子做主，AI 是助手。

APP 的核心作用：准确整理、数字化并集中呈现教材及其配套学习素材，降低翻找教材、音频和练习的操作成本，让孩子更高效地学习、练习并真正吃透教材。

本产品不是：

- AI 题库；

- 自动作业系统；

- 自动学习路径系统；

- 刷题系统；

- 分数、排名、等级系统。

### 2. 孩子做主的准确含义（自主权不等于取消结构）

孩子决定：学哪一部分；什么时候进入；学多长时间；是否暂停；是否回看；是否继续；是否进行巩固；是否进行阶段验证。

系统负责：按教材结构组织内容；提供符合教材学习逻辑的顺序建议；呈现当前教材上下文；记录学习事实；聚合学习证据；给出基于证据的建议。

AI 负责：教材范围内的分析；开放性答案评价；错误归因；学习证据解释；巩固建议；必要时提供严格受教材证据约束的辅助内容。

系统和 AI 都不得：

- 强迫孩子进入下一步；

- 自动决定今天学什么；

- 自动安排学习任务；

- 自动推进学习进度；

- 用弹窗、自动跳转、自动播放干扰学习；

- 代替孩子决定是否继续巩固。

本章明确：自主权不等于取消结构。系统提供符合教材学习逻辑的推荐顺序，但不强制。

### 3. 学习对象的定义

教材学习对象包括：单词、短语、句型、语法点、听力任务、阅读文本、写作任务等。

Activity 是任务容器，不等于学习对象。

Exercise（含 Question）是产生学习证据的任务，不等于学习对象。

三层不得混用：学习对象用于聚合与诊断，Activity 用于组织教材任务，Exercise 用于产生证据。

Exercise（含 Question）必须锚定到明确的教材活动与上下文，不得按页码跨活动串题（见六·8）。

### 4. “学过”与“掌握较稳定”

“学过”只表示：孩子至少主动发生过一次学习行为。它是事实记录，不等于学会、掌握、熟练或掌握较稳定。

“掌握较稳定”必须基于多维证据，而不是单次正确。当前工程初始规则：

- 至少 3 个有效判断证据；

- 至少 2 种不同任务类型；

- 至少跨 2 个自然日；

- 最近 3 次尝试至少 2 次正确；

- 当前没有未处理的当前错误。

参数声明：以上 3+2+2 与“最近 3 次至少 2 次正确”等具体数字属于当前工程初始参数，不是不可修改的教育真理，必须通过真实孩子使用数据验证并调整。本规范保留其“可验证、可调整”的属性。

### 5. 证据优先

学习能力判断必须来自多维学习证据，例如：回忆、填空、阅读、听力、口语、写作、跨自然日重复表现。

- 只看过不能单独证明掌握；

- 只听过不能单独证明掌握；

- 自评不能单独升级掌握状态；自评、完成动作（例如“我完成了这次练习”）与音频播放行为均**不构成正式判断证据**，不得直接产生 correct / incorrect / partial；

- 正式判断证据只能来自经过系统/规则/AI 正式批改或分析的结果（详见七·7、七·8、七·10）；

- 同一学习时段内的重复操作不能无限增加独立证据权重。

并保持：一次错误不等于薄弱。单次错误只记录，不生成结论。

### 6. 教材优先巩固

巩固必须遵循：先回到教材，再考虑 AI 辅助。优先顺序：

- 回看原教材文本；

- 重听官方音频；

- 回到教材中的语法提示；

- 对照教材范文；

- 重做原教材题；

- 做跨 Section 的教材范围综合练习。

只有在“教材中没有对应练习、存在重复性问题、孩子主动选择”等条件满足时，才允许考虑 AI 辅助练习。明确：巩固不是无限重复错题。

### 7. AI 角色边界

AI 最高价值：

- 教材证据约束下的开放题批改；

- 错误归因；

- 阅读、写作、口语等开放答案分析；

- 有明确条件时生成教材范围内的辅助变式；

- 基于证据提供可执行的巩固建议。

AI 不得：

- 决定孩子学什么；

- 决定什么时候学；

- 自动安排学习路径；

- 自动推进学习；

- 生成教材范围之外的学习内容；

- 用 AI 题替代教材原题；

- 用分数、排名、等级评价孩子；

- 在证据不足时做确定性结论。

必须明确：AI 负责分析、评价、提示和辅助；孩子负责学习选择和学习节奏。

交叉引用：教材练习的批改责任、客观题与主观题的批改边界、答案事实原则见第七章第 7–10 条；教材文字—音频—上下文—Question 锚定与音频切分边界见第六章第 8–9 条。

### 8. 阶段验证原则

阶段验证不是考试产品。其目的是获取跨 Unit、跨任务类型的综合学习证据，判断是否出现稳定掌握与迁移迹象。原则：

- 低频；

- 自愿；

- 不强制；

- 不做排名；

- 不做等级；

- 不以分数为核心；

- 不直接因为一次阶段验证结果修改掌握状态；

- 不重复刚刚完成的原题；

- 中途主动退出不产生负面结论。

参数声明：P2-5 设计中的“5–8 题”只是当前实验性工程参数，不是永久固定规则，以后根据真实使用负担和证据价值调整。

### 9. 专项学习的位置

专项学习属于教材主线下的辅助入口，不是一级主线。

组织方式仍然以 Unit / Section 教材范围为核心。

可以由孩子主动选择，或由学习证据提示触发。

但不能演变成独立题库主线。明确拒绝：专项学习 = 独立 AI 题库。

### 10. 完整学习闭环

教材 → 孩子选择 → 学习 → 教材原题实践 → AI 基于教材证据批改 → 学习证据 → 证据聚合 → 基于证据的诊断 → 孩子决定是否巩固 → 教材优先巩固 → 再验证 → 掌握较稳定 → 继续教材主线 → 可选阶段验证 → 综合诊断 → 返回教材或进入下一 Unit。

说明：这是产品设计原则，不代表必须一次性全部自动执行；其中“批改”“证据聚合”与“孩子决定”三个环节必须显式存在。

特别说明：**批改环节属于教材练习的最低闭环，必须由系统/规则/AI 承担，不得以孩子自评替代**（见七·7）。教材练习尚未接入正式批改时，只能记录“发生过作答行为”，不得据此产生掌握结论。

### 11. 原则与参数的区别

本规范只固定“原则”。以下内容保留在 P2-5 工程设计层，不作为永久规则，可通过真实使用验证后调整：

- 掌握阈值具体数字；

- 阶段验证具体题数；

- AI 错误类别最终数量；

- 提醒频率；

- 巩固间隔；

- 某种具体 UI 形式；

- 某个具体数据库表结构；

- 某个具体 API 实现。

原则应稳定，参数可以调整。

## 二十三、V2 产品架构与页面层级最小化原则（V1.3 新增）

### 1. V2 产品总目标

系统应该让孩子用最少的页面和操作进入真正的学习，并通过真实学习证据让孩子清楚知道自己学得怎么样。

### 2. 一级页面不超过 3 个

V2 一级导航固定为：

- 首页
- 学习
- 进展

不得按照 Vocabulary / Grammar / Listening / Reading 拆成多个一级导航；它们属于学习内容类型。

### 3. 学习任务快速进入

学习任务不超过 3 次操作进入学习。

正常学习任务原则上不超过 3 次操作进入真正学习状态：

```text
学习
→ Unit / 内容选择
→ 直接开始学习
```

### 4. 能当前页完成，不新建页面

结果、掌握状态、AI评价和下一步建议应尽可能在同一结果区域完成，不得机械增加“结果页 → AI分析页 → AI建议页”。

### 5. 说明页不得成为学习必经路径

教材说明、学习目标说明、AI说明、知识点长介绍、数据来源说明和教材引用说明不得成为进入学习的强制中间页面；必要信息就地展示。

### 6. 知识点详情不是必经页面

如果孩子可以直接学习，就直接学习。知识点详情只在确实需要时提供。

### 7. 结果、评价、建议尽量合并

推荐闭环：

```text
学习
→ 结果 + 掌握状态 + AI评价 + 下一步建议
→ 继续 / 结束
```

## 二十四、AI职责与评价原则（V1.3 新增）

### 1. AI职责

AI职责定义为：

> 分析 → 评估 → 反馈 → 建议

- 分析：基于孩子真实产生的学习证据进行分析。
- 评估：让孩子直观看到当前学习状态。
- 反馈：不仅给结论，还说明形成判断的主要依据。
- 建议：提出下一步学习建议，但不能替孩子决定。

### 2. 没有证据，不评价

没有足够学习证据时，系统不得给出虚假的掌握评价。

错误示例：

> 你的词汇掌握得很好。

正确示例：

> 目前学习记录较少，暂时无法形成可靠评价。

### 3. AI只能建议，孩子做决定

孩子始终拥有学习内容、时间和学习节奏的决定权。AI不得强制安排、自动连续执行或替代孩子选择。

### 4. 统一评价语言

推荐统一使用：

- 未开始
- 学习中
- 基本掌握
- 掌握较稳定
- 需要巩固

评价必须有真实学习证据作为依据。

### 5. AI不是一级功能

AI是系统能力，不是孤立的一级“AI老师页面”。AI分别存在于首页、学习过程、结果区域和进展页面；不得为AI功能制造大量新页面。

## 二十五、首页、进展与学习进度原则（V1.3 新增）

### 1. 首页不是功能大厅

首页不是 Dashboard、AI聊天页、数据驾驶舱、教材百科或任务管理器。

首页是 Learning Home / 学习首页，只回答：

1. 我现在学得怎么样？
2. AI根据我的学习表现怎么看？
3. 我下一步可以做什么？

首页信息优先级固定为：

```text
当前学习状态
→ AI评价
→ 下一步建议
→ 我的进展
→ 学习内容入口
```

### 2. 学习进度 ≠ 掌握程度

学习进度表示覆盖范围，掌握程度表示真实证据支持的稳定表现。

禁止直接使用：

> 学习完成60% = 掌握60%

### 3. 进展页面

进展页面回答：

> 我到底学会了多少？

进展页面必须区分学习进度、掌握状态、需要巩固内容和最近表现变化。

## 二十六、有效信息优先原则（V1.3 新增）

系统前台信息必须以实际学习价值为第一优先级。

优先展示：

- 学了什么
- 学了多少
- 掌握了什么
- 哪些不稳定
- 哪些需要巩固
- 最近表现如何
- AI为什么这样判断
- 下一步建议什么

减少或删除：

- 欢迎语
- 宣传语
- 空泛鼓励
- 产品理念说明
- AI自我介绍
- 大段教材介绍
- 没有实际学习价值的说明文字
- 装饰性信息

判断标准：任何文字、数字、按钮、卡片必须至少满足一项：

1. 提供真实学习信息；
2. 帮助孩子完成学习；
3. 帮助孩子理解自己的学习表现；
4. 帮助孩子做出下一步学习选择。

四项均不满足，应删除。

## 二十七、V2视觉与交互原则（V1.3 新增）

### 1. 视觉基线

V2采用 **Clean Modern Learning**：

- 简洁
- 清晰
- 专业
- 安静
- 信息优先
- 学习优先

### 2. 明确禁止

- 游戏化
- 儿童化
- 糖果色
- 粉紫渐变
- 积分
- 排名
- 徽章
- 大量动画
- 大量装饰性插画

视觉设计服从信息层级，而不是反过来。

### 3. 跳转与反馈

所有跳转必须有即时响应、明确状态，并保持学习上下文；返回后不得丢失当前学习位置。禁止点击后长时间无反馈，禁止完成学习后突然返回首页并丢失上下文。

## 二十九、教材层级与学习上下文（Unit / Section）与教材原文边界（2026-09-20 同步；2026-09-22 修正）

### 1. 教材层级与学习上下文（Unit / Section）

教材正式层级为：**教材 → Unit → Section**。

- **Unit 是教材组织层级**；**Section 是 Unit 内真实教材目录的一节**（正式数据位于 `contentpack.section`）。
- **`section_key` 是 Section 的稳定业务标识**（不是“临时映射”）。
- **Section 是孩子实际学习推进、学习进度记录的核心业务粒度**：“学到 Unit 2”不足以表达进度，
  必须能够表达“Unit 2 已经学到哪个 Section”；同一 Unit 中已经学习的 Section 与尚未学习的 Section
  必须能够区分；**不得用 Unit 前缀代替 Section 级学习进度**。
- `Starting out` / `Understanding ideas` / `Developing ideas` / `Reading for writing` /
  `Presenting ideas` / `Reflection` 即这些真实 Section 的名称（Starter 另有其 4 个 Section）。
- 首页课时菜单职责：**先定位当前 Unit，再在该 Unit 的 Section 中选择当前学习课时**。
- **Section 是学习进度坐标，不意味着所有学习功能都只能使用当前 Section 的资源**：
  每个功能的候选资源池由该功能自身的正式业务规则确定，可综合当前 Section、已学 Section、
  已有学习记录、掌握情况、错题/薄弱项、历史学习证据，必要时结合 AI 分析结果；
  **不得写成或实现成“六项功能统一只能使用当前 Section”**。
- 本课检测以**当前 Section** 的正式学习内容为核心；自主练习不适用“当前 Section 资源边界”，
  其资源范围见第二十八章第 7 节（当前学习进度之前**全部有效的已学 Section**）。

**资源归属粒度不必统一**：学习进度粒度是 Section，不代表所有资源都必须改造成 Section 级资源。
Section 级资源（教材正文、教材型题目、官方音频）与 Unit 级资源（例如词表）可各自保持其正式归属粒度；
某 Unit 级资源是否允许出现在某 Section 的学习入口，由该功能的正式业务规则决定，
**不得机械地把 Unit 级资源强行拆分成 Section 级资源**。

**Unit 级资源的学习范围边界**：Unit 级资源（vocabulary / phrase / vocab_phonetic / vocab_word_form /
Unit 级辅助资源）**不得天然理解为“整个 Unit 永久全部开放”**；其学习范围边界必须受正式学习进度规则约束，
具体入口如何应用该边界由该功能的正式业务规则决定（仍不得为了套用 Section 进度而人为给 Unit 级资源分配 Section）。

**Unit 级资源出现 ≠ 对应 Section 已学习**：学习 Unit 1 的 vocabulary 不得推出任何 Section 已学，
更不得推出“Unit 1 全部 Section 已学”；Section 进度只由 `learned_sections()` 的正式 Section 映射决定。

**不再保留独立的 Lesson 进度层级**：历史实现中的 `lesson_key`（含 `?lesson=`、Cookie `zx_lesson`，
以及 Demo 的 `current_lesson()` / `lessons(unit)` / `lesson_by_key()` / `lesson_options()` /
`lesson_questions(unit, lesson)`）实际保存的是 `section_key`，属**历史命名**；
语义以本节 `section_key` 定义为准，代码变量统一属后续实施任务。

### 2. 本课检测的正式定义

「本课检测」不是 Unit 测试，而是**针对当前 Section 的综合检测**；
「自主练习」是**孩子自主选择练习类别**。二者职责不同，不得互相替代。

### 3. 听音模式必须真实对应资源

听音辨意的「单词听辨 / 句子听辨」不是 UI 标签，必须实际通过正式
`mode` → `allowed_types()` → 正式题目类型进行筛选；没有音频时不得伪造音频。
各模式的**显隐**与题目筛选**使用同一正式资源池判定**（同源，不新增第二套显隐判断）；
显隐、默认回退与直接访问规则见本节第 15 小节 §15·2 与 §15·4-C。

### 4. 教材原文与 ASR 的正式边界（再次明确）

教材原文是语义事实权威；官方教材 MP3 是教材资源主线与「实际说了什么/在哪里说」的事实证据；
ASR 仅用于音频与教材文本的切分、定位、对齐，**不作为教材文本权威**。

**句级教材原文不得推导生成**：当正式数据不存在可靠的句级教材原文关系时，不得通过 ASR 文本、
题目 `answer` 反推、`content_block` 截取、字符串规则、AI 生成或其他推断方式补造教材原句。

AI 可以分析和辅助学习，但不得为了补齐教材事实而生成未经正式数据验证的教材原文。

### 5. listen_fill 的正式数据边界（当前状态）

`audio_sentence_annotation` 表存在，但目前仅 15 行（`VERIFIED 12` / `REJECTED 3`，
`origin = HUMAN`），且当前 `listen_fill` 涉及的 `AU02`、`AR:AU02:S004`、`AR:AU02:S005`
**没有句级覆盖**。

因此当前正式 Web 对 `listen_fill` 只允许展示：正式 `instruction` + 正式官方音频 + 输入框，
**不得显示所谓"完整教材原句"**。待句级人工核验数据补齐后再正式接入。

### 7. 题目随机性（2026-09-21 补充）

对于具有题目候选池的功能：**必须在该功能业务规则确定的合法候选资源池内随机选择题目**。

- 不得永远从第一题开始；不得长期使用固定顺序；不得用数据库自然顺序代替随机。
- 随机只负责候选池内部的**选择顺序**，**不能改变候选池本身的业务边界**（当前 Section 范围、
  已学内容范围、题型范围等）；不得抽到当前学习进度之后尚未学习的内容。

六入口顺序不变；各入口的正式范围与进度粒度如下（**practice 的规则不得自动复制给其他入口**）：

### 13. 教材展示范围与素材调用分层（2026-09-26 同步）

**一、教材原文展示范围受"官方音频可靠对应关系"约束**

- 其余教材数据（词汇、短语、句型、练习、音频等）继续**完整保留**，供正式学习功能及后续 AI 学习功能调用。

**二、教材原文页的定位**

- 教材原文页 = **教材音频对应内容的查看与播放页**；
- **听读课文已是六个学习入口之一**（2026-09-30 正式决策）；以下约束仍适用于**其余次级内容页**。

  词形变化 → 本课检测 → 自主练习）；
- 它**不是孩子进入日常学习的前置步骤**。

**三、展示形态**

- 播放入口贴合**自然段或可靠对应的文本内容**；
- **不采用逐句喇叭按钮堆叠**的方式破坏阅读体验；
- 只有存在**可靠句子级映射**时，才支持相应句子的播放与高亮；

**四、产品入口边界**

- 本应用是**单教材应用**，**不是多教材平台**；
- 孩子选择当前 Section 后，可直接从首页六个学习入口自主进入学习，不要求先进入教材原文页；

  Section / Activity 等内部解析层级。

### 15. 菜单与目录的最终产品规则（2026-09-27 同步 · 本节为唯一权威记录）

> 本节把已确认的菜单 / 目录产品规则固化为正式口径。**术语区分（必须严格遵守）**：
> **正式学习功能集合**（六项功能）≠ **当前入口显隐**（取决于所选 Section 的真实资源）≠ **功能内容层资源状态**
> （进入功能后页面 / 内容区是否有资源）。三者不得混写为同一件事。

#### 15.1 规则 1：Section 选择入口与目录

- **首页「当前课时」选择器是唯一正式的 Section 选择入口**；完整教材目录为 **8 组、46 个 Section**，
  **不按题目数量或资源数量删减**。
- **Section 是教材目录和当前学习进度的实际粒度**；Unit 仅用于组织与聚合；**不存在独立 Lesson 实体**。
- `lesson` / `lesson_key` / `?lesson=` / Cookie `zx_lesson` 等**仅为承载 `section_key` 的历史代码命名**
  （语义以本节第 1 小节为准），不得据此新建 Lesson 层。
- Section 是目录与当前课程**选择**粒度，**不因此要求每个 Section 都必须成为独立页面**。

#### 15.2 规则 2：正式学习功能集合与当前入口显隐

- `read` / `listen` / `phonetic` / `form` / `check` / `practice` 构成**正式学习功能集合**
  （顺序仍固定：跟读练习 → 听音辨意 → 词形练习 → 本课检测 → 自主练习 → 听读课文）。
- **主页与次页中的所有正式学习功能入口**（不只首页六项），其显隐都根据当前所选 Section 对应功能的
  **真实可调用资源**决定（2026-09-27 补充：适用范围覆盖次页入口）：
  - 当前 Section 有该功能所需的真实资源 → 按真实资源显示该入口；
  - 当前 Section 没有该功能所需的资源 → 该功能入口**可以不显示**，**无须为了凑齐六项**而显示空入口或不可用入口。
- **不得**用整个 Unit 的资源总量（或 Unit 级聚合数）代替当前 Section 的真实可调用资源来判定入口是否显示。
- **入口内部的模式标签同样按当前 Section 的显隐规则处理**（2026-09-29 补充；"听音辨意"的
  `单词听辨 / 句子听辨` 即此类内部模式）：
  - 有该模式真实可调用资源的模式**显示**；没有资源的模式**隐藏**；
  - 模式显隐必须**复用该入口的正式资源池判定**（与实际题目筛选同源），**不得另建第二套显隐判断**；
    **不得**用整个 Unit 的资源总量、其他 Section 的资源或统计数字代替资源判定；
  - **默认模式**（`单词听辨`）无资源时，按固定顺序 `单词听辨 → 句子听辨`
    选择当前 Section 内**第一个有资源的模式**；
  - 当前 Section 两种模式**均无资源**时：**不显示任何无资源的模式标签**，呈现真实空状态（见 §15·4-C）。
- **模式无资源 ≠ 隐藏整个入口**：内部模式全部无资源时，隐藏的是模式标签（以及该入口的可用性），
  **不得**为了凑齐模式数量而显示空模式标签，也**不得**因此删除 Section 或改变完整目录 / 选择器。
- **不得**因某个功能在当前 Section 无资源，就删除该 Section 或把它从完整目录 / 选择器中移除。
- **不得**把"六项是正式功能集合"误写成"每个 Section 必须始终显示六个入口"。
- **不恢复**旧七项训练菜单或旧训练岛。

#### 15.3 规则 3：Appendix

- Appendix **保留在完整教材目录和首页「当前课时」选择器中**。
- Appendix **不是普通教学 Unit**，**不强行进入**六个正式学习功能入口。
- 不得因其不进入六项功能入口而从教材目录或原始数据中删除；**不得伪装成普通 Unit**。
- 不得为了凑齐入口而制造无依据的学习内容。
- Appendix 当前是否存在具体资源，**必须以实际资源为依据**；不得仅因它出现在目录中就推定其应开放六项功能。
- **入口按真实资源显式判断**：Appendix 的入口显隐同样按当前 Section 的真实可调用资源**显式判定**；
  **不得依赖异常被吞掉**（例如服务层抛错后清空入口列表）来隐藏入口；**不得为此修改冻结服务层**
  （`learning/study_call_service.py` 属冻结资产，需修改时必须单独批准）。

#### 15.4 规则 4：零题 Section、入口显隐与空状态（三个层次必须分开）

**A. 目录层**

- 零题 Section **保留真实目录位置、名称和顺序**；不因题目数或某类资源数为零而从目录 / 选择器中删除。

**B. 功能入口层**

- 当前所选 Section 有某功能所需的真实资源时，**可以**显示该功能入口；没有该资源时，该功能入口**可以不显示**。
- **不要求**每个 Section 都显示全部六项功能入口。
- **不得**用其他 Section 的资源冒充当前 Section 的资源；**不得**静默切换到其他 Section。

**C. 功能内容层**

- 用户进入功能后，按**当前功能、当前范围和真实资源**显示内容。
- 若页面或功能内部某个内容区确实没有资源，应**如实呈现真实空状态**；不得伪造题目 / 资源 / 学习结果；
  不得为了避免空状态而静默替换 Section 或资源范围。
- 「当前功能入口不显示」与「进入功能后显示空状态」是**不同处理**：优先按当前 Section 的资源可用性决定入口是否出现；
  只有实际进入的页面 / 内容区存在空资源情形时，才呈现对应空状态。
- 用户**通过历史链接或其它路径直接进入**无资源的功能页时，同样须给出**真实、准确、孩子可理解**的空状态；
  **不得**使用"换个章节看看"这类与事实不符的误导性文案（无资源是资源事实，不是章节问题）。
- **直接访问当前 Section 内无资源的内部模式时**（2026-09-29 补充）：
  - 若同一 Section 内还有可用模式 → 按 §15·2 的固定顺序（`单词听辨 → 句子听辨`）
    改选**第一个有资源的模式**，并停留在**当前 Section**；
  - 若同一 Section 两种模式均无资源 → 给出**真实空状态**（不显示无资源模式标签）；
  - 该回退**不得**切换 Section、**不得**借用其他 Section 的资源；回退本身**不产生学习记录、不改变学习进度**。

#### 15.5 规则 5：Unit 与次级页面

- Unit 是**目录组织和内容聚合层**；不恢复旧七项训练菜单。
- **`/unit/<slug>/text` 经 2026-09-30 正式产品决策，已升级为菜单入口「听读课文」（跟随当前课时进度）**；`/unit/<slug>/resources`、`/unit/<slug>/exercises` 等现存页面仍定位为**次级内容页**，
  **不与**首页正式学习功能入口**并列成为一级学习主入口**。
- 不得把这些页面提升为新的一级入口（除非后续有正式产品决策）；不得因次级页面存在就恢复旧 Unit 菜单或训练岛。

#### 15.6 规则 6：统计语义

- **候选资源数、已完成数、未完成数是不同指标**，必须分别命名和定义。
- 指标必须说明**统计范围及资源口径**。
- 首页与功能页展示同一指标时，应使用**相同范围和计算口径**。
- **不同范围、不同语义的数字不得使用同一标签呈现或直接比较。**
- 统计口径应尽可能与对应功能**实际资源池和学习范围**一致。
- **入口显隐与统计数字是不同概念**：不得用候选资源数 / 已完成数 / 未完成数等统计数字判断入口是否可用；
  入口是否显示只由「当前 Section 是否有该功能的真实可调用资源」决定。
- 本节只确定统计**原则**：不规定未经核实的具体计算公式，不修改统计实现；具体计算口径与实现另行审计、确认和验收。

### 16. AI 挖空素材（固化）

**定义**：AI 的**第二件事**——依据**官方教材音频**把教材文本的对应部分补全为**挖空素材**，供正式题目使用。

- **音频来源**：只允许官方教材 MP3（`contentpack` 的音频资源），不得重新切割官方 MP3、不得用 AI 生成音频、不得调用在线音频。
- **挖空依据**：以教材文本与官方音频的**已确认对应关系**（VERIFIED 区间 / `audio_source_code` / `start_ms` / `end_ms`）为依据；无法确认的部分**不得猜测补齐**（见第 6 节）。
- **落库约定**：
  - 挖空文本写入 `question.prompt_json` 的 **`text`** 字段，空位用 **`______`**（6 个下划线）表示；
  - 空位数量写入 **`prompt_json.blank_count`**（整数）；
  - 答案写入 **`answer_json`**；
  - AI 补全须标注**来源**（`origin` / `prompt_json.question_origin` / `prompt_json.distractor_origin` 等既有标记字段）。
- **边界**：AI 挖空素材是**教材事实的搬运与变形**，**不是新造内容**；不得改变教材原意、不得引入教材外词汇与结构。
- **数量**：不硬凑（见第 3 节）——**质量优先，宁缺毋滥**。

### 17. AI 补全的题型优先级（固化）

**适用范围**：仅指**第 4 节定义的两件事**（补干扰项 / 按音频补全教材文本挖空）在**题型上的倾向**。

- **优先**：**听力**（`listen_*` / `sentence_listen_*`）、**阅读**（`reading_choice`）、**语境词汇**（`vocab_context_choice` / `phrase_meaning_choice`）。
- **少补**：**孤立拼写**（`vocab_phonetic_write` / `phonetics_symbol_write`）、**纯语法**类。

**⚠️ 与第 3 节的边界（必须同时遵守）**：
- 本节是**优先级 / 倾向**，**不是固定配额**——**不得**据此推导出"每类固定 N 题"或"优先题型必须占某个比例"；
- **第 3 节「题量原则」仍然优先**：有多少合格资源就用多少，资源不足时不硬凑（**允许 0 题**）；
- 当"优先题型"没有合格资源时，**不得**为凑优先级而降低质量或越过教材范围。

### 18. AI 老师·例句来源（固化，2026-09-29 同步）

孩子**做错题**后，AI 讲解**三句话**：**① 错在哪 ② 该用什么 ③ 一个例句**（恰好三句，每句不超过一行，不出现语法术语）。

**例句来源三层优先级（先命中先停）**：

1. **检索课文原文优先**：经教材结构化产物 `textbook_content_relations_v2.json` 的 `text_references`（**活动 ↔ 内容块**精确映射，含 `sample` 原句）检索；**场景合适就直接用课文原句**（并标出来源）。
2. **取不到 → 依教材素材生成**：允许 AI 在**教材素材范围内**生成**合乎逻辑**的例句（可复用教材词汇与句型结构）。
3. **都不行 → 不给**：**宁缺毋滥**，只保留前两句。**绝不自行编造教材事实。**

**检索范围（按题目自身的粒度定，不是"当前正在学的课时"）**：

以**那道题所属的范围**为锚点，再向"已学过"扩展：

- **Section 级题型**（`section_key` 非空）⇒ 锚点 = **本题的 `section_key`**（**不是当前正在学的课时**）；
- **Unit 级题型**（见第 8 节：`vocab_word_form` / `vocab_context_choice` / `phrase_meaning_choice`，`section_key` 为空、`unit_code` 非空）⇒ 锚点 = **本题的 `unit_code` 兜底**；
- **锚点 + 之前学过的内容**：取 `learned_sections()` 的**已学 Section 集合**，并**无条件纳入锚点自身**（同第 4 节 :216 口径）；
- **`unit_code` 也为空** ⇒ 划不出范围，**不讲**（当前全库 0 道，兜底仍保留）。

**⚠️ 口径澄清**：此处的"当前课时"= **题目所属课时**，**不是**用户当前正在浏览 / 正在学的课时。

**守界**：例句**不得超出教材范围**，且**只能使用孩子学过的内容**；**越界则丢弃例句**（由确定性闸门拦截，不采信 AI 自证）。

**分层覆盖（如实记录，不夸大）**：

- **有映射的课时 = 25 / 46**（经 `text_references` 实测）⇒ 走第 ① 层；
- **无映射的课时（21 / 46）+ 词表课**⇒ 走第 ② 层。词表课（`WORDS_AND_EXPRESSIONS`）**教材侧确认无课文**（其 `activity` 数 = 0、经页码取 `content_block` = 0），素材是 `contentpack.learning_item` 的**词汇条目**，且**这些条目没有课时归属**；
- **⚠️ 上述 25/46 是「课时覆盖率」，与「适用题占比」是两个不同的数，不得混用。**

**触发条件**：**仅答错**；**按题型清单判定（不得只看 `answer_kind`）**：

| 分派 | 题型 | 理由 |
| --- | --- | --- |
| **讲解** | `textbook_native` / `sentence_listen_write` / `sentence_listen_choice` / `listening_choice` / `listen_choice` / `listen_fill` / `reading_choice` / `vocab_context_choice` / `phrase_meaning_choice` / `vocab_listen_write` / `vocab_meaning_choice` / `vocab_word_form` / `phonetics_sound_choice` | 语境 / 理解 / 语法 / 词汇类，讲解有教学价值 |
| **少讲（优先级最低）** | `vocab_phonetic_write` (265) / `phonetics_symbol_write` (16) | **孤立拼写**（第 17 节「少补」同口径） |
| **不讲** | `ai_eval` / `self_assess` | 无"答错"概念 / 无对错 |
| **不讲** | `read` 入口 | 无判分 |
| **不讲** | `unit_code` 为空的题 | 划不出范围 |

**失败处理**：AI 不可用 / 未配置 / 超时 / release 构建未注入桥时 → **保持现状**（只显示正确答案），**不阻断确定性学习功能**。

**数据来源（教材结构化产物）**：`textbook_content_relations_v2.json`（`text_references`）/ `textbook_structure_v2.json`（课时顺序，`pdf_page_start`）/ `textbook_context_relations_v2.json`（`A:xxx` 形态活动 → Section 的 `belongs_to` 映射）。

### 19. 范围分层原则（固化，2026-09-29 同步）

题库内容分**两层**，两层各有自己的范围规则（**2026-09-29 确认**）：

| 层 | 内容 | 正式范围 |
| --- | --- | --- |
| **题目主体层** | 题干、正确答案、考查点 | **当前课时**（该题所属 Section / Unit） |
| **辅助素材层** | **干扰项**、**例句**、音频、图片 | **当前课时优先；不够时可用孩子已学过的内容**（`learned_sections()`） |

**规则要点**：

1. **题目主体不得越界**：题干与正确答案只能来自该题所属课时（Section 级题型）或该题所属 Unit（Unit 级题型，见第 8 节）。
2. **辅助素材可以借用已学内容**：干扰项 / 例句在当前课时内不足时，**允许从孩子截至当前真实学习进度已学过的 Section / Unit 借用**（与第 4 节 :216 的干扰项规则同口径）；**不得借用未来尚未学习的内容**。
3. **按题型粒度分派范围锚点**（**设计声明已在第 8 节，此处固化其"锚点分派"含义**）：**Section 级用 `section_key`；Unit 级用 `unit_code`**。<br>**⚠️ 这是设计约束，不是实现现状** —— 当前 `_p5_teach_payload()` 仍**只接受 `section_key` 非空**，Unit 级兜底**尚未实现**（属后续实施任务）。
4. **题型分派决定 AI 指令**：不同题型族的 AI 指令**必须分别设计，不得统一模板**（**语法类 / 词汇类 / 理解类 / 写作类**分别定稿）。
5. **不制造重复**：各入口的逐条资源范围**仍以第 8 节为唯一权威**；本节只固化"分层"这一横切原则。
