## 5. Phrase 独立身份设计

| 身份要素 | 判定 | 理由 |
|---|---|---|
| item_id | **REQUIRED** | Phrase 是独立资源；即使文本与 Vocabulary 完全相同，也必须拥有不同身份（命名空间区分：Vocabulary 用 `:V:`，Phrase 建议 `:P:`） |
| content_hash | **REQUIRED** | 需要独立的文本身份用于去重与迁移；不得复制 Vocabulary 的 hash 规则输入 |
| source_ref | **REQUIRED** | Phrase 可以有多个证据来源（词表条目 / 语言注释 / 正文出现处） |
| content_block / page 证据 | **REQUIRED** | 教材可追溯是最高原则 |
| review_status | **REQUIRED** | 资源是否成立需人工可审 |
| textbook_emphasis | **REQUIRED** | 强调是**来源级排版事实**；Phrase 不继承 Vocabulary，必须自持（本册全部 PLAIN，但模型必须支持 BOLD） |
| emphasis_evidence | **REQUIRED（有视觉证据时）/ OPTIONAL（无）** | 词表来源必填；语言注释来源无 head span 时按第 11 节规则处理 |
| learning_requirement | **REQUIRED** | 教材学习要求独立于 Vocabulary |
| requirement_conflict_status | **REQUIRED** | 多来源教学意图不一致时必须可表达 |

## 6. Phrase ↔ Vocabulary 关系

回答：

| 问题 | 结论 |
|---|---|
| 1. 一个 Phrase 关联一个 Vocabulary entry？ | **允许**（如 `junior high` ↔ Vocabulary `junior high`） |
| 2. 一个 Phrase 关联多个 Vocabulary entry？ | **允许**（如 `take part in` 与 `part`、`take` 等单词条目） |
| 3. Vocabulary entry 没有 Phrase？ | **允许**（绝大多数单词条目没有 Phrase） |
| 4. Phrase 没有对应 Vocabulary？ | **允许**（如 `protect... from...`、`along the way` 不是词表条目） |
| 5. 同一 Vocabulary entry 对应多个 Phrase？ | **允许**（如 `part` 可同时出现在多个短语中） |
| 6. 关系实现方式 | **NOW：不新增表**——通过**共享同一 `source_ref.source_id`（同一 content_block）**建立隐式关联；**LATER：**如确需显式多对多，再新增 `item_relation(from_item_id, to_item_id, relation_type)` 关联表 |

最小可行说明：22 条词表多词条目的 Phrase 与对应 Vocabulary entry **指向同一个词表 content_block**，因此"同源"关系可由 `source_ref` 直接查询得出，不需要额外字段或表。

## 7. Phrase ↔ Grammar context 关系

以 `protect... from...` 为例：

```text
Phrase 身份   ：item_type='phrase'，canonical_text='protect... from...'
Grammar 上下文：教材 p.120 的语言注释块
实现方式      ：source_ref(item_type='phrase', source_type='content_block', source_id=<注释块 id>,
                quote_raw=<教材原文>)；在 emphasis_evidence JSON 中记录 context_type='grammar_note'
是否需要额外表：不需要
```

回答：① 需要 Phrase 独立 item；② Grammar context 作为 **source_ref**；③ 需要 `context_type`（作为 JSON 内部的键，不新增列/枚举）；④ 不需要额外表；⑤ 可以只通过 source_ref 表达；⑥ 这与 v3 现有模型完全一致（零 schema 变更）。

## 8. 22 个多词 Vocabulary 条目的处理方案

| 方案 | 说明 | 评估 |
|---|---|---|
| A. 把 Vocabulary entry 同时标记为 Phrase | 需要给 learning_item 增加"也是 Phrase"的标记 | **不推荐**：破坏 Vocabulary 语义与字段冻结；Phrase 的学习要求/强调将无法独立演化 |
| **B. 创建独立 Phrase resource，再关联原 Vocabulary** | 新 `item_type='phrase'` 条目 + 共享 source_ref | **推荐**：资源类型独立、教材事实不复制（共享同一 content_block）、Vocabulary v3 完全不动 |
| C. 其他（如仅存文本关系） | 无结构化身份 | 不推荐：无法接入未来的 review / pronunciation / audio |

**推荐 B。** 补充约束：22 条对应 Phrase 的 `source_ref` 直接复用原 Vocabulary 条目的 `content_block`（同一 block_id），因此不产生第二份教材事实。

## 10. Phrase emphasis 设计

```text
沿用 Vocabulary 的枚举：BOLD / PLAIN / UNKNOWN（不新增枚举）
规则：
  1) 来自词汇表条目 → 按 head span 字体名判定（Medium→BOLD，Regula→PLAIN）
  2) 来自语言注释/正文（无 head span 字体证据）→ UNKNOWN（不得默认 PLAIN）
  3) 多来源时逐来源保存；聚合冲突 → requirement_conflict_status = NEED_REVIEW
```

本册事实：22 条词表多词条目全部 PLAIN；2 条语言注释型固定搭配为 UNKNOWN。模型从第一天支持 BOLD（未来教材可能出现）。

## 11. Phrase learning_requirement 设计

枚举沿用：`CORE / RECOGNITION / NEED_REVIEW`（够用）。确定规则：

| 来源 | 判定 | 依据 |
|---|---|---|
| 词汇表多词条目 + BOLD | CORE | 教材明示重点（与 Vocabulary 同规则） |
| 词汇表多词条目 + PLAIN | RECOGNITION | 教材要求认识、能读懂（本册 22 条） |
| 教材明示“固定搭配 / 固定短语”（非词表） | **CORE**（并标 review_status=NEED_REVIEW） | 教材明确作为语言单位教学并给出释义与用法 |
| 仅出现在 Grammar 结构说明中 | NEED_REVIEW | 资源类型未定（如 `prefer A to B`） |
| 证据不足（仅正文连续词） | 不建条目（或 NEED_REVIEW 候选） | 无教材教学证据 |

实现方式（零 schema 变更）：用现有 `derivation_type` 区分来源 —— `FROM_TEXTBOOK_LIST`（词表）与 `FROM_TEXTBOOK_NOTE`（语言注释）。

## 12. Phrase source_ref 设计

完整链路：`Phrase → source_ref → content_block → page → original PDF`

现有 `source_ref` 已足够表达，**不新增 source_type 枚举**：

```text
source_type = 'content_block'（保持不变）
source_id   = block_id
quote_raw   = 教材原文片段（如“protect... from... 是固定搭配，意为……”）
emphasis_evidence JSON 内记录 context_type：
    textbook_vocabulary_entry（词表条目）
    language_note / grammar_note（语言注释，如 protect... from...）
    textbook_body（正文出现处，作为补充证据）
```

即：**类型区分放在现有 JSON 字段中，而不是扩充枚举列**——避免无必要枚举增长。

## 13. emphasis_evidence 设计

字段沿用 v3 现有 JSON 结构：`font_name / flags / size / pdf_page / textbook_page / bbox / head_block`。

规则：

1. 词表来源：全部必填（与 Vocabulary 一致）；
2. 语言注释来源：无 head span 时 `font_name=null`、`flags=null`、`size=null`，但必须记录 `pdf_page / textbook_page / bbox / head_block / context_type`；
3. **无视觉加粗证据时记录 UNKNOWN，不记录 PLAIN**（"没有证据" ≠ "非加粗事实"）。

## 14. review / conflict 设计

沿用 Vocabulary 的状态体系（不制造第二套）：

```text
review_status                ：AUTO_OK / NEED_REVIEW / REVIEWED_OK / REJECTED（资源是否成立）
requirement_conflict_status  ：OK / NEED_REVIEW（来源学习要求是否冲突）
```

| 场景 | review_status | learning_requirement | conflict |
|---|---|---|---|
| 教材明确固定搭配（protect... from...） | NEED_REVIEW（首次建库，待人工确认） | CORE | OK |
| 教材明确固定短语（along the way） | NEED_REVIEW | CORE | OK |
| Vocabulary 多词条目（22 条） | 沿用 Vocabulary 同源条目的 review_status（AUTO_OK/NEED_REVIEW） | PLAIN→RECOGNITION | OK |
| Phrase 与 Grammar 边界（prefer A to B） | **不落库**，进入审核队列 | — | — |
| knock around ( | 冻结备注，暂不建 Phrase 条目 | — | — |

## 15. item_id / content_hash 设计

```text
item_id      ：<textbook_id>:P:<sha1(canonical_text|item_type)[:12]>   （与 Vocabulary 的 :V: 命名空间区分）
content_hash ：sha256(<schema_version>|'phrase'|<canonical_text>|<meaning_zh>)

原则：
  - canonical_text 采用教材词表/注释中的规范写法（小写、空白归一）
  - content_hash 只表达"教材派生文本身份"
  - 不纳入：textbook_emphasis、emphasis_evidence、learning_requirement、
            requirement_conflict_status、review_status、Grammar context、
            Vocabulary association、pronunciation / audio
  - 因此新增发音、音频、语法上下文、词汇关联都不会改变 item_id / content_hash
```

注意：以上为**设计候选**（本次不修改代码）；正式构建时须以脚本一次性生成并冻结。

## 16. Pronunciation / Audio 兼容性

Phrase 应与 Vocabulary 具备**同等**的发音能力设计（官方教材音频 > 系统标准 TTS > AI/云端 TTS），但本阶段不修改 schema：

```text
NOW（零 schema 变更即可用）：
  learning_item.phonetic          → 若教材提供 Phrase 音标（本册多词条目无 IPA，保持 NULL）
  audio_mapping.target_type='phrase' + target_id=<phrase item_id>  → 复用现有音频映射表
LATER（需 v4 设计评审）：
  pronunciation_text / pronunciation_ipa / audio / pronunciation_source /
  audio_source / audio_status / locale / voice_type / fallback_level
```

E3 事实：本册无 Phrase 独立官方音频（仅 7 个单元词汇表整体音频，CANDIDATE）；因此 Phrase 发音应走**系统标准 TTS 兜底**，AI/云端 TTS 不得作为默认方案。

## 22. Phrase KEEP / EXCLUDE / NEED_REVIEW 规则

### KEEP

```text
1. 教材词汇表以单一条目列出的多词条目（headword 多词 + 释义 + 教材页码 + head span 字体证据）
2. 教材语言注释明确称为“固定搭配 / 固定短语”的语言单位
```

### EXCLUDE

```text
1. 普通正文/对话/课文中的连续词串
2. 高频但无教材解释证据的多词单位（talk about / look at / …）
3. Communication bank • 条目、Useful expressions 内容、教材明示“固定句型” → Sentence Pattern
4. Grammar rules / Guide to the language use 的规则文本与普通例句 → Grammar
5. 仅因为“连续出现两个或多个单词”或“高频”而提出的候选
```

### NEED_REVIEW

```text
1. 教材给出搭配说明但资源类型未定（prefer A to B）
2. 非词表来源的 Phrase（emphasis=UNKNOWN，且 learning_requirement 由教材注释推断为 CORE）
3. 多来源学习要求不一致（requirement_conflict_status=NEED_REVIEW）
4. knock around ( —— 冻结异常（本次仅备注，不建条目）
```
