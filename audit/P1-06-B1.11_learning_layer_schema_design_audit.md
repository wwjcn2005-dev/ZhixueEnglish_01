## 2. Learner Schema

| 字段 | 级别 | 说明 |
| --- | --- | --- |
| `learner_id` TEXT | **MUST / PK** | 应用生成（ULID/UUID 更好，`L…` 短 ID 亦可）。不用 INTEGER 自增：跨库合并与导出更安全，且与项目既有 TEXT 主键风格一致 |
| `display_name` TEXT | **MUST（不唯一）** | 家庭内可能重名或改名，唯一性由 `learner_id` 保证 |
| `status` TEXT | **SHOULD** | `active / inactive`，默认 `active` |
| `created_at` TEXT(ISO) | **MUST** | — |
| `updated_at` TEXT(ISO) | **SHOULD** | — |
| `deleted_at` | **不需要** | 家庭单用户规模；用 `status='inactive'` 逻辑停用即可，避免引入“软删除时间”与 `status` 两套语义 |
| 账号 / 密码 / 角色 / 家长关系 / 头像 | **FORBIDDEN** | 复杂用户体系属 Later（§二十四） |

**删除策略**：**禁止物理删除**。原因：`LearningRecord` / `MasteryState` 均以 learner 为根，物理删除会产生孤儿历史；停用即可。

## 3. LearningTask Schema

定义：一次有明确学习意图的学习活动集合（不是题目、不是记录、不是掌握状态）。

| 字段 | 级别 | 说明 |
| --- | --- | --- |
| `task_id` TEXT | **MUST / PK** | 应用生成（ULID） |
| `learner_id` TEXT | **MUST** | **必须绑定孩子**：任务属于某个孩子的学习流程（见第 9 节） |
| `goal_id` TEXT | **SHOULD / NULL 允许** | 逻辑引用 `learning_goal.goal_id`；可为空（见第 10 节） |
| `task_kind` TEXT | **MUST** | 最小枚举 `learn / review`（见第 11 节） |
| `status` TEXT | **MUST** | `active / completed / dropped`（见第 12 节） |
| `textbook_id` TEXT | **MUST** | 教材版本绑定（`FLTRP-EN-7A-2022CUR`），用于快照追溯 |
| `created_at` TEXT | **MUST** | — |
| `started_at` TEXT | **SHOULD / 可空** | 首次进入任务时写入 |
| `completed_at` TEXT | **SHOULD / 可空** | 完成时写入 |
| `title` TEXT | **SHOULD / 可空** | 展示用（可由规则生成，不存 AI 文案） |
| `source_kind` TEXT | **LATER** | `rule / user / ai_artifact`；第一阶段规则生成，可省略 |
| 掌握状态 / 分数 / 正确答案 / 推荐分数 / AI 正文 | **FORBIDDEN** | 属于其他层 |

**9. Task 的 learner 归属**：**必须绑定**。理由：任务即“某个孩子要学什么”；若未来需要可复用的“模板任务”，应另立 `task_template`（Later），不用“learner_id 为空”来表达，避免语义含混。

**10. Task 的 goal_id**：**可空**。教材显式目标只有 6 条 unit 级；自主学习、复习、临时练习、薄弱项巩固等任务**不应被迫映射教材目标**。推荐：`goal_id` 可空 + `task_kind='review'` 表达复习任务。

**11. task_kind 最小枚举**：`learn | review`。

```text
learn  ：学习卡、认读、理解、跟读、拼写、替换、造句等
review ：复习（由 MasteryState.review_needed 触发或孩子自主选择）
暂不加入：practice（视为 learn 的一种活动组合）、mixed（任务应只有一个主意图）
```

**12. Task status 最小集合**：`active | completed | dropped`。

```text
不要 draft  ：任务创建即生效（规则生成，无审批流程）
不要 paused ：孩子随时可以离开再回来，任务本身不必进入“暂停”状态（用 last 活动时间即可）
不要企业式工作流状态
```

## 4. TaskItem Schema

| 字段 | 级别 | 说明 |
| --- | --- | --- |
| `task_id` TEXT | **MUST（PK 组成，FK → learning_task）** | — |
| `item_id` TEXT | **MUST（PK 组成，逻辑引用 learning_item）** | 教材资源身份，用户无关 |
| `ordinal` INTEGER | **SHOULD** | 展示顺序；缺失时按插入顺序 |
| `created_at` TEXT | **SHOULD** | 低成本审计字段 |
| `item_role` | **LATER** | 第一阶段每条资源都是“学习对象”，无需区分 primary/support/example；引入时再加可空列 |
| `required` / `status` | **不需要** | 完成状态应由 `LearningRecord` 聚合得出，避免两处口径 |
| `item_type` | **不需要** | 见第 15 节（避免重复事实） |

**14. 主键方案**：

| 方案 | 评估 |
| --- | --- |
| **A. `PK(task_id, item_id)`** | **推荐**：天然防重、无额外代理键、查询直接；家庭规模足够 |
| B. 代理键 + `UNIQUE(task_id,item_id)` | 仅当未来需要“同一资源在同一任务中出现两次（不同角色）”才有价值 |
| C. UUID | 过度设计 |

**15. 是否需要 `item_type`**：**不需要**。`item_id` 前缀已含资源类型（`:V:` / `:P:` / `:SP:`），且类型真值在 `learning_item.item_type`；在 TaskItem 冗余会产生“两处事实”，一旦不一致无法判断谁正确。需要类型时通过 join `learning_item` 获取。

| 字段 | 级别 | 说明 |
| --- | --- | --- |
| `record_id` TEXT | **MUST / PK** | ULID |
| `learner_id` TEXT | **MUST（FK）** | — |
| `task_id` TEXT | **MUST（FK，NOT NULL）** | 所有学习行为都发生在任务内（孩子直接看词卡时，系统创建最小任务 `task_kind='learn'`；浏览教材不产生学习记录） |
| `item_id` TEXT | **MUST（逻辑引用）** | 哪条教材资源 |
| `activity_type` TEXT | **MUST** | 见第 8 节枚举 |
| `result` TEXT | **SHOULD / 可空** | 见第 9 节枚举 |
| `response_raw` TEXT | **SHOULD / 可空** | **仅文本**；手写图片与音频本轮不进入 |
| `attempt_no` INTEGER | **SHOULD** | 语义见第 22 节；默认可为 1 |
| `hints_used` INTEGER | **SHOULD** | **只存数量**（默认 0），不存 AIArtifact ID（见第 24 节） |
| `created_at` TEXT | **MUST** | — |
| `textbook_id` TEXT | **MUST** | 教材版本绑定（快照追溯，见第 14 节） |
| `snapshot_id` TEXT | **SHOULD / 可空** | 记录产生时的教材快照 |
| `duration_ms` | **LATER** | 见第 23 节 |
| `activity_id` | **LATER** | 见第 18 节 |
| `mastery_level` / `review_due` / AI 诊断正文 / 归一化分数 | **FORBIDDEN** | 属于其他层 |

**17. Record 与 TaskItem 的关系（本轮重点）**：

| 方案 | 评估 |
| --- | --- |
| A. `record(task_id, item_id)` | **推荐基础**：与 `TaskItem.PK(task_id,item_id)` 等价定位，无冗余代理键；多资源 Task 天然支持；按 item 聚合掌握度最方便 |
| B. `record(task_item_id)` | 若采用代理键则更“规范”，但引入额外 join 与代理键管理成本；当前不需要 |
| C. `record(task_id, activity_id)` | 第一阶段无 Activity 实体，无法采用 |
| **D. `record(task_id, item_id)` + 未来可加 `activity_id`（可空）** | **推荐方案** |

推荐 **D**。理由：① 数据一致性 —— `(task_id,item_id)` 必须存在于 TaskItem（应用层保证）；② 查询便利 —— 直接支持“按资源聚合”“按任务复盘”；③ 多资源 Task 与非题目型 Activity 均可表达；④ 历史可追溯 —— 记录自含 task 与 item，不依赖 TaskItem 是否仍存在；⑤ 避免冗余 —— 不需要额外代理键。

**18. 与 Activity 的关系**：第一阶段**不设置 `activity_id` 列**；活动语义由 `activity_type` 表达。未来引入 `LearningActivity` 时，用 `ALTER TABLE ... ADD COLUMN activity_id TEXT NULL` 追加可空列即可，**无需数据迁移**（历史记录 activity_id 为 NULL 是合法状态）。

**19. `activity_type` 第一阶段最小集合（9 项）**：

```text
recognize   认读（看词形/听音识别）
read        朗读 / 阅读该资源
understand  理解词义/用法
listen      听音
repeat      跟读/复述
spell       拼写
substitute  句型槽位替换（Phrase / Sentence Pattern）
produce     造句 / 产出表达
review      复习
暂不加入：view（浏览教材不算学习行为）、practice、quiz 等
扩展方式：TEXT 列 + 文档级枚举（不加 CHECK），新增值无需迁移
```

**20. `result` 设计**：**单一字段 + 枚举** `correct | incorrect | partial | done | skipped`。

```text
非题目型活动：done / skipped（不被迫使用 correct/incorrect）
题目型活动：correct / incorrect / partial
不同 activity_type 允许的取值子集由应用层校验（DB 不加 CHECK，便于扩展）
第一阶段不引入 score / outcome 双字段：避免“对错”与“得分”两套口径
未来需要分数时再加 score REAL NULL（LATER）
```

**21. `response_raw`**：保存**文本回答**（选项字母、输入的单词、简短句子）。手写图片与音频**本轮不进入**（避免提前建设媒体系统）；如未来需要，另建媒体引用字段。

**22. `attempt_no` 语义**：**同一 `(learner_id, task_id, item_id, activity_type)` 的第几次尝试**（应用层计算 `count+1`）。与 Record 主键关系一致：`record_id` 是唯一主键，`attempt_no` 是可读序号；第一阶段不设唯一约束。

**23. `duration_ms`**：**LATER**。理由：需要“开始/结束时间”才可靠，而第一阶段只需要最低必要数据；`created_at` 足以支撑“最近学习时间”。

**24. `hints_used`**：**只保存数量**（INTEGER，默认 0）。不保存 `AIArtifact` ID，保持 Record 不依赖 AI 层（AIArtifact 若要追溯，可由 AIArtifact 侧引用 record）。

**25. append-only**：**是**。`LearningRecord` 表示历史事实，**禁止 UPDATE / DELETE**。若发现错误：**新增一条修正记录**（Later 可加 `record_kind ∈ {normal, correction}` + `corrects_record_id`），第一阶段只需“不覆盖”。

## 6. MasteryState Schema

| 字段 | 级别 | 说明 |
| --- | --- | --- |
| `learner_id` TEXT | **MUST（PK 组成，FK）** | — |
| `item_id` TEXT | **MUST（PK 组成，逻辑引用）** | — |
| `mastery_level` TEXT | **MUST** | `unknown / learning / familiar / stable`（见第 10 节） |
| `evidence_count` INTEGER | **SHOULD** | 廉价整数，避免每次实时聚合 |
| `correct_count` INTEGER | **SHOULD** | 同上；一致性由“可由 Record 重建”保证 |
| `last_result` TEXT | **SHOULD** | 派生缓存（避免为了“最近一次表现”扫描 Record）；可由 Record 重建 |
| `last_practiced_at` TEXT | **SHOULD** | — |
| `review_needed` INTEGER | **SHOULD** | 0/1；复习需求是**状态**而非历史（见第 11 节） |
| `next_review_at` | **LATER** | 属调度（见第 11 节） |
| `updated_at` TEXT | **MUST** | — |
| 教材文本副本 / AI 正文 / 算法参数（EF、interval、streak） | **FORBIDDEN** | 属其他层或 Later |

**27. 主键**：**`PK(learner_id, item_id)` 已足够**，不需要 `mastery_state_id`。理由：天然唯一、天然 upsert、无跨库合并需求；代理键只增加复杂度。

**28. mastery_level 等级**：4 级足够。

```text
unknown   ：尚无足够证据
learning  ：已接触，需要提示/辅助
familiar  ：能独立完成，但不稳定
stable    ：多次正确、稳定掌握
不加入 mastered（与 stable 同义，避免同义词膨胀）
不加入 weak / review（这是“复习需求”而不是掌握等级 → 用 review_needed 表达）
```

**29. `last_result`**：**保留（SHOULD）**，但明确它是**派生缓存**：查询便利（无需扫 Record）优于 1 个字段的冗余；一致性由“Record 是事实源、MasteryState 可重建”保证。

**30. `evidence_count` / `correct_count`**：**第一阶段保留（SHOULD）**。理由：数据规模很小但聚合查询频繁（学习卡首页、复习判断）；两个整数成本极低，避免每次 `COUNT(*)`。**不做**更复杂的统计缓存（streak、加权分等）。

**31. review 状态**：保留 `review_needed`（SHOULD）。`next_review_at` **暂缓**：它属于调度算法（间隔复习），第一阶段先由规则决定“要不要复习”，未来加可空列即可（向后兼容）。

## 7. LearningRecord 与 TaskItem 关系

```text
LearningRecord(task_id, item_id)  ──逻辑对应──▶  TaskItem(task_id, item_id)
不建 record → task_item 的外键（TaskItem 是“计划”，Record 是“事实”，事实不应因计划变更而失效）
```

即：TaskItem 被删除（任务取消）时，历史 Record 仍然保留（Record 自含 task_id/item_id）。

## 8. activity_type

见第 5 节（9 项最小集合），并说明：所有值都必须支持**非题目型学习**，且不强制 `result` 为对错。

## 9. result

见第 5 节（`correct | incorrect | partial | done | skipped`；可空；不加 CHECK）。

## 10. Mastery 状态

见第 6 节（4 级语义冻结；不做算法）。

## 11. Review 状态

第一阶段：`MasteryState.review_needed` 即可表达“需要复习”；复习任务 = `LearningTask(task_kind='review')` + `TaskItem`。不建 `ReviewItem`（升级条件见 B1.10 第 9 节）。

## 12. 删除策略

| 实体 | 策略 |
| --- | --- |
| Learner | **禁止物理删除** → `status='inactive'`（学习历史必须保留） |
| LearningTask | **有条件**：无 Record 的任务可物理删除（级联删 TaskItem）；**已有 Record 的任务禁止删除**，只能 `status='dropped'` |
| TaskItem | 随任务级联删除（不承载历史） |
| LearningRecord | **禁止 UPDATE / DELETE**（append-only）；仅整档清理/换设备时整体归档 |
| MasteryState | 可删除（可由 Record 重建）；推荐软重置（`mastery_level='unknown'`）而非删除 |
| learning_item（教材资源） | **完全不属于学习层删除范畴**（v5 只读、冻结） |

## 13. 外键策略

| 关系 | 策略 |
| --- | --- |
| LearningTask → Learner | **必须 FK**（若同库；见第 15 节） |
| TaskItem → LearningTask | **必须 FK** + `ON DELETE CASCADE` |
| TaskItem → learning_item | **逻辑引用**（同库时可加 FK；跨库时不加） |
| LearningRecord → Learner | **必须 FK** |
| LearningRecord → LearningTask | **必须 FK**（不设级联删除：任务不可在有记录时删除） |
| LearningRecord → TaskItem | **不建 FK**（用 `(task_id,item_id)` 逻辑对应） |
| MasteryState → Learner | **必须 FK** |
| MasteryState → learning_item | **逻辑引用** |

原则：**不凭空创建跨数据库 FK**；SQLite 不存在天然跨库外键。

## 14. 教材快照绑定（本轮重点）

核心判断：`item_id` 是**文本身份**（由 `canonical_text` / `pattern_template` 决定）。教材修订导致文本变化 → `item_id` 变化；因此同一个 `item_id` **保证**代表同一教材事实，但**旧 `item_id` 在新快照中可能不存在**。

第一阶段最小方案：

```text
LearningTask.textbook_id   MUST   （教材版本，如 FLTRP-EN-7A-2022CUR）
LearningRecord.textbook_id MUST
LearningRecord.snapshot_id SHOULD（可空；记录产生时的教材快照）
TaskItem / MasteryState   只需要 item_id（无需 snapshot_id）
```

理由：① 需要回答“这条学习历史属于哪个教材版本”→ 放在 Task/Record；② TaskItem/Mastery 是“指向某条资源”，`item_id` 已足够；③ 教材升级后，历史记录仍可追溯（记录自带 textbook_id/snapshot_id），MasteryState 可保留并标记“当前快照已无此资源”（字段 Later）。

**不得**为快照问题修改 v5。

## 15. 跨数据库策略

当前：学习层实体尚不存在，且项目只有一个 contentpack 库（v1–v5）。两种未来方案：

| 方案 | 评估 | 推荐 |
| --- | --- | --- |
| A. 学习层与教材同库（v6 内含新表） | FK 与事务简单、单文件备份；但学习数据（用户）与商业教材内容混在一个文件，违反“商业内容与用户数据隔离”原则 | 否 |
| **B. 学习层独立数据库**（如 `structured/learning/learning.db`），与 contentpack 逻辑引用 | 用户数据与教材内容物理隔离、可单独备份/清理/迁移；代价：无跨库 FK | **推荐** |
| C. 其他（服务端 DB） | 与当前阶段（本地优先、家庭单用户）不符 | 否 |

若采用 B：

```text
教材侧：v5 只读（快照冻结）
学习侧：learner / learning_task / task_item / learning_record / mastery_state
关联：item_id / goal_id / textbook_id 作为逻辑外键；启动或写入时校验存在性
禁止：跨库 FK、禁止学习层写教材库
```

## 16. 索引（逻辑建议）

| 实体 | 必要索引 | 可选索引 | 暂缓索引 |
| --- | --- | --- | --- |
| Learner | PK | — | 任何搜索/画像索引 |
| LearningTask | PK；(learner_id, status, created_at) | (learner_id, task_kind) | 统计/推荐类索引 |
| TaskItem | PK(task_id,item_id)；(item_id) | (task_id, ordinal) | — |
| LearningRecord | PK；(learner_id, created_at)；(learner_id, item_id, created_at)；(task_id) | (item_id, created_at) | 大屏统计/推荐索引 |

## 17. 唯一约束

| 项 | 结论 |
| --- | --- |
| `Learner.display_name` 唯一？ | **不唯一**（家庭内可重名/改名） |
| LearningTask 自然唯一键 | **不需要**（task_id 已唯一） |
| `TaskItem(task_id,item_id)` 唯一 | **是**（= 主键） |
| `MasteryState(learner_id,item_id)` 唯一 | **是**（= 主键） |
| LearningRecord 幂等键 | **第一阶段不设**（append-only 允许重复尝试）；Later 可用 `(task_id,item_id,activity_type,attempt_no)` 防客户端重放 |

## 18. 事务边界

```text
一次学习事件 = 一个事务：
  INSERT LearningRecord
  UPSERT MasteryState
（同一数据库时天然原子）

若 Mastery 更新失败 → 整个事务回滚（不留“有记录、无状态”）
若两者需分库/分进程 → 以 Record 为事实源，MasteryState 允许滞后，并提供“由 Record 重建掌握状态”的维护操作
```

## 19. AIArtifact 兼容性

```text
不建立 AIArtifact → 学习层 的 FK。
引用方式：target_layer ∈ {textbook_resource, learning_task, learning_record} + target_id
         context_ref_ids 可放 item_id / record_id / source_ref_id
可追溯：AI 产物知道自己基于哪条教材资源与哪次学习
低耦合：删除 AI 产物不影响学习层；教材资源不依赖 AI 产物
可缓存：缓存键 = (artifact_kind, target_layer, target_id, model, prompt_version)
```

## 25. 迁移风险

| 风险 | 等级 | 说明 |
| --- | --- | --- |
| 数据库迁移 | **低** | 若采用独立学习库（方案 B），完全不触碰 v5 的 21 张表；若同库新增 5 表，也是纯新增 |
| 教材兼容 | **低** | 学习层只读引用 `item_id`，不修改教材资源 |
| 历史记录 | **低** | Record append-only；TaskItem 变更不影响历史 |

| AI 耦合 | **低** | 无 FK，AIArtifact 可删除、可缓存，不进主链 |
