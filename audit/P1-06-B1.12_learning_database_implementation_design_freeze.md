## 2. 独立数据库方案

**为什么不把 5 张表直接加进 v5？**

```text
① 商业内容保护：教材库是发布资产，不应混入用户数据（否则无法对外分发/授权）
② 教材冻结：v5 已经冻结并被 G1-E/B1.8 归档为基线，任何写入都会破坏冻结语义
③ 用户数据隔离：学习数据含个人行为，需要单独备份、单独删除、单独迁移
④ 备份策略不同：教材库可重建，学习库不可再生（备份频率与保留策略完全不同）
⑤ 未来 v6/v7：教材升级时只需切换只读库，不迁移用户数据
⑥ 学习数据生命周期：用户数据可能被清理/重置，不应牵连教材库
```

**冻结方案**：

| 项目 | 决定 |
| --- | --- |
| 目录 | `D:\ZhixueEnglish\structured\learning\`（新目录，与本轮无关，实施阶段创建） |
| 文件名 | `learning.db`（SQLite 单文件） |
| 与 contentpack 关系 | **单向只读引用**：学习库引用 `item_id` / `goal_id` / `textbook_id`，从不写入教材库 |
| 初始化方式 | 幂等初始化脚本（实施阶段新建，例如 `builder/init_learning_db.py`）；脚本不存在时**不自动创建** |
| 版本号机制 | `PRAGMA user_version`（权威版本号）+ 可选 `schema_migration` 记录表 |
| 迁移机制 | 编号 SQL 步骤顺序应用，每步一个事务，迁移前先备份；不引入 Alembic 等新依赖 |

**现状核查（只读）**：项目当前**没有**迁移机制、没有 `*.sql` 文件、没有 `structured/learning` 目录；v5 的 `PRAGMA user_version = 0`，且不存在 version/migration 表。因此上述方案是**最小新增**，不覆盖任何既有约定。

## 8. Record ↔ TaskItem 最终关系

**最终冻结：`learning_record(task_id, item_id)`**（不保存 `task_item_id`，不建立到 `task_item` 的外键）。

| 维度 | 结论 |
| --- | --- |
| 可追溯 | Record 自含 `task_id + item_id`，永远可定位“哪次任务、哪条资源” |
| 冗余 | 无（`(task_id,item_id)` 本身即 TaskItem 主键，等价定位） |
| 计划变化 | TaskItem 删除（任务取消）后，历史 Record **仍然有效** |
| 多资源任务歧义 | 无 = 每条记录只对应一条资源 |
| 为什么不到 task_item 建 FK | 计划（TaskItem）可变，事实（Record）不可因计划变化而失效；FK + CASCADE 会误删历史，FK + RESTRICT 会锁死任务编辑 |
| TaskItem 删除后 | Record 保持完整；掌握状态不受影响（MasteryState 只依赖 learner+item） |

## 9. textbook_id / snapshot_id

| 标识 | 保存内容 | 位置 | 职责 |
| --- | --- | --- | --- |
| `textbook_id` | **教材身份**（哪本教材，如 `FLTRP-EN-7A-2022CUR`） | `learning_task`（MUST）、`learning_record`（MUST） | 回答“学的是哪本教材” |
| `snapshot_id` | **教材快照身份**（哪一次解析发布，如 `…:S20260912T151307`） | `learning_record`（可空 SHOULD） | 回答“这条记录产生时教材处于哪个快照” |
| `item_id` | **资源文本身份** | `task_item`、`learning_record`、`mastery_state` | 回答“学的是哪条资源” |

**Task 是否需要 snapshot_id？——第一阶段不需要（方案 B）**：

```text
方案 A（Task 存 textbook_id + snapshot_id）：Task 创建时冻结快照，但任务可能持续跨快照，语义会漂移
方案 B（Task 只存 textbook_id；Record 存 textbook_id + snapshot_id）：推荐 —— 任务级只需回答“哪本教材”，
        快照精确性放在每次学习记录上（事实层），更准确且无迁移成本
方案 C：其他（如 TaskItem 存 snapshot）→ 冗余，不采用
```

结论：旧 Task 在教材切换到 v6 后**仍然能准确解释**（textbook_id 不变；快照在 Record 上逐次记录）。

## 10. v6/v7 场景推演

| 场景 | 旧学习记录 | 旧掌握状态 | 新教材资源 | 处理原则 |
| --- | --- | --- | --- | --- |
| **1. v5 → v6，同一 item_id 仍存在**（文本未变） | 保持不变 | 保持不变，可继续累积证据 | 同一资源 | 无缝；无需迁移 |
| **2. v6 删除了该 item_id** | 保持不变（记录自带 textbook_id/snapshot_id/item_id） | **保留**（历史事实） | 该资源在新教材不存在 | 展示时提示“该资源已不在当前教材版本”；不回写、不删除历史；未来可加 `item_missing_in_current_snapshot` 标记（LATER） |
| **3. v6 中同一文本重新出现但 item_id/content_hash 不同**（教材修订导致文本身份变化） | 保持不变 | 保留在旧 item_id 上 | 新 item_id 是新资源 | **视为两条不同资源**：新资源从 `unknown` 开始；不做自动合并（合并需要人工/受控任务） |

统一原则：**永不修改旧学习历史**；教材演进只影响“当前可用资源视图”，不影响历史事实。

## 11. 外键策略

| 关系 | 最终方案 | 理由 |
| --- | --- | --- |
| `learning_task.learner_id → learner.learner_id` | **FK，ON DELETE RESTRICT，ON UPDATE CASCADE** | 有任务的 learner 不能物理删除 |
| `task_item.task_id → learning_task.task_id` | **FK，ON DELETE CASCADE，ON UPDATE CASCADE** | TaskItem 是计划的组成部分，随任务删除 |
| `learning_record.learner_id → learner.learner_id` | **FK，ON DELETE RESTRICT** | 历史不可因删除用户而丢失 |
| `learning_record.task_id → learning_task.task_id` | **FK，ON DELETE RESTRICT** | 有记录的任务不允许删除（只能 dropped） |
| `mastery_state.learner_id → learner.learner_id` | **FK，ON DELETE RESTRICT** | 状态以用户为根 |
| `task_item.item_id → learning_item.item_id` | **LOGICAL REFERENCE（非 FK）** | 跨数据库；SQLite 无跨库 FK |
| `mastery_state.item_id → learning_item.item_id` | **LOGICAL REFERENCE（非 FK）** | 同上 |
| `learning_record.item_id → learning_item.item_id` | **LOGICAL REFERENCE（非 FK）** | 同上 |
| `learning_task.goal_id → learning_goal.goal_id` | **LOGICAL REFERENCE（非 FK），且可 NULL** | 跨数据库；且自主学习/复习任务可以没有目标 |

实施要求：每个连接必须 `PRAGMA foreign_keys = ON`；逻辑引用的一致性由应用层校验（写入前检查 item_id/goal_id 是否存在于当前 contentpack 库）。

## 12. 删除策略

| 实体 | 策略 |
| --- | --- |
| `learner` | **禁止物理删除** → `status='inactive'` |
| `learning_task` | 无记录：可物理删除（级联 TaskItem）；有记录：**只能 `status='dropped'`** |
| `task_item` | 允许删除（随任务级联）；**删除不影响历史 Record** |
| `learning_record` | **append-only：禁止 UPDATE / DELETE**；修正 = 新增记录 |
| `mastery_state` | 允许删除（可由 Record 重建）；推荐软重置为 `unknown` |
| 教材资源（learning_item） | **只读，不属于学习层删除范畴** |

## 13. 枚举策略

**统一策略：枚举以 TEXT 存储，不使用 CHECK 约束**，由应用层校验 + 文档冻结。理由：CHECK 会导致“新增枚举值必须迁移数据库”，与“低成本演进”冲突；当前无外部写入方，风险可控。

```text
learner.status        : active | inactive
learning_task.task_kind: learn | review
learning_task.status  : active | completed | dropped
learning_record.activity_type（9，冻结）:
    recognize | read | understand | listen | repeat | spell | substitute | produce | review
    （ensure 非题目型学习：read / listen / repeat 可用 result='done'；不加 view）
learning_record.result（5 + NULL）:
    correct | incorrect | partial | done | skipped | NULL
    done    ：完成但无对错判定（阅读、跟读、听音）
    correct ：题目型完全正确
    partial ：题目型部分正确
    skipped ：孩子主动跳过
    NULL    ：仅记录“发生过”（如打开卡片）
mastery_state.mastery_level（4，冻结，仅语义不含阈值）:
    unknown  ：尚无足够证据
    learning ：已接触，仍需提示或辅助
    familiar ：当前证据表明能独立完成，但不稳定
    stable   ：当前证据表明该资源掌握较稳定
```

## 14. SQLite 类型策略

```text
ID        : TEXT         （ULID/UUID/短 ID；与项目既有 TEXT 主键风格一致，跨库可移植）
时间      : TEXT ISO-8601（'2026-09-12T15:30:00+08:00'；可读、可排序、无时区歧义）
布尔      : INTEGER 0/1  （SQLite 无原生 bool）
计数      : INTEGER
长文本    : TEXT
枚举      : TEXT
```

理由：与 v5 既有约定一致（`learning_item.created_at`、`snapshot_id` 等均为 TEXT），避免同一项目出现两套时间/ID 语义。

## 17. 事务

```text
BEGIN;
  INSERT INTO learning_record(...);
  UPSERT mastery_state (learner_id, item_id)  -- 依据本次 record 更新派生状态
COMMIT;

MasteryState 更新失败 → 整体回滚（不允许“有记录、无状态”）
Record 是历史事实源；MasteryState 可由 Record 完整重建（维护操作）
```

## 18. 初始化


## 23. SQL 草案（仅文本，**未执行**）

```sql
PRAGMA foreign_keys = ON;

CREATE TABLE learner (
  learner_id   TEXT PRIMARY KEY,
  display_name TEXT NOT NULL,
  status       TEXT NOT NULL DEFAULT 'active',
  created_at   TEXT NOT NULL,
  updated_at   TEXT
);

CREATE TABLE learning_task (
  task_id      TEXT PRIMARY KEY,
  learner_id   TEXT NOT NULL REFERENCES learner(learner_id) ON DELETE RESTRICT ON UPDATE CASCADE,
  goal_id      TEXT,
  task_kind    TEXT NOT NULL,
  status       TEXT NOT NULL DEFAULT 'active',
  textbook_id  TEXT NOT NULL,
  title        TEXT,
  created_at   TEXT NOT NULL,
  started_at   TEXT,
  completed_at TEXT
);
CREATE INDEX idx_learning_task_learner ON learning_task(learner_id, status, created_at);

CREATE TABLE task_item (
  task_id    TEXT NOT NULL REFERENCES learning_task(task_id) ON DELETE CASCADE ON UPDATE CASCADE,
  item_id    TEXT NOT NULL,
  ordinal    INTEGER,
  created_at TEXT,
  PRIMARY KEY (task_id, item_id)
);
CREATE INDEX idx_task_item_item ON task_item(item_id);

CREATE TABLE learning_record (
  record_id     TEXT PRIMARY KEY,
  learner_id    TEXT NOT NULL REFERENCES learner(learner_id) ON DELETE RESTRICT ON UPDATE CASCADE,
  task_id       TEXT NOT NULL REFERENCES learning_task(task_id) ON DELETE RESTRICT ON UPDATE CASCADE,
  item_id       TEXT NOT NULL,
  activity_type TEXT NOT NULL,
  result        TEXT,
  response_raw  TEXT,
  attempt_no    INTEGER NOT NULL DEFAULT 1,
  hints_used    INTEGER NOT NULL DEFAULT 0,
  textbook_id   TEXT NOT NULL,
  snapshot_id   TEXT,
  created_at    TEXT NOT NULL
);
CREATE INDEX idx_record_learner_time      ON learning_record(learner_id, created_at);
CREATE INDEX idx_record_learner_item_time ON learning_record(learner_id, item_id, created_at);
CREATE INDEX idx_record_task              ON learning_record(task_id);

CREATE TABLE mastery_state (
  learner_id        TEXT NOT NULL REFERENCES learner(learner_id) ON DELETE RESTRICT ON UPDATE CASCADE,
  item_id           TEXT NOT NULL,
  mastery_level     TEXT NOT NULL DEFAULT 'unknown',
  evidence_count    INTEGER NOT NULL DEFAULT 0,
  correct_count     INTEGER NOT NULL DEFAULT 0,
  last_result       TEXT,
  last_practiced_at TEXT,
  review_needed     INTEGER NOT NULL DEFAULT 0,
  updated_at        TEXT NOT NULL,
  PRIMARY KEY (learner_id, item_id)
);
CREATE INDEX idx_mastery_review ON mastery_state(learner_id, review_needed);

CREATE TABLE schema_migration (
  version     INTEGER PRIMARY KEY,
  applied_at  TEXT NOT NULL,
  description TEXT,
  sql_sha256  TEXT
);
PRAGMA user_version = 1;
```

说明：`learning_item.item_id` / `learning_goal.goal_id` / `parse_snapshot.snapshot_id` **不写 FK**（跨数据库，逻辑引用）；`learning_record` 的 append-only 由应用层保证（第一阶段不加 trigger，避免过度复杂；如需数据库级强约束，Later 可加 `BEFORE UPDATE/DELETE` trigger `RAISE(ABORT)`）。
