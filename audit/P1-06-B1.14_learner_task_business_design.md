## 2. Learner 业务语义

### 2.1 Learner 是什么

> **Learner = 一个实际学习者的用户层根节点。**

不是：家长、账号系统、登录账号、AI Agent、班级、学校、设备、教材、学习任务。

### 2.2 第一阶段最小行为（冻结）

| 行为 | 冻结结论 | 说明 |
| --- | --- | --- |
| 创建 | 允许（**显式创建**，见第 3 节） | 首启引导，由孩子/用户确认 |
| 查看 | 允许 | 名称、状态 |
| 修改 `display_name` | **允许** | 家庭内改名合法；不唯一 |
| `active / inactive` | 允许 | inactive = 不再使用，不代表删除 |
| 是否允许多个 Learner | **允许**（数据库能力） | 第一阶段 UI 可不做切换（LATER，见第 13 节） |
| 是否允许同名 | **允许**（`display_name` 不唯一） | 用 `learner_id` 区分 |
| inactive 后是否保留历史 | **必须保留**（Record / MasteryState 全部保留） | inactive 不隐藏历史、不影响追溯 |
| 是否禁止删除 | **禁止物理删除** | 学习历史以 learner 为根；误创建只能停用 |

## 3. Learner 创建方式

| 方案 | 分析 | 结论 |
| --- | --- | --- |
| A. 静默自动创建 | 数据语义上无法区分“真实用户”与“占位账号”；多孩子场景会积累空 Learner；误创建后无法删除（只能停用）；后续 Android UI 也无法解释“这个孩子是谁” | **否决** |
| **B. 显式创建** | 首启由用户主动进入“创建学习者 → 输入名字 → 确认”；`learner_id` 有明确语义；多孩子可自然增加；与“孩子做主”一致 | **推荐（B1.12 已冻结）** |

细节冻结：

```text
1. 入口：首次学习前的引导页（UI 属后续阶段，本轮只冻结数据规则）
2. 名称：必填（去首尾空白后非空；建议长度 1–20 字符；UI 可预填提示文本，但必须由用户确认提交）
3. 不自动填充默认名、不自动提交
4. 允许后续改名；允许重名
5. 无删除功能；仅 active / inactive
6. 允许存在多个 Learner（多孩子家庭）；第一阶段 UI 允许只展示“当前 Learner”
```

## 4. Learner 与教材的关系

```text
Learner ≠ Textbook
一个 Learner 可以使用多个教材；一个教材可以服务多个 Learner（关系通过 Task 表达）
```

**Learner 表不得保存**：`textbook_id`、当前科目、当前单元、当前知识点、学习进度 —— 这些属于**学习上下文**，落在 `LearningTask` / `TaskItem` 上，而不是学习者身份。

## 5. LearningTask 业务语义

> **LearningTask = 一次有明确学习范围和学习意图的计划性学习活动集合。**

Task 不是：单个题目、单次答题、一条 LearningRecord、一个知识点、一个页面、一次 AI 对话、一门课程、一份作业单、学校 LMS 作业。

## 6. Task 创建权

```text
第一阶段：孩子主动创建 Task（系统只负责把孩子的选择记录为 Task）
不允许：AI 自动创建 Task
```

必须区分两个动作：

| 动作 | 主体 | 含义 |
| --- | --- | --- |
| 选择学习内容（科目 → 教材 → 单元/范围 → 学习资源 → 学习方式） | **孩子** | 这是“学什么”的决定 |
| 保存学习计划（写入 `learning_task` + `task_item`） | **系统** | 这是“把选择记下来”的执行 |

系统不得替孩子决定范围，也不得在孩子未确认时创建 Task。

## 7. Task 与教材资源的关系

```text
Task
 ├── textbook_id            ← 教材上下文（哪本教材）
 └── TaskItem (1..N)
       ├── item_id → learning_item（逻辑引用，跨库）
       ├── item_id → learning_item
       └── ...
```

| 规则 | 冻结结论 |
| --- | --- |
| `textbook_id` 含义 | Task 的教材上下文（一个 Task 只属于一本教材） |
| `item_id` 含义 | Task 实际包含的教材学习资源 |
| Task 是否拥有教材资源 | **不拥有**，只引用 |
| `item_id` 是否可复制教材文本 | **禁止**（教材文本只存在于 contentpack） |

## 8. Task 是否必须至少一个 TaskItem

| 方案 | 分析 |
| --- | --- |
| A. 允许 0 个 TaskItem | 会产生“空任务”；而第一阶段**没有 draft 状态**，空任务只能是 `active`，语义上等于“正在学习但没有内容”，与状态定义矛盾，并污染 active 列表 |
| **B. 创建时必须至少 1 个 TaskItem** | **推荐**：与用户操作路径一致（先选资源再开始）；无空任务；无 draft 也能保证一致性 |

**冻结：`learning_task` 与其 `task_item` 必须在同一事务内创建，Task 创建时至少 1 个 TaskItem。**

补充：若用户在“选择资源”阶段中途退出，则**不创建 Task**（未开始即不存在）；不需要草稿态。

## 9. Task 状态语义

| 状态 | 进入条件 | 触发者 |
| --- | --- | --- |
| `active` | Task 创建成功（且有 ≥1 TaskItem） | 系统（在孩子的选择被确认后） |
| `completed` | 孩子明确点击“完成本次学习” | **孩子**（不由系统按数量/时间自动判定） |
| `dropped` | 孩子主动放弃/取消该计划 | **孩子**（明确操作） |

禁止引入：`paused`、`draft`、`cancelled`、企业工作流状态。

## 10. Task 与“退出”的关系

| 行为 | 结果 |
| --- | --- |
| 退出 App | Task 保持 `active` |
| 切换页面 | Task 保持 `active` |
| 暂时离开 | Task 保持 `active` |
| 手机锁屏 | Task 保持 `active` |
| 第二天回来 | Task 仍为 `active`（可继续） |

冻结规则：**异常中断与离开不会自动改变任务状态**；只有孩子明确操作才会 `completed` 或 `dropped`。因此任务可能长期保持 `active`；数据层允许同一 Learner 同时存在多个 `active` Task（UI 可只展示最近若干条 —— UI 属后续阶段）。

## 11. task_kind

```text
learn  ：首次学习 / 建立理解 / 新资源学习
review ：针对已经存在学习状态的资源进行复习（孩子主动发起）
```

**`review` 不是 Review 算法。** 第一阶段不得因为 `task_kind='review'` 就实现：间隔重复、`next_review_at`、自动排程、自动选题、掌握度阈值。

## 12. Review Task 的创建

| 路径 | 允许？ |
| --- | --- |
| 孩子主动选择资源 → 创建 `task_kind='review'` → TaskItem → 开始学习 | **允许** |
| AI 发现 `mastery_state.review_needed=1` → 自动创建 review Task | **不允许** |
| AI 提示“这些内容可能值得复习” → 孩子决定是否复习 → 孩子确认后系统创建 | 未来允许（第一阶段可仅提示） |

## 13. TaskItem 职责

> **TaskItem = Task 与教材学习资源之间的最小计划桥接。**

只保存：`task_id` / `item_id` / `ordinal` / `created_at`。

不保存：教材文本、词义、AI 内容、掌握度、答题结果、是否完成、是否正确、`item_type`、`item_role`、`required`、`status`。

## 14. TaskItem.ordinal

| 问题 | 冻结结论 |
| --- | --- |
| 语义 | Task 内资源的展示/学习顺序 |
| 起始值 | **从 1 开始**（0 不使用） |
| 是否允许 NULL | **允许**（表示未指定顺序；展示时按 `item_id` 或插入顺序兜底） |
| 是否允许重复 | 应用层应保证同一 Task 内不重复（**DB 不加唯一约束**，避免未来迁移） |
| 是否允许重新排序 | **允许**（Record 不依赖 ordinal） |
| 是否允许中途添加资源 | **允许**（`active` 状态可新增 TaskItem，不影响已产生的 Record） |

## 15. TaskItem 与资源类型

**允许一个 Task 混合 Vocabulary / Phrase / Sentence Pattern**：

```text
Task（learn）
 ├─ Vocabulary: peaceful
 ├─ Phrase: along the way
 └─ Sentence Pattern: it’s no secret that {1}
```

理由：① Task 是学习活动容器，不是资源类型；② 三类教材资源在教材中本来就在同一课时/同一主题下混合出现；③ G1-A/B 已确认三者同级独立；④ 当前没有 Activity / Question，混合不会造成执行歧义；⑤ 后续 Activity 阶段可按 `item_id` 前缀（`:V:` / `:P:` / `:SP:`）决定活动类型。

唯一限制：`item_id` 必须来自教材资源（不得指向 AI 生成内容）。

## 16. Task 与章节/单元

当前 Task **没有** `unit_id` / `section_id` / `chapter_id`，**这是正确的**：

```text
所需信息已可由现有链条推导：
  task_item.item_id → learning_item → source_ref → content_block → page → unit/section（v5 教材层）
加字段会与教材层重复，并产生“两处事实”
```

如未来产品需要“按单元组织学习计划”的强查询，列为 **LATER / P3**（可先用只读推导实现，不急于改 schema）。

## 17. Task 创建来源

| 来源 | 第一阶段 | 说明 |
| --- | --- | --- |
| 孩子主动选择 | **允许（唯一自动入口）** | 首选路径 |
| AI 建议 → 孩子确认 | **未来允许**（第一阶段可仅提示） | 必须“孩子确认 → 系统创建” |
| 系统自动创建 | **不允许** | 违反“孩子做主” |
| 家长创建 | **不设计** | 当前项目无家长工作流 |
| 学校/教师创建 | **不设计** | 不属于当前产品 |

## 18. Task 生命周期

```text
        ┌──────────────┐
        │    active    │   ← Task 创建（≥1 TaskItem）
        └──────┬───────┘
               │
     ┌─────────┴─────────┐
     ↓                   ↓
 completed            dropped
（孩子点击“完成”）   （孩子主动放弃）
```

| 规则 | 冻结结论 |
| --- | --- |
| 是否允许 `completed → active` | **不允许**（要重新学习 → 新建 Task） |
| 是否允许 `dropped → active` | **不允许**（同上） |
| 状态是否可逆 | **不可逆**（单向） |
| `active` 期间是否可改 TaskItem | 允许（见第 20 节） |
| 有 Record 后可改哪些字段 | 见第 20 节（`learner_id` 永不可改；有 Record 后 `textbook_id` / `task_kind` 不可改） |

## 19. Task 与 LearningRecord 边界

```text
LearningTask   = 计划（意图）
LearningRecord = 历史事实（实际发生）
```

示例：Task A 含 `peaceful`、`along the way`、`it’s no secret that {1}`，孩子实际只学了前两个 → 只产生两条 Record；**TaskItem 存在 ≠ 已学习**，不得由 TaskItem 推断完成度。

## 20. TaskItem 删除与 Task 修改

| 场景 | 规则 |
| --- | --- |
| 无 Record 时 | TaskItem 可自由增、删、改（含 ordinal 重排）；`textbook_id` / `task_kind` 可改 |
| 有 Record 后 | 允许新增 TaskItem（继续学习同一任务）；允许删除 TaskItem（**历史 Record 不受影响**，Record 自含 `task_id`+`item_id`）；**禁止修改 `learner_id`（永不可改）、`textbook_id`、`task_kind`** |
| `completed` / `dropped` 后 | Task 与 TaskItem **只读**（如需继续学习 → 新建 Task） |

避免复杂权限系统：以上规则由应用层校验，数据库不实现触发器与权限表。

## 21. Learner 多用户

```text
数据库能力（允许多 Learner）  ≠  第一阶段 UI 能力（可只支持单 Learner 展示）
```

第一阶段 UI：可只做“当前 Learner”概念（新增/切换界面标记 **LATER / P3**），但**不因此删减数据库设计**。

## 22. textbook_id 的实际来源

v5 实测：`learning_item.textbook_id` 362/362 均为 `FLTRP-EN-7A-2022CUR`。

冻结规则：

```text
用户选择教材 → 系统从 contentpack 读取该教材的 textbook_id → 创建 Task 时写入
禁止：用户手输 textbook_id、从 URL/参数直接写入、使用不在 contentpack 中的值
```

（UI 与读取实现属后续阶段。）

## 23. item_id 的合法性

| 场景 | 规则 |
| --- | --- |
| 创建 Task（含后续新增 TaskItem） | **只允许选择当前可用教材资源**（存在于当前 contentpack 的 `learning_item`） |
| 历史 Task | 教材更新后**不强制删除** TaskItem；若该 `item_id` 在当前快照不存在，展示层提示“该资源已不在当前教材版本”，数据保留 |
| 是否允许引用不存在的 item | **不允许**（写入前校验） |
| v6/v7 后 | 与 B1.12 场景一致：旧记录保留、掌握状态保留、新资源独立（不自动合并） |

## 24. AI 边界

```text
AI 不得：create learner / create task / create task_item / 修改教材资源
AI 可以：分析、提示、建议、解释（结果可缓存为 AIArtifact）
未来路径：AI 建议 → 孩子确认 → 系统创建 Task        （不是：AI → Task）
```

## 25. 不设计 Activity（边界确认）

本轮不创建 `learning_activity`，不设计 question / exercise / answer / audio task / handwriting task / AI exercise。

只需保证现有模型可自然扩展：

```text
现在 ：Task → TaskItem →（后续 Record）
未来 ：Task → Activity → Record
```

## 26. 不设计 Mastery 算法（边界确认）

本轮可使用 `mastery_state` 作为已知结构背景，但**不得**定义：mastery_level 自动变化算法、分数阈值、正确率、连续正确次数、`review_needed` 算法、`evidence_count` 更新规则。这些都属后续 Record / Mastery 业务阶段。

## 27. 业务时序（三场景）

### 场景 A：首次学习

```text
孩子 → 打开系统
（若尚无 Learner）→ 显式创建 Learner（输入名字 → 确认）
→ 选择教材（系统解析 textbook_id）
→ 选择学习资源（Vocabulary / Phrase / Sentence Pattern，可混合）
→ 确认开始学习
→ 系统在一个事务内创建：LearningTask(learn, active) + TaskItem(≥1)
→ （后续阶段才产生 LearningRecord）
```

### 场景 B：孩子主动复习

```text
孩子 → 选择已学过的资源
→ 确认“复习这些”
→ 系统创建：LearningTask(review, active) + TaskItem
→ 后续学习
（AI 可在此之前提示“可能值得复习”，但不创建 Task）
```

### 场景 C：AI 建议

```text
已有学习数据 → AI 分析 → 生成建议（AIArtifact，可缓存）
→ 展示给孩子：“这些内容可能值得复习”
→ 孩子决定（继续 / 稍后 / 跳过 / 换一个）
→ 若孩子确认 → 系统创建 Task
```

**AI 不直接创建 Task**（证明：所有 Task 写入都由“孩子明确选择/确认”触发）。

## 28. 是否需要新增字段

**结论：本轮无需新增任何字段**（B1.12 冻结 Schema 足以表达上述业务语义）。

明确拒绝（不因“以后可能需要”而添加）：

```text
current_unit / current_item / progress / completion_percent /
source / ai_generated / recommendation_id /
parent_id / school_id / class_id / device_id / session_id
```

如未来确需，必须另立受控设计任务并说明“现有 Schema 为何无法表达”。

## 29. 最终冻结内容

### Learner

```text
身份定义 ：一个实际学习者的用户层根节点（非家长/账号/Agent/班级/学校/设备）
创建方式 ：显式创建（B1.12 冻结，不静默自动创建）
多 Learner：数据库允许；第一阶段 UI 可只做单 Learner（LATER）
同名      ：允许（display_name 不唯一）
active/inactive：允许；inactive 保留全部历史
删除      ：禁止物理删除
修改      ：允许修改 display_name
```

### LearningTask

```text
定义      ：一次有明确学习范围和学习意图的计划性学习活动集合
创建者    ：第一阶段仅“孩子主动选择/确认”触发（系统执行写入）
task_kind ：learn | review（review ≠ Review 算法）
status    ：active | completed | dropped（单向；无 paused/draft/cancelled）
textbook_id：必填；由系统从 contentpack 解析，禁止用户手输
goal_id   ：可 NULL；第一阶段不强制映射教材目标
title     ：可 NULL；可由规则生成
生命周期  ：active → completed / dropped；离开/中断保持 active
修改规则  ：无 Record 时可改 textbook_id / task_kind / TaskItem；有 Record 后仅可新增或删除 TaskItem、可改 title；completed/dropped 后只读
删除规则  ：无 Record 可物理删除（级联 TaskItem）；有 Record 只能 dropped
```

### TaskItem

```text
定义      ：Task 与教材学习资源之间的最小计划桥接
item_id   ：逻辑引用 learning_item；创建时校验“当前可用”；教材更新后保留历史
ordinal   ：1 起；可 NULL；应用层保证同一 Task 内不重复；可重排；可中途新增
添加/删除  ：active 期间允许；有 Record 后删除不影响历史 Record
与 Record ：TaskItem 存在 ≠ 已学习；Record 只记录真实发生的行为
```

### AI

```text
能  ：分析、提示、建议、解释（可缓存 AIArtifact）

```

```text

```

## 30. 最终推荐流程

```text
Learner（显式创建）
   ↓
孩子选择教材（系统解析 textbook_id）
   ↓
孩子选择学习资源（Vocabulary / Phrase / Sentence Pattern，可混合）
   ↓
系统创建 LearningTask（learn | review，active）
   ↓
系统创建 TaskItem（≥1，1 个事务）
   ↓
进入后续 Activity / Record 阶段

AI 只能在选择之前或过程中：分析 / 提示 / 建议 / 解释
（不得越过孩子直接创建 Task）
```
