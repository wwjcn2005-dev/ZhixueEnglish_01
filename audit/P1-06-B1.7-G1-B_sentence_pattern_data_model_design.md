## 4. Q1：为什么 Sentence Pattern 必须是独立资源类型

1. **身份语义不同**：Phrase 是词组级单位（无主谓骨架）；Sentence Pattern 是句式级单位（含主谓骨架 + 可替换句子成分槽位）。
2. **教材证据面不同**：Phrase 来自词表条目 / 固定搭配注释；Sentence Pattern 来自 Communication bank、单元内 Useful expressions、教材明文“固定句型”。
3. **学习行为不同**：Phrase 学习是“记住并用”；Sentence Pattern 学习是“替换槽位并迁移造句”——需要模板与实例两个维度。
4. **若不独立**：塞进 Phrase 会丢失槽位结构，塞进 Grammar 会丢失交际可用性，都会破坏 G1-A 已确认的边界。
5. **实现代价为零**：v4 的 learning_item 已是类型无关表（vocabulary / phrase 两种 item_type），新增第三种不需要 schema change。

## 7. Q7：item_id 设计

```text
推荐：<textbook_id>:SP:<stable-id>
      FLTRP-EN-7A-2022CUR:SP:<SHA1(pattern_template | 'sentence_pattern')[:12] 大写>
```

- **canonical identity 输入**：`pattern_template`（教材骨架 + `{n}` 位置槽位）+ 资源类型 token `'sentence_pattern'`。
- **算法**：SHA-1 截取前 12 位十六进制大写，与 v3/v4 既有 `:V:` / `:P:` 实现同族（项目约定 `sha1(canonical|type)[:12]`）。
- **稳定性**：只依赖教材骨架与资源类型；不含学习属性、来源、实例、音频、Grammar 关联。
- **跨快照稳定**：是。新增实例、修改 review_status / learning_requirement / emphasis、绑定音频都不改变 item_id。
- **命名空间**：`:SP:` 与 `:V:` / `:P:` 隔离；**不采用 `:S:`**（`parse_snapshot.snapshot_id` 使用 `:S<时间戳>` 前缀，`:SP:` 避免前缀混淆）。
- 首批 52 条 item_id 唯一性、与现有 310 条 item_id 的冲突检查：见第 20 节。

## 9. Q4/Q5：canonical_text 与 pattern_template

**推荐：canonical_text 即 pattern_template**（同一字段承担身份），不新增列；教材原样另存 `display_text` / `surface_form`。

### 规则 T-SP-1（模板化规则，必须冻结）

```text
1. 输入只能是教材呈现原文（Communication bank / Useful expressions 条目 / 语言注释中被教材点名的句型）。
2. 教材的每个显式槽位标记 “...” 按出现顺序替换为 {1} {2} ...（只标位置，不命名语义）。
3. 归一化：去项目符号、空白归一；保留教材大小写与标点；不做小写化（避免产生非教材写法）。
4. 占位符与相邻单词之间补一个空格；占位符后紧跟标点时不留空格（例：What are some solutions for {1}?）。
5. 教材的斜杠选项与括号变体（a(n) / make(s)）原样保留，不展开、不同义替换。
6. 禁止语法抽象、禁止补充教材未写的词、禁止把不同教材文本合并为一个模板。
```

| `What are some solutions for...?` | `What are some solutions for {1}?` |

## 18. Q14/Q15/Q16：学习属性

### textbook_emphasis（Q14）

| 议题 | 结论 |
| --- | --- |
| 是否保留三态 | 字段沿用 BOLD / PLAIN / UNKNOWN，但**第一批 52 条全部 UNKNOWN** |

### learning_requirement（Q15）

```text
禁止机械继承 Vocabulary 规则（BOLD→CORE / PLAIN→RECOGNITION）。
由“教材是否把该结构作为句式教学对象”决定：

  B/C 级（bank / Useful expressions）  → NEED_REVIEW    （首批 51 条，待人工确认）

本批不预设 51 条的 CORE / RECOGNITION；人工确认后由受控任务回填。
```

### review_status（Q16）

沿用四态 `AUTO_OK / NEED_REVIEW / REVIEWED_OK / REJECTED`（不制造第二套审核体系）：**首批 = 1 AUTO_OK + 51 NEED_REVIEW**；`requirement_conflict_status` 全部 `OK`。NEED_REVIEW 理由：模板归一化与“是否作为独立句型资源”需人工确认。

## 25. 风险与遗留

4. Communication bank 的 Unit 5 / Unit 6 阅读顺序 Note 会影响未来“按 Unit 自动组织 bank 条目”；需在教材解析议题中解决。
5. `meaning_zh` 本批仅 1 条（教材明文释义）；其余 51 条保持 NULL，**不得由 AI 翻译补写**。
6. 51 条 NEED_REVIEW 的人工审核工作量需在 G1-C 之后与 Vocabulary / Phrase 审核队列统一规划。
