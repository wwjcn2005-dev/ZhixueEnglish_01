## 3. LearningGoal

现状：`learning_goal(goal_id, textbook_id, snapshot_id, scope, scope_id, statement_raw, statement_normalized, goal_origin, review_status)`，6 条单元级目标，`goal_origin='TEXTBOOK_EXPLICIT'`。

必须区分两类来源：

| 类别 | 含义 | 现状 | 建议 |
| --- | --- | --- | --- |
| A. 教材显式目标 | 教材原文写出的目标（如 `After completing the unit, you will be able to:`） | **已有**（6 条） | 保持，任何派生内容不得覆盖 |
| B. 系统派生目标 | 系统根据教材结构整理出的学习目标（如“能够识别并理解本单元重点词”） | **不存在** | 未来引入时用 `goal_origin='DERIVED'`，并记录 `derived_from` |

| 概念 | 是否需要 | 说明 |
| --- | --- | --- |
| `goal_origin` | **必须**（已有字段） | 区分教材事实与系统派生，防止 AI/系统目标冒充教材事实 |
| `derived_from` | **建议**（未来） | 指向派生来源（如 unit goal_id 或来源说明），当前可空 |
| `target_item_id` | **暂缓** | 单条资源的归属应由 `resource_goal` 关系表表达；放进 goal 会与关系表重复，且一对多场景会破坏 goal 身份 |

层级：**学习层（意图）**。生命周期：版本化（教材修订产生新 goal），不随孩子改变。

## 4. LearningTask

**定义**：Task 是“一次有计划的学习活动集合”，回答“为什么学、学什么、以什么方式学”。

必须区分的三层概念：

| 概念 | 例子 | 层级 |
| --- | --- | --- |
| Task（任务） | “学习 Unit 1 重点词” | L3 学习任务（意图/计划） |
| Activity / Question（活动/题目） | “选择正确词义”“跟读这个词”“替换 slot 造句” | L4 活动（执行单元） |
| Record（记录） | 孩子选了 B、用时 6 秒、用了 1 次提示 | L5 历史事实 |

```text
Task      ≠  Question   （任务可由多道题/多个活动组成）
Question  ≠  Record     （题目是模板，记录是某一次实际发生）
Task      ≠  Record     （任务可被多次执行，每次产生独立记录）
```

方案比较（§九）：

| 方案 | 可扩展性 | 复习 | 学习卡/跟读 | 非题目型活动 | 未来 AI | 用户自主选择 |
| --- | --- | --- | --- | --- | --- | --- |
| A. `Resource → Question → Record` | 低（被迫把一切做成题） | 弱 | 无法表达 | 不支持 | 只能挂题上 | 弱 |
| B. `Resource → Task → Activity/Question → Record` | 高 | 强（任务级复习） | 自然支持 | 支持 | 可挂任务/活动 | 强（任务可换、可跳过） |

**推荐：方案 B。**

Task 最小字段：`task_id(PK) / learner_id(可空=模板任务) / goal_id(可空) / task_kind ∈ {learn, practice, review} / title / status(planned, active, done, dropped) / source_kind ∈ {rule, user, ai_artifact} / created_at`

层级：**运行层（计划）**。生命周期：创建 → 进行 → 完成/放弃；可重复执行。

## 5. TaskItem

**必须存在**（多对多桥接实体）。

理由：① 一个任务常包含多条资源（如“Unit 1 核心词汇” = Vocabulary A/B/C）；② 一条资源会出现在多个任务（学习、复习、再测）；③ 若用 JSON 数组塞进 `LearningTask.items`，将无法按资源聚合、无法建立 `(learner, item)` 掌握度、无法做复习调度与索引。

```text
TaskItem(task_id, item_id, ordinal, item_role ∈ {primary, support, example})
PK = (task_id, item_id)
```

层级：**学习层（连接）**。生命周期：随所属任务存在，可增删（不影响教材资源）。

## 6. Question / Activity

现状：**NOT PRESENT**（项目无 `question` / `exercise` / `targeted_question` 表）。

归属判定：

| 候选归属 | 判定 |
| --- | --- |
| 属于 Task 层 | **是** —— Activity 是任务的执行单元 |
| 属于 Resource（教材资源）层 | **否** —— 教材资源层零 AI、零题目；题目不得写入 L1 |
| 属于 AI Artifact | **部分** —— AI 生成的题先成为 `AIArtifact(kind=exercise)`，经审核后才可作为 Activity 的来源 |
| 独立题目资源库 | **暂缓**（完整题库系统属 Later） |

推荐结构（未来）：

```text
LearningActivity(activity_id, task_id, item_id, activity_type, ordinal,
                 source_kind ∈ {rule_template, textbook, ai_artifact},
                 prompt_ref, options_ref, answer_key_ref(可空), status)
```

要点：`answer_key_ref` **可空** —— 跟读/朗读/阅读/听音等非题目型活动没有唯一答案。

层级：**运行层（活动）**。生命周期：随任务生成，可在执行后保留或清理（记录不受影响）。

## 7. LearningRecord

**必须存在**：记录“孩子实际做过什么”，属**历史事实**，只追加（append-only），不覆盖。

| 字段 | 判定 |
| --- | --- |
| `record_id` | 核心 |
| `learner_id` | 核心（必填） |
| `task_id` | 核心（必填；无任务的自由浏览不产生学习记录，或标记为 `task_id=NULL` + `activity_type='viewed'` 的轻量事件） |
| `item_id` | 核心（哪条教材资源） |
| `activity_type` | 核心（`recognize / read / read_aloud / listen / spell / understand / substitute / make_sentence / answer / review`） |
| `result` | 核心（`correct / incorrect / partial / done / skipped`；非题目型可用 `done/skipped`） |
| `response_raw` | 核心（简短：所选选项、输入文本；长文本后续再说） |
| `attempt_no` | 核心（同一活动第几次） |
| `duration_ms` | 可选（统计用，缺失允许 NULL） |
| `hints_used` | 可选（计数或引用 `AIArtifact.hint` 的 id） |
| `created_at` | 核心 |
| 音频评分细节 / 手写识别 / 完整交互轨迹 | **暂缓** |
| mastery 值 / review_due / AI 诊断文本 | **禁止混入**（见第 8、9、10 节） |

层级：**用户层（历史）**。

### Record 边界（§十三）

```text
学习行为（started / viewed / practiced / answered / completed）
   → 用 activity_type + 事件产生时点表达（一次行为 = 一条 record）
结果（correct / incorrect / partial）
   → record.result
学习状态（mastery / review_due）
   → 只存在于 MasteryState（不得写进 record）
AI（hint / diagnosis）
   → 只存在于 AIArtifact；record 只保存 hints_used 计数或 artifact_id 引用
```

## 8. MasteryState

语义：**“孩子目前对该教材资源掌握到什么程度”**（当前状态），**不是**“最近一次表现”。

```text
第一次答错：Record.result = incorrect
          ≠ MasteryState.mastery_level = 0
（首次证据只更新 evidence_count / last_result；达到最少证据量后才升级/降级掌握等级）
```

推荐最小字段：

```text
MasteryState(learner_id, item_id,
             mastery_level ∈ {unknown, learning, familiar, stable},
             evidence_count, correct_count,
             last_result, last_practiced_at,
             review_needed(bool), next_review_at(可空),
             updated_at)
PK = (learner_id, item_id)
```

层级：**用户层（状态，派生数据）**；可由 Record 重算，但单独存储以避免每次实时聚合。

## 9. ReviewItem

方案比较：

| 方案 | 评估 |
| --- | --- |
| A. 只用 `MasteryState.review_needed / next_review_at` | 最小、零冗余；无法表达“多次复习排队/来源/历史” |
| B. 独立 `ReviewItem` | 强表达力；但当前需要的信息（要不要复习、何时复习）已在 A 中 |
| C. 两者并存 | 未来方向（状态在 Mastery，计划在 ReviewItem） |

**阶段性推荐：先 A（暂不建独立 ReviewItem）。**

升级条件（满足任一即建立独立 `ReviewItem`，属 P1/Later）：

```text
1. 需要同一资源多次复习的排队与历史（复习→再复习链）
2. 需要区分复习来源（错题 / 薄弱项 / AI 诊断 / 人工安排）
3. 需要按天聚合的复习计划视图
4. 需要保留复习结果链与其对掌握度的影响路径
```

## 10. AIArtifact

现状：`ai_artifact(artifact_id, artifact_kind, target_layer, target_id, context_ref_ids, content_markdown, model, prompt_version, confidence, review_status, is_visible_to_child, textbook_id, snapshot_id)`，0 行，**表已就绪**。

| 问题 | 结论 |
| --- | --- |
| 引用教材资源 | **是**：`target_layer='textbook_resource'` + `target_id=<item_id>` |
| 引用学习任务 | **是**：`target_layer='learning_task'` + `target_id=<task_id>` |
| 引用具体题目/活动 | 建议 `target_layer='learning_activity'` |
| 引用学习记录 | 建议 `target_layer='learning_record'`（用于诊断） |
| 允许 `context_ref_ids` 上下文引用 | **建议保留**（可放 `source_ref_id` / `content_block_id` / 多条 item_id） |

原则：**AIArtifact 单向依赖教材资源与学习层对象；教材资源不依赖任何 AI 产物**；默认 `is_visible_to_child=false`，经 `review_status` 审核后可见；`(artifact_kind, target_id, model, prompt_version)` 作为缓存键，避免重复生成。

层级：**AI 层（旁路）**。

## 11. Resource → Goal

推荐：当前**解耦**（不建映射表）。教材只显式给出 unit 级目标；把 362 条资源强行映射到 6 条 unit 目标属于自造课程体系。

未来引入派生目标后：`resource_goal(item_id, goal_id, relation_type ∈ {textbook_explicit, derived}, evidence_type, review_status)`（多对多，LATER）。

## 12. Goal → Task

推荐：`LearningTask.goal_id`（任务级意图）。一个目标可派生多个任务；一个任务只归属一个主目标（若需多目标，再建 `task_goal` 关系表，LATER）。

## 13. Task → Activity

推荐：一对一/一对多（`LearningActivity.task_id`）。任务内的活动按 `ordinal` 排序；活动是“执行单元”，任务是“学习流程”。

## 14. Activity → Record

推荐：`LearningRecord.activity_id`（可空：无活动实体的早期阶段可按 `activity_type` 记录）+ 必填 `item_id` + 必填 `learner_id`。一次执行 = 一条记录；重试产生新记录（`attempt_no` 递增）。

## 15. Record → Mastery

推荐：由 Record **聚合**出 MasteryState（同一 `(learner_id, item_id)` 的所有记录）。方向严格单向：`Record → MasteryState`；掌握状态**永不写回 Record，也永不写回教材资源**。

## 16. Review 设计

阶段性结论：`MasteryState.review_needed + next_review_at` 已足够表达“这个资源需要复习 / 何时复习”。复习任务本身仍通过 `LearningTask(task_kind='review')` 表达，并复用 `TaskItem` 指向资源 —— **不需要现在引入新实体**。间隔复习算法（SM-2/FSRS 等）属 Later，本轮不设计。

## 17. AI 介入

| 时机 | 允许的 AI 产物 | 约束 |
| --- | --- | --- |
| 学习前 | 解释、准备性问题 | 按需触发，结果缓存 |
| 学习中 | 提示（hint） | 先规则后 AI；不得打断孩子选择 |
| 学习后 | 诊断、错因分析 | 只生成 AIArtifact，不写教材资源 |
| 复习时 | 讲解、变式练习 | 可复用已有缓存产物 |

架构建议：**规则优先 → AI 按需 → 结果缓存复用**。禁止“浏览教材触发 AI”“每次打开资源调用 AI”“把 AI 当作资源基础设施”。

## 18. 孩子自主权

```text
Recommendation ≠ Task ≠ Requirement
系统可以推荐（“这个词建议再复习一次”）
孩子可以：继续 / 稍后 / 跳过 / 换一个
AI 推荐不得改变教材资源，也不得强制进入任务
```

推荐结果既可表现为 `AIArtifact(kind=suggestion)`，也可仅在前端作为瞬时提示（不落库，P2）。

## 19. 非题目型学习

任务/活动模型必须支持：阅读、认读、跟读、听音、拼写、理解、替换、造句、复习。

设计要求：

1. `activity_type` 覆盖非题目型活动；
2. `answer_key_ref` 允许为空；
3. `LearningRecord.result` 支持 `done / skipped`（不强迫判定对错）；
4. 不得把“跟读一次”硬编码成选择题。

## 20. 最小生命周期

```text
① 孩子选择资源/主题（自主）
② 形成学习目标（教材显式目标 + 可选派生目标）
③ 创建/进入任务（Task，规则优先；AI 可提供建议）
④ 执行活动（Activity：题目型 / 非题目型）
⑤ 产生学习记录（Record，append-only）
⑥ 更新掌握状态（MasteryState，(learner_id, item_id)）
⑦ 决定是否复习（review_needed / next_review_at → 生成复习任务，孩子可选择现在学/稍后/跳过）
   └──（旁路）AI 在需要时生成提示/解释/题目 → 存入 AIArtifact → 缓存复用
```
