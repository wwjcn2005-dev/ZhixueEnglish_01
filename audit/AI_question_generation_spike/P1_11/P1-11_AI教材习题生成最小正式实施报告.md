## 6. `answer_unique` 结果（实施 4）

### 6.1 选择题（逐候选按需；本轮按 Test B 启用）

```text
FIX-C1  flagged = [students]        → answer_unique = FAIL / answer_unique_status = UNIQUE_RISK
FIX-C2  flagged = [name, word]      → answer_unique = FAIL / answer_unique_status = UNIQUE_RISK
candidate_coverage = COMPLETE（候选集合 = 题目选项，天然完整）
```

程序侧规则（不采用模型的整体唯一性结论）：

```text
任一非当前答案选项满足下面任一条 → UNIQUE_RISK
  ① grammar_valid = YES 且 semantic_valid = YES 且 textbook_context_valid = YES
  ② 模型自己的逐候选 roll-up：valid_alternative = YES
规则②是**只增不减**的保守触发：它只能把 UNIQUE_SUPPORTED 变成 UNIQUE_RISK，
不可能反向放宽，因此不会制造"假唯一"。
```

### 6.2 填空题（本轮未做逐候选）

```text
answer_unique = NOT_PROVABLE · answer_unique_status = NOT_PROVABLE · coverage = NONE
不建候选池、不扫描整个教材、不做 prescreen、不为证明唯一性增加调用
（模块中该分支已固定：任何 fill 题都会走到这里）
```

### 6.3 与设计的一次偏差（必须如实记录，详见 §12 L1）

```text
首次 Test B 调用返回的逐候选 flags 中，students / word 被标成 textbook_context_valid = NO
（模型把该字段理解成"被教材支持"，而不是"与教材相容、不被否定"），
若按原三字段规则会算出 UNIQUE_SUPPORTED —— 与 P1-09-F 已验证的结论矛盾。
处理：① 程序规则改为"三字段全 YES 或 valid_alternative=YES"双触发（只增不减）；
      ② 提示词补回 P1-09-F 的字段定义，版本记为 v1.1，供下一轮真实验证；
      ③ **没有**重新调用 AI（不重复审同一 fingerprint），复用已保存的同一次响应重算。
```
