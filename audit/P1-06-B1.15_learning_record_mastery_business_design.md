## 1. 第一原则：LearningRecord 是什么

> **`LearningRecord` = 一次真实发生的学习行为历史事实。**

它不是：Task、TaskItem、Activity 定义、Mastery、ReviewItem、AI 诊断、学习计划、进度百分比。

```text
孩子看到 peaceful 并做了 read        → 产生 1 条 Record（行为真实发生）
TaskItem 中存在 peaceful（未学习）   → 不产生 Record
打开学习页面 / 纯浏览                → 不产生 Record
```

## 2. 什么情况下产生 LearningRecord

| 情形 | 是否产生 Record | 说明 |
| --- | --- | --- |
| 打开学习页面 | **否** | 页面打开不是学习行为 |
| 浏览资源 | **否** | 第一阶段不把纯浏览定义为学习行为；**不引入 `view`** |
| 阅读 / 朗读（`read`） | 是 | 孩子明确进行该行为 |
| 理解（`understand`） | 是 | 孩子完成理解/自测理解 |
| 听（`listen`） | 是 | 听完该资源音频 |
| 跟读（`repeat`） | 是 | 完成跟读/复述 |
| 拼写（`spell`） | 是 | 完成一次拼写 |
| 替换 / 套用（`substitute`） | 是 | 完成一次槽位替换 |
| 产出（`produce`） | 是 | 完成一次造句/表达产出 |
| 复习（`review`） | 是 | 完成一次复习行为（见第 9 条补充规则） |
| 主动跳过 | 是 | `result='skipped'`（真实流程事件） |

## 3. activity_type 九种正式业务定义

行为主体一律为**孩子本人**；“是否主动学习行为”指是否由孩子主动发起的学习动作（而非系统后台动作）。

| activity_type | 用户实际做了什么 | 何时产生 Record | result | response_raw | hint | 主动学习 |
| --- | --- | --- | --- | --- | --- | --- |
| `recognize` | **主动辨认一个学习资源**：看词形认词、听音辨词、从候选中指出目标资源 | 孩子完成一次识别动作时 | correct / incorrect / partial / skipped / NULL | 可（所选选项或简短输入） | 可 | 是 |
| `read` | 把该资源读出来 / 阅读其承载内容 | 完成一次朗读或阅读动作时 | done / skipped / NULL | 通常 NULL（第一阶段不录音） | 可（发音提示） | 是 |
| `understand` | 完成“理解词义/用法”的动作（含自测理解、主动确认已理解） | 孩子完成理解动作时 | correct / incorrect / partial / done / skipped / NULL | 可（若有文本输入） | 可 | 是 |
| `listen` | 听完该资源的音频 | 一次完整听音结束时 | done / skipped / NULL | 否 | 不适用 | 是 |
| `repeat` | 跟读 / 复述该资源 | 完成一次跟读时 | done / skipped / NULL | 否（第一阶段不录音） | 可 | 是 |
| `spell` | 拼写该资源 | 提交一次拼写时 | correct / incorrect / partial / skipped / NULL | 可（孩子输入的拼写文本） | 可 | 是 |
| `substitute` | 对 Phrase / Sentence Pattern 做槽位替换 | 提交一次替换时 | correct / incorrect / partial / done / skipped / NULL | 可（替换后的表达文本） | 可 | 是 |
| `produce` | 造句 / 自由表达产出 | 提交一次产出时 | correct / incorrect / partial / done / skipped / NULL | 可（孩子写的句子） | 可 | 是 |
| `review` | 完成一次**复习动作**（整体回顾型；见下） | 完成一次复习动作时 | done / skipped / NULL（若该复习动作本身可判定，允许 correct / incorrect / partial） | 通常 NULL | 可 | 是 |

**`recognize` 冻结定义（§七第 11 项）**：孩子**主动**对某个学习资源做“识别 / 辨认”的行为（例如看到词形说出意思、听到发音指出对应词、从候选中辨认目标），是**主动学习行为**；不等于“页面浏览”，也不等于“系统自动匹配”。

**`review` 归类规则（截断补齐）**：`activity_type` 描述**孩子做了什么动作**，不描述任务类型。因此：

```text
task_kind = review 且孩子做了拼写      → activity_type = spell（不是 review）
task_kind = review 且孩子整体回顾一遍  → activity_type = review（无法归入前 8 类时）
```

即 `review` 仅用于“复习动作无法归入其他 8 种动作语义”的情形，避免与具体动作重复计数。

## 5. result 业务语义

| result | 定义 | 何时使用 |
| --- | --- | --- |
| `correct` | 行为完成，且判定为完全正确 | 有对错判定的活动（recognize / spell / substitute / produce / understand 等） |
| `incorrect` | 行为完成，且判定为错误 | 同上 |
| `partial` | 行为完成，但**只有部分正确** | 简答、句子产出、替换、口语等部分正确场景 |
| `done` | 行为完成，且该行为**本身没有对错概念** | `read` / `listen` / `repeat`；`understand` 的“我已理解”标记 |
| `skipped` | 用户**明确跳过**此次行为 | 孩子主动点击“跳过” |
| `NULL` | 行为已产生 Record，但当前阶段**不存在适用结果值** | 严格限定，见下 |

**NULL 的严格边界**：

```text
允许 NULL 的情形（第一阶段仅两类）：
  ① activity_type='review' 的整体回顾型复习行为（无可判定产出）
  ② 未来新增 activity_type 尚未定义 result 语义时（需受控评审）

禁止用 NULL 表示：未完成 / 未判断 / 正在进行 / 错误
如果行为本身应有对错 → 必须给出 correct / incorrect / partial
如果行为本身无对错 → 用 done
```

## 7. partial 审计

```text
partial ≠ correct
第一阶段：partial 只记录为事实，不视为“已掌握”，也不触发任何自动升级
不得因为 partial 而把 MasteryState 置为 familiar / stable

```

## 8. response_raw

> **定义：用户在一次学习行为中产生的原始响应文本。**

它不是：标准答案、AI 诊断、结构化评分、教材文本、Mastery、AI prompt、AI response。

| activity_type | 是否需要 response_raw |
| --- | --- |
| spell | 需要（孩子输入的拼写文本） |
| substitute | 需要（替换后的表达文本） |
| produce | 需要（孩子写的句子） |
| understand | 视界面而定（若有文本输入则保存） |
| recognize | 可选（所选选项） |
| read / listen / repeat / review | 通常 NULL |

第一阶段**仅文本**；不得保存音频、图片、手写图像、视频、OCR 结果、embedding、AI 分析正文。有文本产出才保存；不得为“完整”写空字符串（应写 NULL）。

## 9. attempt_no

```text
定义：同一 (learner_id, task_id, item_id, activity_type) 上下文内的连续尝试序号，从 1 开始
示例：spell peaceful → attempt 1 = incorrect；attempt 2 = correct
新上下文（新 Task / 新 item / 换 activity_type）→ 重新从 1 开始
同一 Task 内跨会话继续同一活动 → 继续递增（仍属同一上下文）
不做全局计数器；不跨 Task 累计
```

## 10. hints_used

```text
定义：本次 LearningRecord 对应行为中，孩子实际使用的提示次数
0 = 未使用；1 = 一次；2 = 两次 …
只记录数量；不保存 hint 正文 / AI prompt / AI response / 提示内容快照
```

## 11. created_at

> 该学习行为事实**实际发生并被系统记录**的时间（ISO-8601）。

不是：Task 创建时间、页面打开时间、AI 分析时间、Mastery 更新时间。

## 12. Task 与 Record 的合法关系

```text
learning_record.task_id  → 必须是真实存在的 Task（FK，ON DELETE RESTRICT）✓ 已冻结
learning_record.item_id  → 逻辑引用（跨库，无 FK）
```

**冻结规则**：

```text
创建 Record 时（业务层校验）：item_id 必须是该 Task 当时的 TaskItem
之后即使 TaskItem 被删除：历史 Record 保留，永不被删除或被改写
数据库层不建立 learning_record → task_item 的外键
```

理由：TaskItem 是**可变计划**，Record 是**不可变事实**；若建 FK + CASCADE 会误删历史，若 RESTRICT 会锁死任务编辑。

## 14. Record 是否允许修改（append-only）

```text
INSERT ：允许（唯一写入方式）
UPDATE ：业务层禁止
DELETE ：业务层禁止

若发现错误（例如误记 incorrect）：
  不得修改原记录，也不得“伪造纠错历史”；
  只能新增一条**真实发生过的**新行为 Record。
第一阶段不引入数据库触发器（应用层约束；如需数据库级强约束，另立受控评审）。
```

```text
第一阶段不设置幂等键
```

## 16. skipped

```text
孩子明确点击“跳过” → 产生一条 Record（result='skipped'）
skipped ≠ incorrect
skipped ≠ “未学习”（它是真实发生的流程事件，只表示本次行为被主动跳过）
```

```text
适用：read / listen / repeat（本身无对错），以及 understand 的“我已理解”标记
```

## 18. MasteryState 是什么

> **`MasteryState` = 某 Learner 对某一个教材资源当前掌握状态的缓存 / 状态事实。**

```text
主键：(learner_id, item_id)
不是：历史记录、Task、TaskItem、题目、分数、AI 诊断、Review 计划、教材内容
```

## 19. mastery_level 四级语义

| 等级 | 冻结定义（仅语义，不含阈值） |
| --- | --- |
| `unknown` | 尚无足够学习证据，或尚未形成有效的掌握状态 |
| `learning` | 正在学习中：已接触该资源，仍需要辅助或提示才能完成 |
| `familiar` | 已经能够较稳定地识别 / 完成该资源，但尚不稳定（仍需偶尔提示，或在变化情境下仍可能出错） |
| `stable` | 当前证据表明该资源掌握较稳定（能够独立、持续地正确完成） |

```text
禁止：分数阈值、正确率、连续正确次数、自动升级/降级规则
本轮只冻结语义；算法属后续 Record / Mastery 业务阶段
```

## 20. MasteryState 其余字段语义（截断补齐）

| 字段 | 冻结语义（最小规则，非算法） |
| --- | --- |
| `evidence_count` | 该 `(learner_id, item_id)` 下**参与掌握判断**的 Record 数。第一阶段最小口径：`result ∈ {correct, incorrect, partial, done}` 各计 1；`skipped` 与 `NULL` **不计入** |
| `correct_count` | `result='correct'` 的 Record 数。**`partial` 不计入**；`done` / `skipped` / `NULL` 不计入 |
| `last_result` | **最近一次参与掌握判断的** Record 的 `result`（`skipped` / `NULL` 不更新该字段）；属派生缓存，可由 Record 重建 |
| `last_practiced_at` | 最近一次参与掌握判断的 Record 的 `created_at` |
| `review_needed` | 0/1 当前状态（非历史）。可写来源：① 系统规则（规则本身属后续阶段）；② 孩子显式操作。**AI 只能建议，不得直接写入** |
| `updated_at` | MasteryState 最近一次被更新的时间 |

## 21. Record → MasteryState 事务（截断补齐）

```text
一次学习事件（同一 learning.db、同一事务）：
  BEGIN
    INSERT INTO learning_record (...)
    UPSERT mastery_state (learner_id, item_id)   -- 按第 20 节最小口径更新
  COMMIT

失败：整体回滚（不允许“有记录、无状态”或“有状态、无记录”）
不产生 Record 的行为（浏览 / 打开页面）：不写 Record，也不更新 MasteryState
```

细则：

```text
1. result ∈ {correct, incorrect, partial, done}：写入 Record 并更新 evidence_count（correct 另加 correct_count、
   更新 last_result / last_practiced_at）
2. result = 'skipped' 或 NULL：只写 Record，**不改变** mastery_level / evidence_count / correct_count /
   last_result / last_practiced_at
3. mastery_state 行不存在：按 PK(learner_id,item_id) 新建（mastery_level 默认 unknown），再按上述口径更新计数
4. mastery_level 的变化（升级/降级）属后续算法阶段；第一阶段只维护计数与最后结果（可由规则实现，本轮不定义阈值）
5. MasteryState 可由 Record 完整重建（重建工具属后续阶段）
6. 事务失败重试必须保证不产生重复 Record（第一阶段不设幂等键，由应用层保证单次写入）
```

## 27. 最终冻结摘要

```text
Record  ：真实学习行为的历史事实；append-only；浏览不产生；重复行为逐条独立；错误只新增不修改
activity：9 种；描述“孩子做了什么动作”（review 仅用于无法归类的复习动作）

attempt ：同一 (learner, task, item, activity_type) 内的连续尝试序号，从 1 开始
```
