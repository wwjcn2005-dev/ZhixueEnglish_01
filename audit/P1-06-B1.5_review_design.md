## 1. 目标与定位

审核机制要回答的唯一问题是：

> **这个候选是否确实可以作为「教材派生学习资源」成立？**

它**不**回答“这个内容对孩子有没有用”“现在要不要推荐给孩子”——后者属于学习推荐层，由教材进度、当前年级、学习状态与「AI 反馈水平与阶段适配原则」共同决定，与本机制的判定相互独立。

## 2. 审核对象与当前样本现状（v2 只读取证）

```text
Vocabulary learning_item ：287
  ├─ OK          ：196
  └─ NEED_REVIEW ：91
Proper nouns（p.163–164，尚未进入 Vocabulary）：33 条条目 + 1 个 "Names" 小标题 = 36 个内容块
source_ref：714（含 learning_goal 6 条）
```

91 条 NEED_REVIEW 的成因分布（可能重叠）：

| 成因 | 数量 | 真实示例 |
| --- | --- | --- |
| 跨块合并（headword 的释义在下一块续行） | 68 | `textbook /ˈtekstbʊk/ n. 教科书,教材,` + `课本 3` → `textbook … 教科书,教材, 课本 3` |
| 缺词性（教材本身未标注词性，多为多词条目） | 25 | `junior high 初级中学 3`、`red scarf 红领巾 5`、`school uniform 校服 5` |
| 缺教材页码（教材条目本身没有页号） | 1 | `smile /smaɪl/ n. 笑容` |

结论：这 91 条**不是抽取失败**，而是教材排版本身带来的三类结构差异；因此审核的目标是“确认边界与归属”，不是“补全缺失信息”。

## 3. 推荐状态模型

```text
AUTO_OK        机器高置信、无需人工判断（原 OK 的语义改名）
NEED_REVIEW    需要人工确认（保持原语义）
REVIEWED_OK    人工审核通过（= 该候选确实可成立为教材派生资源）
REJECTED       人工审核否决（= 该候选不作为资源；教材原文与其 source_ref 仍保留）
```

可选扩展（暂不启用，避免过度设计）：`RE_REVIEW`（旧审核结论因来源变化需重审）。

### 七个必答问题

| 问题 | 结论 | 理由 |
| --- | --- | --- |
| 1. AUTO_OK 与 REVIEWED_OK 是否需要区分？ | **需要** | 二者可信度来源不同：前者是规则高置信，后者有人工背书；未来 AI 解释、错误诊断与“可展示给孩子的资源集”会区别对待。 |
| 2. NEED_REVIEW 是否可以直接变成 REVIEWED_OK？ | **可以，但必须留下审核轨迹** | 需写入 `reviewed_by / reviewed_at / review_note`；没有轨迹的状态变化视为非法。 |
| 3. REJECTED 是否保留记录？ | **必须保留** | 删除会破坏可追溯性，也会导致下一轮构建重复出现同一候选、重复审核。 |
| 4. REJECTED 是否允许重新审核？ | **允许** | 但必须新增一条审核记录（保留历史结论），不允许覆盖旧结论。 |
| 5. 是否需要 reviewed_by / reviewed_at / review_note？ | **必须** | 这是审核可追溯的最小集合。 |
| 6. 是否需要 review_version？ | **需要（设计上保留）** | 用于区分“审核结论基于哪一版规则/教材包”；实现上可先记录为常量（如 `review_v1`）。 |
| 7. 审核后原始教材来源是否永远保留？ | **永远保留** | `content_block`、`source_ref`、原始 PDF 不因 REJECTED 而删除（见第 8 节）。 |

## 4. 审核字段

### 4.1 必须字段（建议在 contentpack v3 的 `learning_item` 上扩展）

```text
review_status      AUTO_OK | NEED_REVIEW | REVIEWED_OK | REJECTED
reviewed_by        审核人标识（本地化字符串；不允许 AI）
reviewed_at        ISO8601 时间
review_note        审核说明（必填于 REJECTED 与状态变更场景）
review_version     审核规则版本，如 review_v1
```

### 4.2 可选字段（有明确需要再加）

```text
review_evidence_refs   审核时引用的证据（默认就是 source_ref 链，可显式记录）
review_batch           批量审核批次号（便于回滚与统计）
```

### 4.3 不需要的字段

| 字段 | 不建议的理由 |
| --- | --- |
| `ai_suggestion` / `ai_confidence` | 会让 AI 意见混入权威资源层；AI 建议属 L3，不应进 L2 表 |
| `difficulty_level` / `grade_level` | 属于学习推荐维度，不是“资源是否成立”的判定依据（见第 13 节） |
| `is_recommended` | 推荐由学习层决定，教材资源层不承担 |
| 独立的 `review` 新表 | 当前规模（127 条候选）不需要；先扩展 `learning_item` 字段即可。只有在需要保存“多轮审核历史”时，才建议另建 `review_log`（并在报告中说明理由） |

## 5. 统一审核原则（基于证据）

审核人必须能够看到完整证据链：

```text
learning_item → source_ref → content_block → page → 原始 PDF
```

审核必须逐项判断：

1. 是否确实来自教材（`quote_raw` 与 PDF 页面文字是否一致）
2. 是否属于对应资源类型（Vocabulary 必须是教材词汇表条目）
3. 词条边界是否正确（headword 与释义的分界、音标是否被误切）
4. 跨块合并是否正确（续行是否属于同一条目）
5. 是否存在重复（同一词汇是否被拆成两条）
6. 是否存在分类错误（是否本应属 Proper nouns / Phrase 等其他类型）
7. 是否存在 PDF 排版异常（断行、串行、页码错位）
8. 是否应该拒绝

**不得**依据常识、网络搜索、AI 建议或“感觉这个词重要”来决定资源是否成立。

## 6. Vocabulary 专项审核规则

| 情况 | 审核要点 | 允许的结论 | 明令禁止 |
| --- | --- | --- | --- |
| A. 跨块合并（68 条） | 确认续行块与 head 块在原始 PDF 中确为同一条目（同一栏、紧邻、语义连续） | `REVIEWED_OK`（合并正确）或 `REJECTED`（合并错误，如需拆分为两条则应回到构建阶段重建） | 手工拼接教材没有的文字 |
| B. 缺词性（25 条） | 确认教材词汇表该条目本身未标注词性（多词条目常见） | 词条成立 → `REVIEWED_OK`，`part_of_speech` 保持为空 | 凭英语知识补写 `n./v./adj.` |
| C. 缺教材页码（1 条） | 回到 PDF 确认该条目是否确实无页号（排版截断） | 保留原样 + `REVIEWED_OK`；若条目本身不成立则 `REJECTED` | 凭经验补页码 |
| D. 多词条目（22 条） | 确认它是否**作为教材词汇表中的一个条目**存在 | `REVIEWED_OK` | 不要在本阶段判定“它是不是 Phrase”（属 P1-06-B-2） |
| E. Proper nouns（36 块 / 33 条） | 判断是否单独作为教材资源类型 | 本阶段**不并入 Vocabulary**；建议未来新增 `item_type = proper_noun`（或 `vocabulary` 下的 `subtype`），需在 v3 设计中确认 | 直接混入普通 Vocabulary |

## 7. 审核动作必须可追溯

- 任何状态变化都写入 `review_status + reviewed_by + reviewed_at + review_note + review_version`。
- **不允许**只改状态不写轨迹。
- `REJECTED` 必须写 `review_note`（说明拒绝理由）。
- 审核记录不可物理删除；如需更正，追加新记录并保留旧值（v3 若需要可启用 `review_log`）。

---

## 8. 审核不能破坏教材内容

```text
教材原文（content_block / PDF） → 始终保留
候选 learning_item             → 可被标记 REJECTED
source_ref                     → 始终保留
```

拒绝的是“这个候选作为学习资源成立”，不是“这个内容不存在”。任何审核动作都不得删除 `content_block`、`source_ref`、原始 PDF 或 MP3。

---

## 9. 版本管理与审核结果迁移

```text
contentpack v2（已发布）  →  contentpack v3（未来）
```

迁移原则：

1. **稳定标识**：`item_id` 由 `sha1(canonical|pos)` 确定性生成，跨版本稳定；`content_hash` 由 `schema_version|item_type|canonical|pos|meaning_zh` 生成。
2. **迁移规则**：
   - `item_id` 与 `content_hash` 都不变 → 直接沿用历史审核结论（含 `reviewed_by/at/note/version`）。
   - `item_id` 不变但 `content_hash` 变化（释义、词性、规范化形式变化）→ 重置为 `NEED_REVIEW`，**必须重新审核**。
   - 旧 `item_id` 在新版本消失 → 审核结论归档保留（不删除），不迁移。
   - 新增 `item_id` → `AUTO_OK` 或 `NEED_REVIEW`，按构建规则判定。
3. **字段分离**：教材派生结果（canonical/display/phonetic/pos/meaning/source_ref）与人工审核结果（review_*）在模型上分列，构建过程只写前者、审核过程只写后者。
4. 本阶段**不执行迁移**，仅确定规则。

## 10. AI 边界

| AI 可以（未来，需另行设计） | AI 不可以 |
| --- | --- |
| 向审核人解释候选内容、给出对比、提示可能存在排版问题 | 直接写 `REVIEWED_OK` / `REJECTED` |
| 帮助定位证据（source_ref 链） | 修改教材资源内容或 `source_ref` |
| 生成候选清单排序建议（仅排序，不决策） | 修改审核状态或审核记录 |

核心原则：**AI 可以辅助审核，人必须拥有最终决定权。** 本阶段 AI 调用次数 = 0。

## 11. 与“当前孩子阶段”的边界

```text
教材中确实存在  →  教材资源可以成立（L2）
教材资源成立    →  ≠ 现在就推荐给孩子
```

推荐与否由以下因素在学习层决定：

```text
教材进度 + 当前年级 + 学习状态 + AI 反馈水平与阶段适配原则
```

特别提醒（写入审核规范）：**不能因为一个词对成年人简单就降低审核标准，也不能因为一个词对孩子较难就把真实教材词汇拒绝掉。**

## 12. 审核界面最少所需信息

### 必要信息（缺一不可）

```text
词汇名称（display_text / canonical_text）
词性（part_of_speech，可为空）
中文释义（meaning_zh）
资源类型（item_type）
当前 review_status
原始 ContentBlock 文本（quote_raw）
教材页码（textbook_page）+ PDF 页码（pdf_page）
是否跨块合并（source_ref 条数 ≥3 视为跨块）
```

### 可选信息（提升效率，非必须）

```text
音标、Unit / Section 归属、来源词汇表（Words and expressions / Vocabulary A–Z）、
同一词汇的其他来源、content_hash、历史审核记录
```

**不需要**：难度标注、推荐度、AI 点评、孩子学习数据——这些属于学习/AI 层，审核界面不应承担。

## 13. 审核规模与人工成本

| 批次 | 对象 | 数量 | 单条所需信息 | 处理建议 |
| --- | --- | --- | --- | --- |
| 1 | 缺词性条目 | 25 | 词条 + 来源块 + PDF 页 | 一次性处理，多为多词条目，判断快 |
| 2 | 跨块合并条目 | 68 | 词条 + 首块 + 续行块 + PDF 页 | 需要看两处原文，逐条确认合并是否成立 |
| 3 | 缺页码条目 | 1 | 词条 + PDF 页 | 单独确认 |
| 4 | Proper nouns | 33 | 词条 + PDF 页 | 待分类方案确定后再处理 |

合计 **127 条**。按每条 1–2 分钟估算约 2–4 小时，**适合分批人工处理，不需要专门建设后台管理系统**。

建议流程（v3 实施阶段）：

1. 由脚本导出审核清单（JSONL 或 CSV），审核人在离线表格中填写结论；
2. 用脚本校验并写回 v3 的 `learning_item`（不写回 v1/v2）；
3. 生成审核统计报告（AUTO_OK / NEED_REVIEW / REVIEWED_OK / REJECTED 数量）。

## 14. 审核清单格式（最小可用）

建议采用 **JSONL**（每行一条，便于脚本读写与 diff），字段：

```json
{"item_id":"...","item_type":"vocabulary","canonical_text":"textbook","display_text":"textbook /ˈtekstbʊk/ n. 教科书,教材, 课本 3","part_of_speech":"n","meaning_zh":"教科书,教材,课本","current_status":"NEED_REVIEW","merge_count":3,"source_blocks":["...:B3","...:B4"],"textbook_page":151,"pdf_page":156,"quote_raw":"...","decision":"","review_note":"","reviewed_by":"","reviewed_at":"","review_version":"review_v1"}
```

CSV 亦可（字段相同），但 `source_blocks` 等数组字段需要转义，JSONL 更稳妥。SQLite 写回仅在“审核结论已确定”阶段进行，且只写 contentpack v3。

## 15. 未决问题与停止条件

未决（需在 v3 设计阶段决定，本阶段不实施）：

1. Proper nouns 的资源类型归属：`item_type=proper_noun` 还是 `vocabulary` 下的子类型；
2. 是否需要 `review_log` 保存多轮审核历史（当前规模下暂不需要）；
3. 跨块合并被判定为错误时的处理路径（建议回到构建阶段按新规则重建，而不是在审核结果里手工拆分）。

停止条件复核：本设计**不需要修改 v1/v2**（审核字段在 v3 扩展）、**当前 schema 可安全承载**（通过扩展 learning_item 即可）、**不需要调用 AI**、**审核可追溯**（字段+证据链）、**不需要修改 parser/builder** → 无 STOP 条件触发。

## 16. 结论

1. 采用四态模型：`AUTO_OK / NEED_REVIEW / REVIEWED_OK / REJECTED`（可选 `RE_REVIEW`）。
2. 审核字段最小集：`review_status / reviewed_by / reviewed_at / review_note / review_version`，扩展在 contentpack v3 的 `learning_item` 上，不新增独立表。
3. 审核必须基于 `learning_item → source_ref → content_block → page → PDF` 证据链；不得凭常识、网络或 AI 判断。
4. `REJECTED` 只否决“资源候选”，永不删除教材原文与来源引用。
5. 跨版本通过稳定 `item_id` + `content_hash` 迁移审核结论；来源内容变化必须重新审核。
6. AI 只能辅助审核，最终决定权属于人；本阶段 AI 调用为 0。
7. 教材资源审核 ≠ 学习推荐；推荐由教材进度、年级、学习状态与阶段适配原则另行决定。
8. 127 条待审候选（91 NEED_REVIEW + 36 Proper nouns）建议分批人工处理，使用 JSONL 清单，无需自建复杂后台。
